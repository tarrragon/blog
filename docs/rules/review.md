# 審查與理解探針

## 審查與理解探針

### 多輪審查

寫完章節後跑 `multi-round-review` skill 時，至少跑三輪，Round 3 跑完之前不問「要不要繼續」：Round 1 與 Round 2 從已經寫好的內容裡找錯，Round 3 從還沒寫的內容出發（漏掉的選項、反向引用、搜尋落點、知識卡缺口），這一類在前兩輪的審查視角（frame）下看不到。Round 3 跑完之後，由主 session 判斷要不要再跑。frame 的選擇、reviewer 的產出契約與嚴重度量尺都以 skill 為準。依據：[多輪審查至少三輪是硬底線](/report/multi-round-review-minimum-three-rounds/)。

### 理解探針

驗一段文字會不會被誤解時，判斷依據放在多份獨立理解實際讀到什麼，不放在任何一個 reviewer 的判斷上。做法是把同一個低階模型獨立跑多份，每一份用逐字相同的指令讀同一份稿件，回報讀到什麼。低階模型推理較弱，讀到殘缺的句子時比較不會自動補完，缺漏因此會出現在回報裡；成本低，才能同時派出多份。

派發之前確認這幾個條件都成立，缺一個，分歧就無法歸因到文字：

- **指令逐字相同，餵給每一份的內容範圍也相同**。
- **不給審查框架**：問「你讀到什麼」，不問「這寫得好不好」；給了審查框架，低階模型會變成品質較差的 reviewer。
- **要求標記不確定**：文章沒說的地方要它寫「文章沒說」，不要推測填平。
- **問理解，不問評價**：每段在講什麼、每個動作誰做的、指涉詞各指誰、讀完之後會做什麼。

**歸因先於處置**：判定「讀者讀錯了」之前，先在原文裡搜那個讀法對應的字串。回報分三類：

- **原文寫錯**：找得到逐字對應的句子，是文章自己這樣寫的。修那一句，並找出它跟哪裡衝突（同一節的正文與結尾摘要互相矛盾是常見的形態）。
- **表述有歧義**：找不到對應的句子，而現有材料足以推出那個讀法。改寫成只有一種讀法。
- **模型誤讀**：文章已經給出足以排除那個讀法的材料，模型仍讀錯。在這裡結案。

前兩類都要處置，一份讀錯就修：引導讀者是寫作者的職責，任何一份讀錯都代表文字容許那個讀法。多份落在同一處提高的是證據強度，不決定要不要修。

規則類文件（AGENTS.md 與 `docs/rules/` 的分冊、CLAUDE.md、skill、spec）是理解探針的高價值對象：一條規則被讀錯，往後每個 session 都會照錯的版本執行。低階模型在事實正確性、跨檔一致性、承重論點的反證三個面向上不可信，那些仍要高階 reviewer；大量已知形態的掃描用 grep。

探針的其他用途（重點涵蓋度、閱讀負擔、翻譯探針、術語探針、類型探針、集合探針）、各自的設計條件、回報格式、處置門檻與判讀方式，以 `multi-round-review` 的 `references/round-2-probes.md` 為準。Claude Code 的派發參數在 CLAUDE.md。

審查的嚴重度分兩級，依讀者學不學得會分：**必修**是照做會學錯或做錯、在這一段理解不了、要離開這一頁或回頭翻才讀得懂，以及作者的編排脈絡寫進了正文；**可改**是讀者拿得到資訊也不會錯，但要多花力氣。規則分冊寫「審查時列為必修」的類別，就是落在前一級的那些。量尺的完整版在 `multi-round-review` 的 SKILL.md〈每個 reviewer 的 prompt 都要指定的事〉。依據：[理解檢查用低階 model 取樣讀者的實際理解，不靠單一 reviewer 的判斷](/report/comprehension-sampled-not-judged/)、[翻譯探針：中文可以不決定的，英文強制決定，多份譯本的分歧就是歧義的位置](/report/translation-forces-disambiguation/)、[譯者拿得到作者的意圖時，最該被偵測的那一類歧義會被安靜譯對](/report/probe-independence-is-not-transferable/)、[術語探針讀得到定義那個詞的規範檔時，收斂度量到的是詞頻](/report/probe-reads-the-prompt-that-defines-the-term/)、[探針的收斂度分不出無主的詞與已經有主人的詞，要讀有把握那幾份給的定義](/report/term-already-owned-inside-the-domain/)、[逐段審查量讀者學不學得會，指稱解不解得開要問沒讀過前文的讀者](/report/reviewer-holds-the-map-readers-land-without-it/)。
