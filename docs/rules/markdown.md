# Markdown 排版與 mdtools

這份分冊管 `content/` 的 Markdown 排版規範在哪裡、哪些類別由 mdtools 與 pre-commit 擋下（含自動連結的詞典這個生成檔與資料夾的登記）、路徑大小寫、列表排序與 weight，以及修改 mdtools 時讀哪裡。提交前的 lint 在 `AGENTS.md`〈提交〉。

## Markdown 與 mdtools

`content/**` 所有 markdown 的排版與結構規範，以 `content/posts/markdown-writing-spec.md` 為單一真實來源；完整規則、識別碼白名單、TLD 清單、執行時機與擴充流程讀那一篇。工具鏈是 `scripts/mdtools`（Go 加 goldmark AST），在 pre-commit、pre-push 與 CI 執行。規則與 `scripts/mdtools/internal/rules/` 的實作保持同步，任一方修改時同步更新另一方與規範文章。

### 工具會擋的類別與要自己跑的類別

### 自動連結的候選：`mdtools autolink-gaps`

`./bin/mdtools autolink-gaps <文章或目錄...>`（在 repo 根目錄執行）逐行印出 `<頁面>	<名字>	<原因>	<卡片路徑>`：正文裡出現、網站不會自動連結、而那張卡在這一頁還沒有任何連結（手寫的，或網站經由它的另一個名字連的）的卡片名稱，一頁一個名字一行；比對跟網站一樣不分大小寫。哪些要手寫連結照 `sentences.md`〈術語的解釋方式〉判；原因的意思用不給參數的 `./bin/mdtools autolink-gaps` 印出。

- **什麼時候跑**：寫完一篇文章的草稿之後（`writing-process.md`〈文章產出流程〉的術語掃描），以及審查一篇文章的連卡時（`review.md`〈多輪審查〉）。工具讀的是詞典，沒重產生時新的名字與範圍它看不到：作者在〈工具會擋的類別與要自己跑的類別〉詞典那一列的重產生條件成立時先重產生；審查的人先跑 `bin/autolink-dict --check --with <受審的全部檔案> data/autolink_terms.json`（不用不帶 `--with` 的 `--check`：它比對整個工作樹，另一個 session 還沒提交的卡會讓它一直 exit 1），exit 1 時這次的輸出不採用，回報作者重產生。
- **輸出怎麼讀**：exit 0 代表掃完，有沒有候選都是 0。stderr 的 `N file(s), M candidate(s)` 裡，給檔案時 N 等於檔案數，給目錄時 N 是目錄裡的 `.md` 數；N 是 0、印不出這一行或 exit 2 時，原因在 stderr，修好再跑，不把沒有輸出當成沒有候選。`unknown subcommand` 代表 `bin/mdtools` 是舊的，照 `scripts/mdtools/README.md`〈Build〉重建。逐個候選的判定（連或不連與依據，同一個名字與原因可以合成一列）寫進 `writing-process.md`〈掃描與探針的紀錄寫進 repo〉的術語處置表。
- **範圍的決定**：`-summary` 改印「頁面資料夾、原因、卡片資料夾」的計數。某個資料夾的文章大量用到另一個資料夾的卡（backend 的文章寫到 devops 的 MySQL、DNS、Prometheus 卡）時，要不要把那個卡片資料夾加進這個鍵的值是範圍的決定，改一次全資料夾的頁面一起變；判斷照〈工具會擋的類別與要自己跑的類別〉資料夾登記那一列，還沒決定的記在 `content/backend/knowledge-cards/_index.md` 的 `## Backlog`（那一對已經有一列時更新它的計數，不另加）。

### 路徑大小寫

`content/` 的資料夾、檔名與站內連結 route 一律小寫（`content/devops/ci` 對應 `/devops/ci/`）。macOS 預設檔案系統不區分大小寫而 Linux CI 區分：目錄是 `content/devops/CI`、連結寫 `/devops/ci/` 時，`mdtools cards` 在 CI 判成 broken link。新增或改名 `content/` 底下的資料夾或檔案之後，提交之前跑 `git ls-files -co --exclude-standard content | rg '^content/.*[A-Z]'`，有輸出就是大寫的路徑。`ls-files -co` 列的是工作樹裡已追蹤與還沒追蹤的檔案，所以這次新建、改名而還沒提交的路徑也在裡面；pattern 比對整條路徑，因為大寫可能出現在任何一層（大分類底下的教學模組在第二層）。

### 列表排序與 weight

Hugo 的列表依 weight 遞增排序，未設 weight 的頁面排在全部有 weight 的頁面之後，同 weight 才依日期遞減。由此推出：

- **同一個 section 的 weight 全有或全無**：混用會讓缺 weight 的頁面沉到列表底部，`mdtools cards` 的 `L5-section-weight-consistency` 會警告。刻意用低 weight 置頂單篇的 section（如 `content/linux/tools/cli`）在 `scripts/mdtools/internal/rules/config.go` 的 `WeightExemptSections` 登記。`weight: 0` 在 Hugo 就是未設，`L9-weight-zero-is-unset` 以 error 擋下，章節從 0 起算時最容易寫出這個值。
- **後補文章的 weight 放在屬於它的位置**：值落在該 section 既有的編號帶之內、順序對得上這篇在模組裡的位置。只確認沒跟別人重號不夠，重號與排序是兩件事。補號前先看該 section 既有的編號帶。L5 只查全有全無，對「有 weight 但值錯」不報。
- **新增一個要求 `title`、`date`、`description`、`weight` 四個欄位都必填的目錄**（目前登記的是知識卡目錄與 `content/report/`）時，在同一個 `config.go` 的 `FrontMatter.CardPaths` 登記，否則卡片層的 frontmatter 檢查不涵蓋它；未納管目錄的零 error 跟合規目錄的零 error 看起來一樣。依據：[檢查規則的作用域要顯式列舉：零 error 可能是沒被檢查](/report/lint-scope-must-be-explicit-fact/)。
- **frontmatter 的 date 是台北時間**：`hugo.toml` 設了 `timeZone = 'Asia/Taipei'`。拿掉這一行的話，在 UTC 的 CI 上、台北 00:00 到 08:00 之間 build，當日日期的文章會被判成未來文章而排除。

### 修改 mdtools

修改 `scripts/mdtools` 之前，讀 `scripts/mdtools/README.md` 的〈Development〉：那一節寫了測試要在哪個目錄跑、跨檔規則放哪個套件、fmt 規則的冪等要求與測試 fixture 的寫法。改完 mdtools 的規則時，同步更新 `content/posts/markdown-writing-spec.md` 與本分冊〈工具會擋的類別與要自己跑的類別〉的表。
