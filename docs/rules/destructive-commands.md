# 破壞性指令的適用範圍與細則

這份分冊補充 `AGENTS.md`〈破壞性指令的目標寫在指令文字裡，檢查與刪除分成兩次執行〉：規則本身與「暫存目錄」的定義寫在那一節，這裡寫適用範圍、哪些目標不算字面絕對路徑，以及長清單、shell 腳本與假資料的處置。

## 破壞性指令規則的適用範圍

這些規則管 agent 執行的 shell 指令，以及規則檔、skill、`bin/` 與 `.githooks/` 的 shell 腳本裡的指令；既有的指令只在這次改到那一行時才照改。`bin/` 與 skill 裡的 Python 由程式算出路徑、由各自的測試驗證，不在此列；容器、雲端資源這類檔案以外的刪除也不在此列；`content/` 文章裡給讀者照做的示範指令不在此列。agent 執行 repo 內的工具時，被改寫的檔案由工具自己決定、由它的檔頭與測試管。「一次執行」指一次工具呼叫（Claude Code 的一次 Bash 呼叫、Codex 的一次指令執行），裡面用 `;`、`&&`、`|` 串起來的都算同一次。

破壞性動作依效果判：刪除、移動或覆寫一個已經存在的檔案，例如 `rm`、`mv`、`git rm`、`git clean`、`find … -delete`、`find … -exec rm`、`xargs rm`、`rsync --delete`、`sed -i`、`truncate`，以及 `>`、`tee`、`cp` 寫到已經存在的檔案。重跑時覆寫暫存目錄裡自己建的檔（例如 `bin/changed-lines … > <暫存目錄>/added.txt`）也屬於 `AGENTS.md` 那一節的例外。

## 不算字面絕對路徑的目標

目標含 `$`（`$HOME` 也算）、反引號或 glob；由 `find` 的條件、管線、檔案內容（`xargs rm < list.txt`）或直譯器（`python3 -c`）算出；相對路徑，而同一次執行的開頭沒有 `cd` 到一個字面的絕對路徑（cwd 不在指令文字裡，前一次呼叫的 `cd` 會延續）。`~` 開頭的路徑算絕對路徑。

展開失敗也不報錯，只改變刪除範圍：`S` 為空時，`rm -rf ${S%/content/books}/` 展開成 `rm -rf /`（其餘的展開結果在依據卡）。

## 長清單、shell 腳本與假資料的處置

- **清單長到寫不進一條指令時**：下一次執行用列出清單時的同一個條件加 `-delete`，條件跟列出清單的那一次逐字相同。agent 自己下的 `for` 迴圈也算要靠條件選出目標。
- **shell 腳本裡的路徑**：相對路徑照腳本檔頭寫明的執行目錄起算，不算〈不算字面絕對路徑的目標〉裡的相對路徑。`${X:?}` 寫在組成路徑的每一個變數上（截取之前的 `${S:?}`、`${SKILL_NAME:?}`），只檢查組好的那個字串擋不到空值：`content/skills/${SKILL_NAME}/skill.md` 在名字為空時仍然不是空字串。截取的結果另存一個變數、印到 stderr，再交給刪除：非互動的腳本裡沒有人在刪除之前核准，印出來的路徑讓事後讀 log 的人看得到實際刪了什麼。
- **shell 腳本裡的檢查與清理**：腳本在一次執行裡先檢查、再清理自己建的暫存檔，不受「檢查與刪除分成兩次執行」限制，變數照上一項寫。
- **自己建的未追蹤檔**：用 `rm` 加字面的絕對路徑刪。
- **正對照的假資料**：重跑時再建一個新子目錄。暫存目錄本來就跟專案隔開，刪除換到的整潔抵不過它帶進來的風險。工具與測試在自己的 `finally`、`tearDown` 裡清掉自己建的暫存目錄不在此列。檢查的工具只讀 repo 工作樹、假資料非放進 repo 不可時，檢查跑完另開一次執行、用字面路徑刪掉，提交之前用 `git status --short` 確認它不在工作樹裡：留在 `content/` 的假資料會被 pre-commit 掃到，擋下其他 session 的提交。
