> **何時讀**：分流連結之前；核對某個網站的頁面、要知道欄位在頁面的哪一區時；要新增或修改一列之前。

## 新增一列的條件與寫法

腳本抓過的網域，核對完都登記一列，這張表才分得出「確認過用 curl」與「沒有人試過」。查證方式那一欄依那一次的結果填：

- **填 `瀏覽器`**：狀態是 403 或 503，或狀態是 200 而腳本印的 `blocked` 欄是 `yes`（頁面含腳本 `BLOCK_MARKERS` 的字樣）。字樣命中的那一種先打開存下來的頁面，確認它是驗證頁或拒絕存取的頁面才登記；正常的商品頁也可能帶到這些字樣。另一種是狀態 200、`blocked` 是 `no`，而書目欄位只在瀏覽器執行完 JavaScript 之後才出現在頁面上；觀察到的回應那一欄寫出這個原因。網域的 robots.txt 禁止商品頁那一類路徑時，也填 `瀏覽器`。
- **填 `curl`**：狀態是 200、`blocked` 是 `no`，頁面上找得到書目欄位，而且 robots.txt 沒有禁止商品頁那一類路徑。
- **不登記**：狀態是 429（請求太密，這是自己的速率造成的，不是網站對 curl 的態度）、000（連不上）、404 或其他錯誤。這些是速率、連結或連線的狀態。

觀察到的回應那一欄寫出日期、在什麼環境觀察到（本機或雲端沙箱，加上大致的地區，例如台灣）、狀態碼，以及 robots.txt 對商品頁路徑的規定，讓之後的人判斷這一列過期了沒、換一個地區是否適用。頁面上取得到的欄位那一欄寫出這次在頁面的哪一區找到哪些欄位、哪些找不到；下一次核對同一個網站時，執行者照這一欄就知道哪些欄位要另外查。

## 把一列從 `瀏覽器` 改回 `curl`

腳本對登記成 `瀏覽器` 的網域不送請求，所以要改回時，先把那一列的查證方式暫時改成 `curl`，只放那個網域的一條連結跑一次腳本。拿到 200、`blocked` 是 `no`，而且頁面上找得到書目欄位時，保留 `curl`，把這一次寫進觀察到的回應那一欄；否則改回 `瀏覽器`。這一次請求用的是腳本平常送的同一組標頭，不算被擋之後換標頭重試。測試結束之前用 `git diff` 確認那一列已經是最後要留的值：中途中斷時，暫時改成的 `curl` 會留在檔案裡，下一次查證就會對那個網站送 curl 請求。
