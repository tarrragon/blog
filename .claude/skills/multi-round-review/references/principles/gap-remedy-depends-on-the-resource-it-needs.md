# 盤點出來的缺口，處置要看補上它需要哪一種資源

> **角色**：本卡是 `multi-round-review` 的支撐型原則（principle）、被「Round N 規劃判讀」段與 [七軸盤點](review-seven-axes.md) 引用。
>
> **何時讀**：盤點出還有哪些軸沒動、準備決定要不要跑下一輪時。

## 核心原則

**盤點出一個未覆蓋的維度之後，處置由「補上它要付出哪一種資源」決定。** 缺口清單長得像一份待辦，而待辦的預設動作是把剛才那個活動再做一次。同一個活動再做一次就補得上的維度，這個預設是對的；要時間、要另一個執行者、要另一個組織才補得上的維度，再做一次補不到任何一格——而報告上「跑了第五輪」與「補上了那個缺口」同形。

判別是一句話：**補上這一項，我要付出的是什麼。** 答案是「下一輪」的照原流程走；答案是時間、另一個人、另一台機器的，處置是建一張票綁上觸發條件。

## 實例：七軸裡未動的兩軸都不是下一輪買得到的

一次四輪、二十餘個 reviewer 的審查跑完，按七軸盤點覆蓋狀況，未動的是 timing 與 instance：

- **Timing** 的切換方式是寫作前、寫作中、寫完當下、寫完一週後。四輪連續跑完，全部落在「寫完當下」——把這一格填滿要的是時間，第五輪買不到。
- **Instance** 要的是另一個來源的視角。同一個 session 派出的 reviewer 拿的是同一份 prompt、繼承同一個框架，換掉執行體取得的是採樣噪音（見 [規模買不到異源視角](review-scale-does-not-buy-independent-origin.md)）。第五輪同樣買不到。

照「未動的軸就是下一輪的價值來源」這條推論走，動作是跑第五輪。而第五輪在七軸上補不了任何一格，它的產出只能來自把 frame 軸再細分——正是七軸卡自己列為反模式的加輪數。**把資源缺口讀成流程缺口，產生的是這套方法自己要防的行為。**

## 停在資源用完與停在證據齊備，寫出來同形

兩者的文字都是「四輪之後停止」。差別在依據，而依據不寫下來就消失：下一個接手的人讀到的是一個已完成的盤點。

處置是停止判定寫成兩句話：哪幾個維度判定為已覆蓋，哪幾個維度判定為取不到、已建票。上面那次的實際落地是兩個軸各建一張票（異源交換掃描、隔一段時間後的冷讀），停止判定改寫為「停在四輪是資源決定」。

## 加輪是「補上缺口」的代理

它比補上缺口便宜（同一套流程再跑一次，不必等時間、不必協調另一個人），它會產生 finding，而報告上它與實際補上缺口長得一樣。三個條件湊齊就是[代理](proxy-is-cheaper-than-the-thing-it-stands-for.md)的定義。所以落點與那張卡相同：改的是盤點表的欄位，不是執行者的自律。

## 修法

**盤點表加一欄「這一軸靠什麼補上」。** 欄位值只有兩類：下一輪、或某一種本輪拿不到的資源。前者留在流程裡，拿不到的那一種出表建票。

**票要綁觸發條件，不綁時程。** 「隔一段時間後冷讀」的觸發是下一次有人要動這份內容；「異源交換」的觸發是有另一個執行者可用。綁時程的票在時程到之前沒有人看得到它。

## 判讀徵兆

- 缺口清單上的某一項，補上它的動作與剛才做完的動作是同一個動作。
- 停止判定只有一句話，說的是「已經夠了」而沒有分開寫哪幾項是覆蓋到了、哪幾項是取不到。
- 盤點表上有一格連續幾輪都是空的，而每一輪的規劃都把它列為「下一輪的價值來源」。
- 補上缺口的計畫寫成一個時程（下週再跑一次），而不是一個觸發條件。
