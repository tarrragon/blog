# Content Pressure Resolves By Expansion Not Compression

> **角色**：本卡是 `compositional-writing` 的支撐型原則（principle）、被原則一（Atomization）的內容壓力段與 [writing-articles](../writing-articles.md) 的自檢清單引用。
>
> **何時讀**：寫作時判準裝不進表格格、概念裝不進標題、範例讓段落過長、想裁內容遷就容器時；或審查時撞到「像簡報的文章」時。

## 核心命題

教學文章的內容超出容器的自然大小時、合法的出口有兩個、壓縮內容遷就容器在這兩個出口之外：

| 出口             | 做法                                                           | 適用條件                                     |
| ---------------- | -------------------------------------------------------------- | -------------------------------------------- |
| 就地展開         | 表格下方加延伸段、判準在正文攤開、標題只承載結論由正文交付推導 | 內容是本篇專屬、其他文章用不到               |
| 外部化成卡片     | 概念拆成知識卡、範例寫進卡片、文章引用卡片承接論證             | 概念會被多篇引用、或概念值得獨立的討論空間   |
| 壓縮內容遷就容器 | 判準裁成殘語、範例被砍、推導縮成口訣                           | 違規——容器該服務內容、方向相反時換出口不裁量 |

出口選擇的判準是**概念角色**：主線概念（本篇論證繞著它轉）必須就地展開——外部化會讓讀者跳出去讀卡、論證線斷裂；支撐與背景概念可以拆卡、卡片自帶範例、文章保留「什麼情境用哪張卡」的判讀敘事。

**擴充的對象是結構、每句的字數另有裁決者**：擴充彈性指的是卡片數、範例數、討論空間可以長——句子的長短由消費單位分配管（見 [sentence-self-sufficiency-by-consumption-unit](sentence-self-sufficiency-by-consumption-unit.md)）、metadata 由精簡規範管。把本卡讀成「全域加長」跟把容器壓力讀成「該壓縮」是同一類錯：都把裁決權交給了錯的層。

## 為什麼內容會被裁去遷就容器

生成端的**容器形狀先驗**：生成文字時、標題傾向固定的長度帶、表格格傾向短語、段落傾向固定節奏——這個規律在輸出端可直接觀察。形狀先驗讓因果方向反轉：本該由內容決定容器、實際上內容被裁切去符合容器的預期形狀——一個需要三句話的判準放進表格格時被裁成殘語、或者作者根本沒展開、因為容器的形狀暗示「這裡只該放這麼多」。人工寫作有同構推力：「讓文章乾淨」是正當追求、用壓縮實現它就走錯了出口——文章變短的合法方式是外部化（細節住進卡片、每篇自然短）、把每句削薄是錯的實現。

## 反模式：簡報式文章

壓縮遷就容器的終點形態：標題句化、表格當主體、格內塞判準殘語、段落退化成條列的連綴——讀者拿到 talking points、缺推導與範例。簡報這個文體的正當性來自**有講者在場補完**、文章沒有講者、把文章寫成簡報等於把補完責任丟給不存在的人。

| 訊號                                     | 判定                                       |
| ---------------------------------------- | ------------------------------------------ |
| 表格是段落的主體、正文只有表格前後各一句 | 每格需要延伸段或拆卡                       |
| 表格格裡是判準殘語（無主詞、指涉懸空）   | 同時命中單句消費位的自足要求、展開或外部化 |
| 段落由條列連綴、沒有推導句銜接           | 條列間的推導被壓掉、讀者拿到結論拿不到理由 |

邊界：**簡報式的判定限教學文章文體**。skill reference 的 checklist、audit 清單、規格表的表格形態合法——消費單位是逐項執行、不是連續閱讀、殘語只要通過單句自足檢查就合規。

## 自查清單

- [ ] 每個表格格裝得下完整判準；裝不下時選了出口（延伸段或拆卡）、沒有裁內容
- [ ] 想外部化的概念是支撐或背景角色；主線概念留在正文行內展開
- [ ] 範例的去處是卡片或正文、沒有被刪掉
- [ ] 文章讀起來有推導句銜接、條列與表格是輔助不是主體
- [ ] 對 checklist / 規格表型內容沒有誤用本卡（那類內容的表格形態合法）

## 跟鄰近原則的分工

- **句自足**（[sentence-self-sufficiency-by-consumption-unit](sentence-self-sufficiency-by-consumption-unit.md)）：那卡管句子的成分完整度、本卡管內容的量對容器的關係；表格格是交會點——格內殘語同時違反兩卡。
- **原子化**（SKILL.md 原則一）：拆卡的單卡 scope 仍由原子化判準管（認知負擔、focus 完整度）；本卡管「何時該拆」、原子化管「拆出來的卡合不合格」。
- **判定分工**（[multi-pass-review-frame-granularity](multi-pass-review-frame-granularity.md) 的判定層段）：「表格當主體」是候選不是判決——判定看文體與消費單位、checklist 型內容合法。

**核心**：容器該服務內容。內容裝不下時、換出口（延伸段）或換容器（卡片）、內容量本身不是可裁的變數——文章要短、讓細節搬家、別讓細節消失。
