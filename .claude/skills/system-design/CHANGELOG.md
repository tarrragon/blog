# system-design 版本紀錄

新到舊。版號的兩個住址是本檔與 `SKILL.md` frontmatter 的 `metadata.version`。

**Version**: 0.13.5 — decision-timing 兩條與 SKILL.md 分工表的實作指向改成 saas-tech-selection 新拆出的 implementations/ 兩份檔案。

**Version**: 0.13.4 — 多輪審查 Round 4 修正：decision-timing 費用那一條的驗收程序縮成一句並指向 principle 卡與 saas-tech-selection、修正標點；觸發詞收窄成管理通道與支出停損。principle 卡同 saas-tech-selection 1.10.4。

**Version**: 0.13.3 — 多輪審查 Round 3 修正：decision-timing 的觀察期寫明涵蓋最長週期的排程；停損驗收寫出先低於後超出、測完重新連結、已上線改用可拋棄複本，刪掉實測證據句。SKILL.md 分工表補「既有專案只想處理管理通道或費用停損」的路由。principle 卡同 saas-tech-selection 1.10.3。

**Version**: 0.13.2 — 多輪審查 Round 2 修正：decision-timing 管理通道條寫明「收斂」是第一台時沒做、事後才收掉全開規則的情形；費用失控條刪掉括號裡的實測證據，測試訊息改成低於與超出預算各一則，與 saas-tech-selection 一致。

**Version**: 0.13.1 — decision-timing〈先做〉的管理通道條改寫：網路層只放行身分感知代理或 VPN、登入改用 OS Login 或 SSH 憑證，兩層分開寫（原句把 SSH 憑證放在「放行」那一層），成本枚舉限定在 GCP；費用失控條補上預算通知花費為 0 也可能來自抵免、停用帳單時資源可能被永久刪除。principle 卡 `protection-proves-itself-by-firing` 依多輪審查修正：段標改寫、補合成觸發的定義句、低於預算的訊息兩個權限都沒用到、正對照改成不依賴同一個欄位的查詢、靜默監看寫明監看的是觸發來源的訊息、補英文錨點。

**Version**: 0.13.0 — decision-timing〈先做〉新增兩條：登入主機與叢集的管理通道從第一台就只放行身分感知代理或 SSH 憑證（第一台時是一條規則、一個角色與一個 metadata 鍵，之後收斂要盤點依賴舊規則的連線、依序停用驗證刪除，救援入口事先登入過，template 建的主機寫進 template）；決定費用失控時的處置（警示不停止扣款、計費資料落後數小時以上，寫下誰收警示、多久處理、要不要自動解除帳單連結；建了停損就以超出預算的測試訊息實際觸發一次）。新增 principle 卡 `protection-proves-itself-by-firing`（平常不動作的防護機制以合成觸發驗收）。SKILL.md 補觸發詞。來源是一次 GCP 測試專案上的管理通道與帳單停損開關實機驗證。

**Version**: 0.12.0 — decision-timing〈先做〉：主機外的訊號要心跳監看與外部探測兩種都有，寫明兩者成立的條件（不共用失效域、通知管道與帳號不經過被監控的主機、觀察者自己有人看），單台主機第一天就接（原句「至少一個訊號放在主機之外」改寫，與兩種都要一致）；備份三種做法寫明擇一；連線清單寫明逐台假設、一次一台；新增「備份放到另一個業者或帳號，而且寫入它的憑證刪不掉、覆寫不了既有的備份」與「兩個網路接起來時先寫連線清單再開通」兩條（每一台各假設一次被入侵、限制放在被入侵的那一台改不到的地方、管理者裝置的處置）。escalation-triggers 基礎設施表新增「第二台主機（先給監控）」一列，表後寫明多一台主機時的用途先後（備份、監控、副本）。新增 principle 卡 `independence-is-what-the-guarded-side-cannot-disable`。來源是一組單機監控、兩到三台主機配置與跨網路連線安全文章的五輪審查。

**Version**: 0.11.3 — 多輪審查 Round 3（誤用梯度）：量測紀錄寫機器、指令、量測前與期間的值與門檻出處，使用者沒給門檻時不自訂而標「未經門檻判定」；共用主機的限制要寫出線上與批次並讓批次的值較低，主機外的訊號寫明跑在哪裡（同一份 compose 的探測不算）；需求盤點的尖峰重疊不知道時寫「未知」與要看的指標

**Version**: 0.11.2 — capacity-estimation 的主機前置檢查寫明看哪兩個值、門檻由使用者定並記錄，並分開 CPU 與磁碟（虛擬機裡可能看得到主機磁碟）；decision-timing 的資源限制指名部署設定的鍵

**Version**: 0.11.1 — 需求盤點的筆電共用說法修正：虛擬機裡看不到的是 CPU 負載，磁碟要確認看到的是哪一顆

**Version**: 0.11.0 — 共用主機作為設計條件：需求盤點新增「哪些服務、資料庫與監控共用同一份資源」，容量估算的非正式環境數字要附主機負載並先確認主機安靜，先做類新增共用主機的服務先寫下共用關係、用限制分開、監控至少一個訊號在主機之外，觸發指標表新增依角色分開部署

**Version**: 0.10.0 — 先做類新增：多套實作共用的規格寫成可執行的形式，當成每一套的比對基準，規格寫完就實際執行一次

**Version**: 0.9.0 — 容量估算的儲存逐表分成有保留期與不刪除兩類，新增〈不刪除的表：逐條查詢讀的量〉（讀的頁數由回傳筆數還是表的列數決定、列表排除大宗類別時分類欄位的位置與部分索引）；先做類新增列表索引對齊篩選與排除條件、同一批建立的資料共用的值存在批次那一列；觸發指標表的分割補唯一約束的前提，分片改以索引是否放得進記憶體、autovacuum 與建索引耗時為訊號、不以列數，新增冷熱分離一列

**Version**: 0.8.0 — 分類依據補「已寫入的資料」的追問：有沒有人需要舊資料以新形式出現，沒有則只影響切換之後的資料、可延後；先做類新增統計彙總以 UTC 時段存並依時區組日、事件去重識別碼由產生端給、排程互斥與最後成功時間放在每種實作都看得到的共用儲存；需求盤點新增報表的一天依哪個時區切、事件最晚多晚寫入，業務約束新增「要看某個比率」先確認訊號歸得到人（追蹤圖片被隱私保護與安全掃描觸發）；觸發指標表新增熱點列計數拆開、彙總改寫入時累加、彙總改更細時間粒度

**Version**: 0.7.0 — 定案類新增「會被客戶端存起來再送回來的值的格式」（分頁的接續標記、時間格式；滾動部署時由另一版本解讀，改格式要分兩次部署，框架內建的接續標記格式不可攜）與「登入憑證的撤銷以什麼為單位」（比對依據須是撤銷當下拿得到的東西：單一 token 只撤銷得了手上那個，停用帳號要以使用者為單位）；需求盤點新增「停用帳號、改權限之後多久要失效」與「每個報表維度在寫入時有沒有記下」（寫入時沒記的補不回、原始資料只回溯得到保留期內、多份文件列的維度要對同一份資料模型）

**Version**: 0.6.0 — 加入健康檢查：定案類新增「保留給固定路由的路徑」（`/{code}` 這類整段參數的路由與 `/healthz` 等固定路徑同名時，依明確度匹配的路由器交給固定路徑、依註冊順序的交給先註冊者，同名識別碼發出後收不回；三種避開方式依維護成本排列，最省的是固定路由使用參數字元集外的字元）；先做類新增「服務的健康檢查與它失敗之後的處置」（依服務類型的健康訊號：HTTP 端點、worker 心跳、批次的完成回報、serverless 的平台告警；訊號保證什麼、誰讀、讀到失敗誰做什麼；Compose 不因 unhealthy 重啟、入口等上游健康會連鎖起不來）；需求盤點〈基礎設施〉新增「服務掛了由誰發現、由誰恢復」

**Version**: 0.5.1 — 分工表下補一句：表中的 skill 不一定安裝在每個專案，未安裝時情境欄的工作仍要做

**Version**: 0.5.0 — 分工表修正：migration-playbook-methodology 是寫遷移系列文章的寫作方法論、不是執行遷移的指南，該列改指向本 skill 的〈先擴充才能上線或切換的變更〉；新增 wrap-decision 絆腳索一列（延後項目的觸發指標就是絆腳索）；foundation-design 一列寫明接的是先做類裡的地基產物。新增「開發順序」產出：延後類也都要實作時（練習、原型），排成較後的階段並以前後壓測對照

**Version**: 0.4.0 — 「練習專案／學習目的」擴大為「目的不是上線服務的設計」（原型、提案 demo、學習或比較），要求記下跳過了哪些設計，並把目的改變列為重新分類的觸發點；依行動 App API 契約文章的審查修正 release-and-rollout：回退手段不再依速度排列、遠端設定生效時間改依讀取間隔（Firebase 預設 12 小時）、暫停分階段發布移出回退清單、強制更新分兩層、補提高最低支援版本前要分出拿不到新版的使用者、補 Apple DPLA 3.3.1(B) 與 Google Play 的熱更新條款、補 Feature Flag 預設值與移除時機、補版本比較與缺版本請求；decision-timing 把 header 與錯誤碼格式移到定案

**Version**: 0.3.1 — 熱更新的商店政策改依 Apple App Review Guidelines 2.5.2 原文（先前寫的「不改變主要用途」沒有原文依據）；範圍限制註明各工具不同（Shorebird 不能更新素材檔）
