# knowledge-cards 版本紀錄

新到舊。版號規則與兩個住址（本檔與 `SKILL.md` frontmatter 的 `metadata.version`）見專案的 skill 同步規範。

**Version**: 1.7.1 — 術語校正：判準全數改為判斷標準（動作修飾語縮為「X 標準」、狀態義改為「X 條件」）。判準的語域在哲學與教育評量、工程讀者解析不了——五份低階模型探針一致回報非通用

**Version**: 1.7.0 — 站 2 的卡層載體判斷標準換掉理由。原本寫「卡層通常是住址——入連數高於任一章節」，而實測推翻了那個前提：以連進來的檔案數計，其中一個章節是卡的一倍多。錯在量測單位——入連數量的是整頁被引用幾次，而要選載體的對象是頁裡那組成員，那個章節的入連幾乎都指向它的主題、沒有一條是為了拿欄位定義。理由改成「欄位與成員的定義本來就是卡的責任」，並明寫不要用入連數當理由。這是同一個判斷標準在三份副本裡的第二次修正（前一次是選法順序被推翻），而兩次的成因相同：原則卡改了而 skill 的操作化副本沒跟上。

**Version**: 1.6.0 — 站 2（落點）補卡層載體判斷標準：同一個對象已在兩篇各自被分解過（兩套階段表 / 欄位組 / 責任清單）時，卡層通常是該收斂到的住址——入連數高於任一章節、本來就是可被多篇引用的獨立短頁，章節沿用卡的語彙並各自只留判讀。從一批三章改寫的審查抽出：該批的證據包欄位在兩章各被重述一次（七項）而卡是八項，兩章都宣告「規格由卡承載」而讀者照章節填會少一欄。

**Version**: 1.5.1 — 站 1′ 表格格修正：補回被省略的賓語（「砍掉範例或推導讀者就接不住」）、位置式引用「（見下）」改段名引用「見『內容壓力是第二個建卡入口』段」、「（站 1）」補名詞頭「（站 1 判斷標準）」——表格格是單句消費位、依句自足原則展開。

**Version**: 1.5.0 — 新增「內容壓力是第二個建卡入口」段與生命週期站 1′：教學需求從讀者缺口出發、內容壓力從寫作現場出發（概念展開過長、判斷標準裝不進表格格、砍了讀者接不住）、兩入口指向同一動作；明文「範例是卡片的正當組成」（概念加範例住進卡片、文章引用、細節搬家而非消失）與兩條邊界（拆卡限支撐 / 背景概念、主線行內展開優先；壓縮遷就容器在出口之外）。對應容器層原則「內容超出容器時擴充結構、不壓縮內容」、經 WRAP 評估帶邊界落地；同步修正 frontmatter 版號漂移（1.3.0 → 1.5.0、changelog 實際已到 1.4.0）。

**Version**: 1.4.0 — gap-audit-and-backfill 補「消費側 audit」段（從一次多輪審查 Round 3 outbound 回收：兩張缺卡與一張分類矛盾都不是建卡當下的術語掃描抓到、是反向連結輪抓到）：缺卡 / 孤兒 / 矛盾三種問題住在卡↔文章的關係邊上、不住在單卡或正在寫的單篇裡——單卡結構檢查與建卡當下的單篇掃描都看不到；觸發點是寫 / 改用到既有概念的文章時 re-audit 那些卡（缺 + 錯），outbound frame 是這一輪的制度化位置；自檢清單加對應項。判定矩陣是建卡當下 / 供給側、消費側 audit 是第二個發現點、兩者互補
**Version**: 1.3.0 — 從第一輪全站 audit（4 掃描 fork + 3 建卡代理 + 3 債務艦隊、19 張新卡、338→6 warning）回收判定補充規則：(1) 「無卡」比對範圍是全站所有卡片目錄含同義詞——實測擋下 4 張would-be重複卡；(2) 跨篇逐字重複定義是缺卡加強訊號、建卡後收斂重複句；(3) 「連長文」含同章段落式教學；(4) 模組索引 backlog 筆記是候選來源、以正文實際出現做最終判定；(5) L4 首段判定精確化（AST 第一段、遇空行即止）；(6) L2 孤兒的 `_index.md` 本文算有效來源、無真實出現走存廢清單且刪卡由維護者裁決
**Version**: 1.2.0 — gap-audit-and-backfill 補「規模化執行：代理人派工協議」段（從第一次全模組回填的多代理實測抽出）：prompt 給清單與底線、判斷標準指向 skill；事實紀律顯式重申；回報必含完成度自證（實測主要失誤是代理靜默停止不回報）；驗收以 repo 狀態為準不以報告為準；多代理飛行中主線不提前 format / commit；每次派工同時回收 skill 完整性回饋
