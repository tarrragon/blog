# Changelog

**Version**: 1.2.0 — `references/popup-state-rendering.md` 新增〈亮色與暗色模式〉（popup 與其他擴充功能頁都適用）：建立分頁時帶 `colorScheme` 或在 `goto` 之前 `page.emulateMedia` 切模式，各截一次（`goto` 之後才切時，只在載入時讀一次 `matchMedia` 的腳本停在舊模式）；用 `getComputedStyle` 核對該換色的元素換了、不隨模式換色的元素沒變，讀到透明時往上讀不透明的祖先（漸層、圖片、半透明與脫離文件流的元素改看截圖），讀回的格式依寫法而不同；暗色只套部分範圍的頁面另查範圍邊界（文字色停在亮色、對話框沒帶範圍屬性、原生控制項沒跟 `color-scheme`），對話框打開之後再讀一次。〈切到每一個狀態〉第 1 步指向這一節。SKILL.md 路由表與觸發詞補亮暗模式。

**Version**: 1.1.0 — 範圍從 popup 擴大到其他擴充功能頁：`references/popup-state-rendering.md` 改成渲染擴充功能頁，新增〈popup 以外的擴充功能頁〉（假 storage 依 key 回傳測試資料、只顯示 http(s) 圖片的頁面用假的 https 網址加 `page.route`、捲動後的狀態只截視窗範圍並說明 `fullPage` 截圖對 fixed 與 sticky 元素的假象、偏好存在 `localStorage` 時每個狀態用新的 context）。SKILL.md 共通規則加「測試輸入取下一層實際收到的形狀」：一次存錯 storage key 的錯誤沒被測到，因為測試手寫的事件明確帶了正確的 `source`，跳過了轉送層把它覆蓋成物件的那一步。新增〈測試開出的瀏覽器：關閉與殘留〉：預設 headless（照 `references/loading-and-markers.md` 的設定）、在 `finally` 關閉、啟動到一半失敗時程序可能已經開出來而變成孤兒、跑專案既有的測試套件時瀏覽器 E2E 只用它指定的設定跑、測完用 `pgrep`（macOS `-fl`、Linux `-af`）與 profile 目錄名查殘留，pattern 的第一個字母包進方括號（Linux 的 `pgrep` 不排除包住指令的那層 shell），列含 `--user-data-dir=` 而不含 `--type=` 的主程序 PID 交給使用者決定關閉；跑專案既有的套件之前列出實際用的設定檔、`testEnvironment` 與 `testMatch`；headless 要帶 `channel: 'chromium'`。〈限制〉的換瀏覽器那一條改成：換 Chrome for Testing 或 Chromium 大版本時重跑正對照，品牌版 Google Chrome 與 Edge 的新版本不接受 `--load-extension`，不必試。`references/loading-and-markers.md` 的關閉那一步改成 `try … finally`，並在 `close()` 之前跑一次 `pgrep` 當測完那一次的正對照。`references/popup-state-rendering.md` 的擴充功能頁一節另寫視窗尺寸、假 storage 依 MV3 語意處理物件、`null` 與不帶引數、捲動後等事件與轉場跑完再截圖。來源：在預設 jsdom 設定下誤跑專案的 Puppeteer E2E，留下 8 個只有空白分頁的 Chrome 視窗。description 加觸發詞。

**Version**: 1.0.0 — 初版：以 `--load-extension` 全新載入建置副本驗證 content script 與 service worker（本機頁注入、標記、CDP 停 service worker 與狀態序列、正對照），以 `file://` 加假 chrome API 渲染 popup 各狀態（API 形狀比照 MV3、握手要回應、連線中用拒絕模擬），以及限制（`chrome.runtime.reload()` 讓 `--load-extension` 載入的擴充功能消失、拿不到登入狀態與真實 DOM）。內容來自一個 MV3 擴充功能專案 popup 改版與開發迴圈實驗。
