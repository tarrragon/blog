CGNAT（carrier-grade NAT，電信業者級 NAT）是電信業者在自己的網路裡做的位址轉換：好幾戶用戶的連線共用同一個公開 IPv4 位址出去，用戶家裡的路由器拿到的 WAN 位址是電信業者內部的位址，不是網際網路上連得到的位址。它跟 [NAT Gateway](/devops/infra/knowledge-cards/nat/) 做的是同一種轉換（改寫出站封包的來源位址），差別在由誰營運、替誰轉換。電信業者內部用的位址常落在 RFC 6598 為這個用途保留的 `100.64.0.0/10`（共用位址空間，shared address space），有些業者用的是 RFC 1918 的私有位址段。

## 跟其他概念的關係

家用網路在 CGNAT 後面時，封包從主機到網際網路要經過兩層 NAT：家裡的路由器把區網位址轉成電信業者內部的位址，電信業者的 CGNAT 再把它轉成共用的公開位址。出站的連線兩層都會自動建立對應，所以上網、拉套件、主機主動往外連都照常可用。

入站的連線要靠某一層預先有對應。家裡的路由器設連接埠轉送（port forwarding），是在路由器上做 [DNAT（目的位址轉換）](/devops/infra/knowledge-cards/dnat/)，把送到路由器某個連接埠的封包改送給區網裡的主機；可是外面的封包送到的是電信業者那個共用的公開位址，先到 CGNAT，CGNAT 上沒有對應這一戶的轉送規則，封包在那裡被丟棄，永遠到不了家裡路由器上的那條 DNAT 規則。用戶管不到電信業者那一層，所以在 CGNAT 後面，靠連接埠轉送接受入站連線的做法都用不了。

NAT Gateway 指雲端用戶在自己的 VPC 裡建立的出站閘道，用戶自己決定哪些 subnet 經過它、付它的費用，它後面的主機想接受入站連線時，可以在前面放負載平衡器，或改放到路由指向 Internet Gateway 的公開 subnet 並掛公開位址（留在預設路由指向 NAT Gateway 的 private subnet 裡掛公開位址，入站連線照樣進不來）；CGNAT 指電信業者替許多用戶做的出站轉換，用戶看不到也改不了它的設定，入站的路徑整個不存在。

## 可觀察訊號與例子

- **路由器的 WAN 位址跟外面看到的位址不同**：路由器管理頁顯示的 WAN 位址落在 `100.64.0.0/10`（`100.64.0.0` 到 `100.127.255.255`）或 RFC 1918 的私有位址段，而從主機去查「外面看到的公開 IP」的服務回的是另一個位址，代表兩者之間還有一層 NAT。那一層不一定在電信業者那裡：電信業者給的數據機兼路由器跑在路由模式、後面再接自己的路由器時，家裡自己就有兩層 NAT，這一層用戶改得了（把數據機改成橋接模式，或在數據機上也設轉送）。分辨的方法是用 `traceroute` 看離開自己路由器之後的下一跳：下一跳是家裡的另一台設備，是自家的雙層 NAT；下一跳已經在電信業者的網路裡、或是 `100.64.0.0/10` 的位址，才是 CGNAT。WAN 位址跟外面看到的位址相同時，路由器拿到的是公開位址，入站連不進來的原因在別處（路由器或主機的防火牆、電信業者擋了特定連接埠）。這一條看的是路由器的 WAN 位址；主機上看到的 `100.x` 位址可能屬於 [Mesh VPN](/devops/infra/knowledge-cards/mesh-vpn/) 的介面（Tailscale 借用同一段位址），要先看它在哪一個網路介面上。
- **連接埠轉送設好了，從外面連照樣逾時**：從家裡以外的網路（手機的行動網路）連自己的公開 IP，連線沒有回應；在路由器上看不到任何進來的封包紀錄。
- **同一個公開位址被別人的行為影響**：共用同一個位址的其他用戶觸發了某個網站的速率限制或封鎖，這一戶的連線也被一起擋下，因為網站看到的是同一個來源位址。

## 判斷條件與後果

家用網路在 CGNAT 後面時，任何要求「主機從網際網路連得進來」的入口都接不上：DNS 紀錄沒有可填的公開位址，連接埠轉送沒有作用。仍然可用的是由主機主動往外建立連線的做法，因為出站在 CGNAT 後面照常運作：[Outbound Tunnel](/backend/knowledge-cards/outbound-tunnel/) 讓公開服務經由服務商的邊緣送進來；[Mesh VPN](/devops/infra/knowledge-cards/mesh-vpn/) 讓自己的裝置互連，CGNAT 這類位址轉換讓兩端之間打不通直接連線時，流量改經中繼伺服器轉送，連線照樣建得起來，延遲較高（中繼的機制見 [Tailscale 深入：tailnet、MagicDNS、直連與 DERP 中繼](/linux/tools/remote/tailscale-tailnet-and-relay/)）。兩類做法各自要求什麼、經過第三方代理要接受哪些限制，見 [5.10 Outbound Tunnel 入口與生命週期](/backend/05-deployment-platform/outbound-tunnel-entry/) 的〈家用主機對外提供網站時接上 Cloudflare 的兩種方式：Proxied 紀錄指向公開 IP 與 Cloudflare Tunnel〉。

家用網路同時有 IPv6 時，IPv6 不經這一層 NAT，主機可能有一個從外面連得進來的 IPv6 位址，只有具備 IPv6 連線的訪客連得到它；家用路由器的 IPv6 防火牆常預設擋入站（RFC 6092 建議家用閘道對 IPv6 做有狀態的過濾），要在路由器上另外放行（這是依 IPv6 不經 NAT 的機制推論，各家電信業者與路由器的實際預設沒有查證）。有些電信業者提供改配公開 IPv4 位址的選項，有沒有、要不要另外付費依業者與方案而定，查法是讀方案的條款或問業者；換成公開位址之後，主機回到可以用連接埠轉送接受入站連線的條件，也就同時要自己負責那些連接埠上的防護。
