這張卡談退出路徑的到達成本，也就是讀者從目前的位置到按下退出路徑要走幾步（其他資料常寫作 interaction cost，範圍更廣）：放在頁首的「回到文章」會跟著頁首捲出畫面，讀者讀到中段想離開時，要先捲回頂部、再按一次。[U.C1 Terminal 畫面五個狀態零個退出路徑](/ux-design/cases/five-states-zero-exits/) 處理的是完全沒有退出路徑，這一張處理的是有退出路徑、但要多走一步才到得了。

## 觀察

本站的 SQL 練習頁（Web，桌機與手機兩種寬度）在頁首放一條導覽列：左邊是各階段的名稱，右邊是「回到文章」按鈕，按下它回到讀者進來的那一篇文章。一道題目的畫面很長：題目、資料表結構、四個選項的 SQL 與解析，桌機上一題超過三個畫面高。

讀者有兩條進入路徑，瀏覽器的上一頁在兩條路徑上的行為不同。從文章結尾的練習連結直接進入一輪題目時，頁面用 history API 取代那一筆瀏覽紀錄，上一頁一步就回到文章。經由練習首頁開始一輪時，進入題目新增一筆紀錄、換題時取代那一筆，上一頁回到的是練習首頁，不是文章；這條路徑上，「回到文章」是唯一一步就回到文章的路徑。下文談的是這一條。

元件規格的 [Screen State Matrix（畫面狀態矩陣）](/ux-design/knowledge-cards/screen-state-matrix/) 裡，「題目・已作答」那一列的退出路徑那一格寫的是「文章 → 離開後可回來」，這一格不是空的。本站作者看元件展示頁（把每個元件的各種狀態排在同一頁、供檢視用的頁面）時指出：讀到最後一個選項的解析、想回文章查一個觀念時，按鈕已經跟著頁首捲走，要先捲回頂部、再按一次。離開從一步變成兩步，捲得越深，捲回去的距離越長。鍵盤使用者往回按 Shift+Tab 回到頁首的按鈕，要按的次數等於中間隔著的可聚焦元素數，題目讀得越後面，次數越多。

## 判讀

1. **畫面狀態矩陣的退出路徑欄只記「有沒有」，沒記「從哪裡到得了」**。矩陣的一列對應一個狀態，長頁面的同一個狀態卻是一段捲動範圍，退出路徑的到達成本隨讀者所在的捲動位置與焦點位置變化。欄位填了，讀者仍然可能在大部分位置要兩步才離開。

2. **長頁面的退出路徑，到達成本不該隨深度增加**。這一條在頁面會改寫瀏覽紀錄（單頁應用、分步表單）、或退出的目的地不是上一頁時成立；靜態長頁面在沒有用頁內錨點跳轉時，瀏覽器的上一頁在任何捲動位置都是一步，不受影響。讀者在中段讀到一個不懂的觀念、想回文章對照時，頁首已經捲出畫面；頁首的按鈕只在讀者剛進來、還沒往下捲的那一段捲動範圍看得到。深度同時以兩種方式計：滑鼠與觸控讀者捲回去的距離，以及鍵盤讀者要按的 Tab 次數。

3. **桌機與手機的垂直空間不同，常駐一條精簡頂列的代價也不同**。桌機的畫面高度容得下這條頂列一直在；手機的畫面高度有限，底部已經有「下一題」的動作列，頂部再常駐一條會佔掉內容的高度。常駐的頂列另外會跟正在取得焦點的元素重疊：鍵盤移動焦點時瀏覽器不會自動避開它，被聚焦的按鈕可能整顆藏在頂列底下（WCAG 2.2 的 2.4.11 Focus Not Obscured 管的就是這一種）。

## 策略

1. **退出路徑的到達成本寫進畫面狀態矩陣**：替長頁面的狀態在退出路徑欄加寫「在哪個範圍內一步到得了」，例如「頁首可見時一步；其餘捲動位置兩步；鍵盤從內容中段要按 N 次」，要兩步或要按很多次的那一段就是要處理的缺口。

2. **捲過頁首之後補一條精簡頂列**：只放目前位置（「階段二・第 3／6 題」）、「回到頂部」與「回到文章」，不重複整條導覽列（其他資料常寫作 sticky header，往下捲收起、往上捲出現的那一種也叫部分常駐的 header）。桌機在頁首捲出畫面後常駐；在手機上，讀者往下捲時精簡頂列收起、往上捲時出現，跟手機瀏覽器網址列的行為一致。手機上往上捲一小段就出現，到達成本固定是兩個動作，不隨深度增加。頂列常駐時，頁面的 `scroll-padding-top` 設成頂列的高度，鍵盤移動焦點與錨點跳轉時目標才不會停在頂列底下。鍵盤讀者的 Tab 次數不會因為頂列而減少，另外給一個不靠捲動的入口，例如跳到導覽列的連結或快捷鍵。

3. **精簡頂列收起時，裡面的按鈕不在 Tab 順序裡**：收起時把精簡頂列往上移出畫面，並設成 `visibility: hidden`。元素設成 `visibility: hidden` 時，瀏覽器把它與它的子元素移出 Tab 順序與無障礙樹（子元素自己沒有另外設回 `visible` 的話）；只把透明度降到 0 時，按鈕看不見卻仍然拿得到焦點。焦點正好在頂列裡時不收起，等焦點離開再照捲動狀態決定，否則焦點會留在一個看不見的按鈕上。

4. **「回到頂部」之後，焦點跟著回到導覽列**：按下「回到頂部」、頁面捲回頂部之後，腳本把焦點移到導覽列上讀者目前所在的那個階段，鍵盤使用者不必從頁首重新找起。

5. **兩條頂列不同時出現，也不疊在宿主的頁首上**：精簡頂列只在完整的頁首捲出畫面之後出現；兩者同時出現在畫面上，會被讀成兩個 header。宿主頁面另有自己的 sticky 頁首時，精簡頂列的位置從宿主頁首的下緣算起，否則兩條疊在一起，頂列上的按鈕被宿主頁首蓋住。
