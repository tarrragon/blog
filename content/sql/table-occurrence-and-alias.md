`FROM` 裡寫下的表名指的是那張表在這個查詢裡的一次出現，而那個名字是這次出現的稱呼。標準把這件事叫 table reference，關聯代數那一側的傳統名稱是 range variable，各家文件裡也常寫成 correlation name——三個名字說的是同一件事。同一張表因此可以出現兩次、各自扮演不同角色——這就是自連接。

這個區別在一張表只出現一次的時候看不出來。出現兩次就開始有代價：兩次出現共用同一個名字，引擎分不出某個欄位屬於哪一次，於是擋下來。

引擎把這件事講得很明白。同一張表寫兩次而不另外命名，PostgreSQL 直接回 `table name "訂單" specified more than once`；SQLite 與 DuckDB 在引用欄位時才擋下來，訊息分別是 `ambiguous column name` 與 `Ambiguous reference to column name`。**表名本身就是預設的別名**，所以同一張表的兩次出現共用同一個名字時，等於兩次出現叫同一個稱呼，之後每一次引用都無從分辨。

## 同一個機制也管兩張不同的表

欄位的歸屬要靠名字決定，所以兩張不同的表共用一個欄名時同樣分不開。書店的顧客表與訂單表都有 `顧客編號`：

```sql
SELECT 顧客編號 FROM 顧客 LEFT JOIN 訂單 ON 訂單.顧客編號 = 顧客.顧客編號;
-- MySQL:  ERROR 1052: Column '顧客編號' in field list is ambiguous
-- SQLite: ambiguous column name: 顧客編號
-- DuckDB: Ambiguous reference to column name "顧客編號"
```

`id` 是這件事最常撞到的名字，因為多數表都有一個。**連接之後每個欄位引用都要能追回它屬於哪一次出現**，加上表名或別名當前綴就解決。

自連接只是這個規則的極端情形：兩次出現連表名都一樣，所以連前綴都救不了，非取別名不可。

## 給了名字，兩次出現就分得開

訂單表裡的兩張單都掛在佳穎名下。要找出同一位顧客的訂單先後配對——哪一張在前、哪一張在後。這件事需要把訂單表的兩列擺在一起比較，而一列一列處理的查詢做不到，除非讓訂單表出現兩次：

```sql
SELECT 早.訂單編號, 早.下單日, 晚.訂單編號, 晚.下單日
FROM 訂單 AS 早
JOIN 訂單 AS 晚 ON 早.顧客編號 = 晚.顧客編號 AND 早.下單日 < 晚.下單日;
-- 101 | 2026-03-02 | 102 | 2026-03-09
```

`早` 與 `晚` 是同一張表的兩次出現。連接條件在做兩件事：`顧客編號` 相同把配對限制在同一個人身上，`下單日` 的大小關係決定哪一次出現扮演「早」、哪一次扮演「晚」。

**條件裡的第二項是這個寫法的重點。** 少了它，每張訂單會跟同一位顧客的每張訂單配對一次，包括跟自己配。加上嚴格的大小比較之後，每一對只留下一個方向，而同一張訂單跟它自己組成的那一對，因為兩邊日期相等也被排除。同一位顧客三張訂單時實測回三對（101-102、101-103、102-103），不多不少。

## 自連接處理同一張表裡兩列之間的關係

自連接處理的是**同一批資料裡兩筆資料之間的關係**——兩列，不是兩個欄位。一列一列的處理看不到這種關係，因為每一列在被判斷的時候不知道其他列長什麼樣子。

常見的形態有三種。**前後配對**：同一位顧客的訂單先後配對，把時間上相鄰或有先後關係的兩列擺在一起。**同組比較**：找出訂單金額高於同一位顧客其他訂單的那些，比較的對象是同一張表裡的兄弟列。**層級關係**：一張員工表裡每個人有一個主管欄位指向同一張表的另一列，要把人與他的主管一起列出來時，員工表出現兩次，一次當員工、一次當主管。

三種的共同點是**要比較的兩列住在同一張表裡**。判斷需不需要自連接分兩步：先問這個問題要不要拿一列去跟同一張表的另一列比，要才進入第二步；第二步問要不要把另一列的欄位輸出出來。

第二步是 [1.7](/sql/in-exists-join/) 那條判準——自連接也是一種 `JOIN`，所以它同樣適用。只是判斷「有沒有另一列符合條件」而不輸出它，用 `EXISTS` 比自連接省一次配對展開；要把兩列並排列出來（像上面的訂單先後配對），才非自連接不可。

**「每組最大值」這一類要多問一句：輸出的是自己那一列，還是對方那一列。** 「找出每位顧客金額最高的訂單」要的是自己那一列，所以寫成 `NOT EXISTS (…比我大的…)` 就夠；「找出每筆訂單與同顧客下一筆的差額」要的是對方那一列的欄位，那就非自連接不可。

這一類有兩個邊界要順手決定。**並列的最大值**——`NOT EXISTS (…比我大的…)` 會把並列的那幾筆全部留下，要只留一筆得另外加一個決勝的條件（通常是編號最小的那筆）。**可為空的比較欄**——`NULL` 跟誰比都判不成真，所以「沒有人比它大」對它恆成立，那一列會被選成最大；要排除它就在子查詢裡加一句 `IS NOT NULL`（機制見 [1.5](/sql/join-changes-rows-and-nulls/)）。

## 別名不只用在自連接

同一張表只出現一次的時候，別名的作用是縮短引用。長表名在有三四張表的查詢裡會讓每個欄位引用都變得很長，取一個短別名之後可讀性差很多。

而作用不只是省字。取了別名之後原本的表名在這個查詢裡就不再是它的稱呼，三個引擎都會擋下來：PostgreSQL 回 `invalid reference to FROM-clause entry for table "訂單"` 並附上一句提示要改用別名，SQLite 回 `no such column`，DuckDB 回 `Referenced table "訂單" not found`。`FROM 訂單 AS 早` 宣告的是「這次出現叫早」，而宣告過後就只有這一個稱呼。

## 表的別名與欄位別名落在求值順序的兩端

`SELECT` 裡的 `AS` 替算出來的欄位取名，`FROM` 裡的 `AS` 替表的一次出現取名。兩者的作用範圍不同，可用的時機也不同。

表的別名在 `FROM` 那一步就成立，所以 `WHERE`、`GROUP BY`、`ON` 全部用得到它。欄位別名到 `SELECT` 那一步才誕生，所以 `WHERE` 照語意模型用不到（見 [1.2](/sql/clause-evaluation-order/)）。兩個 `AS` 長得一樣而落在求值順序的兩端。
