位置篇按責任範圍組織，不按職稱。同一個職稱在不同組織對應的責任差很多——三十人公司的「資深工程師」經常同時對別人的產出與技術品質負責，五百人公司的同一個職稱可能只對自己的產出負責。職稱與實際責任一致時兩者等價，不一致時以責任為準；責任軸的代價是它要自我診斷，而職稱是外部給定、查得到的。下一段的判準就是為了讓這個診斷有可操作的做法。

每篇處理三件事：這個位置一天實際在處理什麼、同一個責任範圍在制度成文與不成文的組織裡問題差在哪、以及往相鄰位置移動前該預習什麼。制度化程度才是那一段的軸，人數只是粗略訊號——三百人的家族企業可能沒有職級帶，八十人的新創可能整套沿用大廠的 ladder。遠距、跨國、公部門這三種情境會再疊上各自的變形（可見度、單一薪資市場的假設、法定薪級），那些差異這批內容沒有處理。書的完整描述都在 [主題書單](../topics/)，這裡只說「你的處境對應哪本」與為什麼。

## 五個位置

| 位置                                         | 你對什麼負責               | 最常見的失敗                           |
| -------------------------------------------- | -------------------------- | -------------------------------------- |
| [只對自己的產出負責](own-output/)            | 交出去的東西本身           | 做完了但沒人知道它做完了               |
| [對技術品質負責、不帶人](technical-quality/) | 跨越多人的技術決策與標準   | 方案是對的，但推不動                   |
| [對別人的產出負責](others-output/)           | 團隊交出去的東西           | 自己重寫比教會別人快，於是永遠自己重寫 |
| [對人負責](people/)                          | 這些人留不留得住、成不成長 | 把「管理」做成「更大範圍的自己動手」   |
| [對組織結構負責](org-structure/)             | 團隊怎麼切、交接面誰扛     | 改組織圖而沒有改任何人的實際約束       |

## 怎麼判斷自己在哪一格

判準是**你交不出來的時候，誰會被問**：

- 只有自己被問 → [只對自己的產出負責](own-output/)
- 沒有人交不出來、但技術決策錯了你會被問 → [對技術品質負責](technical-quality/)
- 別人交不出來而你被問 → [對別人的產出負責](others-output/)
- 人走了你會被問 → [對人負責](people/)
- 團隊之間卡住而沒有人特別該負責時你會被問 → [對組織結構負責](org-structure/)

有三種組織會讓這個判準失準：什麼都問同一個人的、集體負責而沒有人被特別問的、以及被問的人不是有槓桿的人。這幾種情況改看**你能動的槓桿**——能不能改變別人的優先序、能不能動人事、能不能改變交接面怎麼定，能動到哪一層就讀哪一篇。被問而動不了的位置是需要處理的問題，不是一個要照著選書的位置。

這個判準問的是現在，而換位置的人需要的是下一格。**已經確定要轉換的人（下個月開始帶人、下一季接下平台團隊）照現況判會落在舊的那一格**，那不是判錯，只是判準只看得到當下。這種處境讀兩篇：現在這個位置的「想往哪裡走」段說明該預習什麼，目標那一格的前兩段說明你即將接手的問題長什麼樣。轉換之後再讀一次目標那篇，拿到的東西會跟轉換前不同——這是刻意的，判準要等到承擔責任才長得出來。

這五格是有僱傭關係、責任由組織分配的處境。獨立接案者、開源維護者、DevRel、研究型工程師、技術寫作者的責任來源不同——對客戶、對社群、對外部讀者——那些處境不在這條線的範圍內，套進五格會失真。五格之間也不是階梯：檔案的排序是責任範圍由小到大，不是該走的順序，橫向移動與留在原地都是正常路徑，每篇的「想往哪裡走」段有標出哪些方向存在。

同時符合兩處時取你現在解不掉的那一處——已經在解的那些問題不需要一本書告訴你怎麼開始。完全對不上的情況也存在——小公司的技術負責人可能同時扛技術品質、別人的產出、人與組織結構，那種處境的建議是照急迫度挑一篇開始，而不是四篇一起讀。

有一個規模下限要先確認：[對組織結構負責](org-structure/) 那篇的書預設組織裡至少有三個團隊。人數在一個團隊以內時，那些內容是為不存在的問題做設計，先看 [對別人的產出負責](others-output/)。其他會改變答案的約束（人員流動率、法規義務、預算）見 [書單推薦](/books/) 的「有四種約束會改變答案」段。

## 這幾篇跟主題篇的分工

主題篇按問題組織，回答「這個問題該讀什麼」；位置篇按人組織，回答「我現在該讀什麼」。同一本書會出現在多個位置的建議裡，用法不同——[Peopleware](../topics/retention-motivation/) 給只對自己產出負責的人的是「原來我的環境是這樣壞掉的」，給對人負責的人的是「我可以動哪些槓桿」。

書的性質判定（證據來源、時效狀態、讀得出價值的前提）一律在主題篇，位置篇不重複，避免同一本書的多份說明各自漂移。
