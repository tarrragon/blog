位置篇按責任範圍組織，不按職稱。同一個職稱在不同組織對應的責任差很多——三十人公司的「資深工程師」經常同時對別人的產出與技術品質負責，五百人公司的同一個職稱可能只對自己的產出負責。用職稱找書會找錯，用責任找不會。

每篇處理三件事：這個位置一天實際在處理什麼、同一個責任範圍在有職級階梯與沒有階梯的組織裡問題差在哪、以及往相鄰位置移動前該預習什麼。書的完整描述都在 [主題書單](../topics/)，這裡只說「你的處境對應哪本」與為什麼。

## 五個位置

| 位置                                         | 你對什麼負責               | 最常見的失敗                           |
| -------------------------------------------- | -------------------------- | -------------------------------------- |
| [只對自己的產出負責](own-output/)            | 交出去的東西本身           | 做完了但沒人知道它做完了               |
| [對技術品質負責、不帶人](technical-quality/) | 跨越多人的技術決策與標準   | 方案是對的，但推不動                   |
| [對別人的產出負責](others-output/)           | 團隊交出去的東西           | 自己重寫比教會別人快，於是永遠自己重寫 |
| [對人負責](people/)                          | 這些人留不留得住、成不成長 | 把「管理」做成「更大範圍的自己動手」   |
| [對組織結構負責](org-structure/)             | 團隊怎麼切、交接面誰扛     | 改組織圖而沒有改任何人的實際約束       |

## 怎麼判斷自己在哪一格

判準是**你交不出來的時候，誰會被問**。只有自己被問，是第一格。別人交不出來而你被問，是第三格。沒有人交不出來、但技術決策錯了你會被問，是第二格。人走了你會被問，是第四格。團隊之間卡住而沒有人特別該負責時你會被問，是第五格。

同時符合兩格時取責任範圍較大的那一格，因為較大那格的問題是你現在解不掉的，較小那格的問題你已經在解了。完全對不上的情況也存在——小公司的技術負責人可能同時佔第二到第五格，那種處境的建議是照急迫度挑一格開始，而不是四篇一起讀。

有一個規模下限要先確認：第五格的書預設組織裡至少有三個團隊。人數在一個團隊以內時，那一格的內容是為不存在的問題做設計，先看第三格。其他會改變答案的約束（人員流動率、法規義務、預算）見 [書單推薦](/books/) 的約束段。

## 這幾篇跟主題篇的分工

主題篇按問題組織，回答「這個問題該讀什麼」；位置篇按人組織，回答「我現在該讀什麼」。同一本書會出現在多個位置的建議裡，用法不同——[Peopleware](../topics/retention-motivation/) 給只對自己產出負責的人的是「原來我的環境是這樣壞掉的」，給對人負責的人的是「我可以動哪些槓桿」。

書的性質判定（證據來源、時效狀態、讀得出價值的前提）一律在主題篇，位置篇不重複，避免同一本書的多份說明各自漂移。
