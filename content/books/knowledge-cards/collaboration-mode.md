協作形態指團隊成員在時間與空間上怎麼重疊，變數是每天的重疊工時而不是辦公室的位置。它是 [處境相容性](/books/knowledge-cards/context-compatibility/) 四種環境裡最容易被略過的一個，因為前三種（組織形態、僱傭關係、法規環境）逐條檢查都不踩時，選書或選做法會照一般路徑進行，而真正支配這個處境的變數根本不在被檢查的清單上。

## 概念位置

判讀落在兩格上——**重疊足夠**與**重疊不足**——中間有一條要分開處理的過渡帶。多數管理與團隊類的建議預設前者。共享物理空間只改變成本——走過去問一句比發訊息快——不改變那些論證成不成立，所以「在不在同一個辦公室」不進判讀，「每天重疊多久」才進。

判讀要落在重疊工時上，「遠端」這個詞區分不出這一項：同一間公司全員在家但都在同一個時區，跟八個人分在四個時區，兩者都叫遠端，而前者幾乎不觸發這一項、後者觸發整批。

它跟 [證據來源](/books/knowledge-cards/evidence-provenance/) 那一項要分開問：一本大規模實證的書，它的樣本可能全部來自重疊充足的組織，於是證據強度很高而處境相容性為零——高強度的證據不會補上缺席的環境。

## 建立在時間重疊上的那一批論證會失效

失效的不是整本書，是建立在「隨時問得到人」上的那一批。逐項對照比整本判斷有用：

| 建立在時間重疊上的論證       | 非同步下發生什麼                                                       |
| ---------------------------- | ---------------------------------------------------------------------- |
| 中斷成本（被打斷、恢復專注） | 中斷從同步事件變成回應期待，成本結構不同，書裡按分鐘算的那套換算不過去 |
| 團隊凝聚的形成條件           | 磨合所需的非正式接觸不會自然發生，要靠刻意設計的場合替代               |
| 走廊上的一句話解決一個誤會   | 誤會要累積到有人正式提出才會被發現，發現時已經走了幾天                 |
| 領導者當場示範坦承錯誤       | 沒有同步場合承載即時反應，要換成公開的決策紀錄與對壞消息的第一則回覆   |
| 會議引導的收斂技巧           | 多數格式預設全員同時在場，逐時腳本類的方法整套需要重新設計             |

書裡通常不會標出哪些論證屬於這一批，因為原作者沒有理由把一個當時普遍成立的前提寫成假設。

## 判讀方式

先算重疊工時再判斷，因為其他判斷都建立在那個數字上。四小時以上的重疊，上表那批論證多半照原樣成立；兩小時以下，整批要逐列檢查。這兩個切點沒有研究背書，是照「一次同步問答加對方回覆需要多少共同時段」估出來的——四小時容得下幾輪來回加上各自的專注時間，兩小時只夠一次會議。團隊的往返節奏不同時，這兩個數字要跟著重設。

過渡帶（兩到四小時）的做法不是「兩邊都準備」：照上表逐列檢查，凡是**靠時間重疊承載**的功能（中斷成本的量化、凝聚的形成、走廊上那句話）一律換載體，其餘照重疊充足處理。這一格最容易被誤歸到兩端，而它要做的動作比兩端都多。

換算的責任落在讀的人身上，而換算失敗有一個具體形態：把非同步當成「同步少了一點」來處理。加開視訊會議把重疊工時湊出來，是把非同步的成本轉嫁到某一邊的作息上。湊出來的那一小時通常落在其中一邊的晚上十點以後，而每週兩次不會有人反對——會議本身開得順，出席率與紀錄都正常。沒有被及時發現，是因為團隊看得到的訊號全部長在會議那一側，作息不對應任何一項團隊指標；等到有人離職，理由會被歸成個人生涯選擇。有效的換算方向相反——找出原本靠時間重疊承載的功能，替它找一個不需要重疊的載體。

這層換算目前得自己做。[書單推薦](/books/) 裡把非同步當成正面題目處理的只有[個人工作流與工作負荷](/books/software-management/topics/personal-workflow/)收的 A World Without Email。[困難對話與無權限影響力](/books/software-management/topics/influence-conversation/)收的 Humble Inquiry 第三版加了遠距工作專章，但那一章處理的是遠距而非重疊不足，而且繁體中文版譯自較早的版本、沒有那一章。其餘的書都要自己做這層換算。
