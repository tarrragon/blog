這篇整理一種把 LLM 當成快速決策器的用法：題目附上一組封閉選項，每個選項用一個單 token 代碼表示，模型只輸出一個 token，決策直接取這個 token 的機率分布，不讓模型生成任何推理過程。本篇涵蓋這個分布在量什麼、怎麼取得、哪幾類題目適合交給它、它在選項設計與統計判讀上的侷限、它跟完整推理與確定性工具怎麼排在同一條流程裡，以及採用之前要怎麼驗證。temperature、top_p 這些取樣參數的完整機制在 [3.5 Sampling 與 Decoding 策略](/llm/03-theoretical-foundations/sampling-and-decoding/)，本篇只寫這個用途為什麼需要特定的取樣設定；推理模型怎麼把思考時間變成可擴展的維度在 [3.8 Reasoning models](/llm/03-theoretical-foundations/reasoning-models/)。

## System 1 與 System 2 的類比與本篇採用的定義

System 1 與 System 2 是心理學的雙歷程（dual-process）理論用語。這組名稱由 Keith Stanovich 與 Richard West 在 2000 年的論文 *Individual differences in reasoning: Implications for the rationality debate?*（*Behavioral and Brain Sciences* 23 卷 5 期）提出；Daniel Kahneman 在 2002 年的諾貝爾獎演講〈Maps of Bounded Rationality〉沿用這組名稱並註明出處，再在《快思慢想》（*Thinking, Fast and Slow*，2011）把它們推廣開來。System 1 是快速、自動、不費力的直覺判斷，System 2 是緩慢、需要專注、可以逐步檢查的推理。類比到 LLM，System 1 對應「模型讀完輸入之後直接給答案」，System 2 對應「模型先生成推理過程、查證、再給答案」——完整推理在推論端多花的計算叫 [test-time compute](/llm/knowledge-cards/test-time-compute/)。

本篇的 **System 1 決策模型**指一個具體的操作：題目與選項全部放進輸入，模型的輸出上限設為 1 個 token，決策取那一個位置上各選項代碼的機率。這個操作的計算量是一次完整的 [prefill](/llm/knowledge-cards/prefill/)（推論時一次讀完整個輸入的階段）：第一個輸出 token 的機率分布，就在 prefill 那次計算的最後一個位置產生。模型照樣用全部的層讀完整個輸入，所以它的「快」來自省掉生成後續 token 的步驟，讀輸入用的計算量和平常相同。成本因此幾乎只剩輸入 token，延遲接近 [TTFT](/llm/knowledge-cards/ttft/)（送出請求到收到第一個 token 的時間）。這個成本差在大量、逐筆的判斷上才有份量：每次部署要看的每張截圖、每張進來的工單、每一題送去推理之前的分流，下文的例子都是這一類。

類比的邊界要先劃清楚：人的 System 1 有自己的記憶與經驗，模型的 System 1 只有輸入裡的文字加上訓練時學到的分布。這個差別讓模型讀不到輸入以外的證據，〈單 token 分布的量測對象〉從這一點推出單 token 決策在哪裡可靠、在哪裡危險。

## 單 token 分布的量測對象

單 token 分布量到的是**模型在不做任何查證時，根據輸入文字對各選項的傾向**。模型只輸出一個 token 時讀不到檔案、跑不了工具、也沒有機會生成「先確認一下這個前提」的推理。它判斷一個前提可不可信，只能依輸入本身的線索：輸入裡有前後矛盾、或寫法露出了不確定，它有機會察覺；線索不足時，它以輸入寫的為準。

這個性質把題目分成兩種：

- **輸入就是全部證據的題目**，傾向等於判斷。例如問一張截圖裡哪個按鈕是主要操作，截圖本身就是全部的證據，沒有輸入以外的事實需要查證。
- **輸入含有未經查證前提的題目**，傾向預期會繼承那個前提。假設輸入寫著「這個檢查已經在測試裡涵蓋」，而測試裡並沒有這項檢查，模型預期會依這句話選出「不需要額外處理」，而且可能選得很有把握。完整推理在這裡的價值是有機會先去讀那份測試、發現前提是錯的；單 token 決策結構上沒有這個機會。這種前提出現在輸入裡，通常是因為輸入經過某一方的轉述或整理：一個 agent 把自己對專案狀態的理解寫進題目，或上一步的摘要被當成事實傳給下一步。

下文說的**信心**指被選中那個代碼的機率（重複取樣時是它被選中的比例），**有把握**指信心高於事先登記的門檻。輸入含有未經查證前提的題目，可以寫成一個可檢驗的假設：**前提錯誤的題目上，單 token 決策會以高信心選錯，而信心高低預測不了對錯**。信心與正確率之間的對應關係叫[機率校準](/llm/knowledge-cards/probability-calibration/)，本篇查到的校準量測都不是在這種題目上做的：

- GPT-4 技術報告（2023）讀取模型在 [MMLU](/llm/knowledge-cards/llm-benchmarks/) 子集上給 A、B、C、D 四個選項代碼的對數機率，預訓練模型的信心與答對比例相當吻合，經過後訓練之後校準明顯變差。
- Saurav Kadavath 等人（2022，*Language Models (Mostly) Know What They Know*）量到較大的模型在格式合適的選擇題與是非題上校準良好——格式合適指選項全部列在題目裡、模型只用代碼作答——量測也涵蓋 TruthfulQA 這類針對常見誤解設計的題組；同一篇論文還量到，把其中一個選項換成「以上皆非」會明顯降低準確率與校準。
- CREPE 資料集（Xinyan Velocity Yu 等人，2022）處理的是帶錯誤預設的問句：開放領域問答模型找得出問句帶了哪些預設（表現中等），卻難以判斷那些預設是不是事實，論文把主因歸給檢索不到相關的證據段落。那份實驗量的是偵測與更正錯誤預設，沒有量信心。

前提寫在輸入裡、而且是錯的這種情形，本篇沒有找到直接量過信心的研究，所以這個假設要靠實驗驗證（做法與一次量測的結果見〈驗證 System 1 用法前要預先登記的實驗條件〉）。在驗證之前，高信心只能讀成「模型對這個前提的傾向很集中」，這個傾向和答對的機率有多接近要另外量。

## 取得單 token 分布的方式：token 機率與重複取樣

取得分布有兩條路，差別在 API 是否回傳 token 機率。

**直接讀 token 機率**：部分 API 與多數本地推論伺服器可以回傳每個輸出位置上機率最高的幾個 token 與它們的對數機率（logprobs）。輸出上限設為 1，一次呼叫就拿到第一個位置上前幾名 token 的機率，而這份清單和選項的分布之間隔著四個落差：

- 同一個代碼常有幾種 token 寫法（有沒有前導空白、有沒有括號），把這些寫法的機率相加，才是那個選項的機率。
- 排在回傳名單之外的代碼讀不到機率，只知道這個代碼的機率低於名單上的最後一名。
- 落在選項代碼以外的 token 上的機率，代表模型想輸出的不是任何一個選項；這部分的大小是模型有沒有照格式作答的訊號，先記下來，再對選項重新正規化。
- 部分伺服器回傳的是經過取樣參數截斷、再對留下的 token 重新正規化之後的機率，留下的選項機率因此偏高，信心看起來比模型原本的更集中。確認的方式是把 top_p、top_k、min_p 與重複懲罰設成停用值，比對同一題在設與不設時回傳的機率是否不同。

這條路還有一個前提：每個選項代碼恰好是一個 token。代碼若被 [tokenizer](/llm/knowledge-cards/token/) 切成兩個 token，第一個位置上的機率只代表代碼的前半段，不同選項的前半段又可能相同，分布就失去意義。單一字母或數字在常見的 tokenizer 裡多半是一個 token，但切法依模型而定，所以這個性質要對實際使用的那個模型的 tokenizer 確認。

**重複取樣近似分布**：API 不回傳 token 機率時，把同一題在 temperature 1.0 下獨立取樣 K 次，各選項被選中的比例就是分布的估計值。取樣用的機率是 [softmax](/llm/knowledge-cards/softmax/)(logits / T)，logits 是模型對每個 token 輸出的原始分數，T = 1 時算出來的就是模型原本的分布（機制見 3.5 的〈[Temperature：調分佈尖銳度](/llm/03-theoretical-foundations/sampling-and-decoding/#temperature調分佈尖銳度)〉）；T 設成 0 會讓每次都選同一個選項，量到的只剩眾數。其餘會在取樣前截斷或改寫機率的參數——top_p、top_k、min_p（三者見 [Top-K / Top-P / Min-P](/llm/knowledge-cards/top-p-sampling/) 卡）與重複懲罰——都要明確設成該 API 表示停用的值。只是不寫這些參數，等於套用伺服器的預設值，而多數本地推論伺服器預設開著其中幾個。被截掉的低機率選項在 K 次取樣裡一次都不會出現，分布因此比模型原本的更集中；本篇要求固定放的「找不到」「現有選項都不夠」正是機率常常偏低、最容易被截掉的那一類。重複懲罰另外有一個針對這個用途的問題：選項代碼全部出現在輸入裡，懲罰範圍涵蓋輸入的伺服器會把它們一起壓低。

這條路的代價是成本乘上 K，而估計值的精度隨 K 慢慢提升。估計值的格距是 1/K，K=5 時只能落在 0%、20%⋯⋯100% 六格；格距小不代表分得出小的差距：K=20、比例在 50% 附近時，估計值的 95% 區間仍寬約正負 22 個百分點（標準誤是 √(0.5 × 0.5 / 20) ≈ 0.11）。要比較相差幾個百分點的兩個比例，需要的取樣次數遠多於 20。

兩條路共用一個設計：**選項順序每次都重新打亂**，並記錄當次的順序，事後才能把每個代碼對回它當次代表的選項內容。重複取樣時每一次取樣各打亂一次；直接讀 token 機率時，同一題用幾種不同的順序各呼叫一次，把每次的分布對回選項內容再平均。Chujie Zheng 等人（2023，*Large Language Models Are Not Robust Multiple Choice Selectors*）量到模型在選擇題上會偏好特定的選項代碼，而這個偏好主要來自代碼 token 本身：不論選項內容是什麼，模型都先天給某些代碼較高的機率。代碼與內容的對應固定不變時，這個偏好會和模型對內容的判斷混在一起，事後分不開。打亂順序同時處理另一個來源：[4.21 LLM-as-Judge](/llm/04-applications/llm-as-judge/#1-position-bias位置偏見) 的 position bias 指 judge 偏好先出現的候選，成因是出現的順序而不是代碼，緩解做法同樣是交換或打亂順序。

## 適合單 token 決策的題型

適合交給單 token 決策的題目有一個共同條件：**判斷所需的證據全部在輸入裡，或者要問的是題目答案以外的事：這一題要不要先查證、模型在畫面上能否找到某個元件**。下面三類題型各自用不同的方式滿足這個條件。

### 證據完整的封閉選項題

這一類題目附上封閉選項，作答需要的證據全部在輸入裡，例如「這張截圖裡的錯誤訊息出現在哪個編號的區塊」「這段 log 屬於哪一類錯誤」。這類題目沒有輸入以外的前提要查證，所以缺查證機會這個弱點不出現，剩下的是模型本身的辨識能力，以及〈單 token 決策的侷限〉一節的選項設計問題。

截圖類題目常用 [Set-of-Mark](/llm/knowledge-cards/set-of-mark-prompting/) 的做法：在圖上候選元件的位置疊上編號，選項就是這些編號。疊編號會帶來一個副作用：編號框本身把「這裡有一個元件」標了出來，模型不用自己找到元件也能答對一部分題目。要量模型能否自己找到元件，就要另外準備沒有編號、改用座標或描述作答的版本當對照。這個對照在〈弱模型可用性測試〉上更必要：那裡量的是元件夠不夠突出，而編號框本身就讓每個元件變得一樣突出。

這類題目的另一個邊界是視覺細節。[視覺語言模型](/llm/knowledge-cards/vlm/)會把輸入圖片縮放到固定的解析度、切成固定大小的區塊再讀，縮放後比一個區塊還小的差異——小字、細邊框、像素級的對齊誤差——可能已經不在模型讀到的輸入裡。這些細節在縮放時已經消失，換更大的模型也讀不到它們；[4.15 Vision in coding workflow](/llm/04-applications/vision-in-coding-workflow/) 把這個限制歸給低解析度模式與 image token 預算，處置是開高解析度模式。在「找出渲染缺陷」這種漏判代價高的用途上，這個弱點直接變成漏判，判定規則要依失效方向設計（見〈判定門檻的方向〉一節）。

### 分流題：判斷題目要不要升級給 System 2

分流題不問答案，只問「**這一題需不需要先查證再決定**」，選項是「需要」與「不需要」兩個代碼。單 token 決策在這裡扮演 router：依題目內容把它派到不同處理路徑的分類器（見 [4.7 Workflow 編排模式](/llm/04-applications/workflow-patterns/#router依輸入分流)的 router 模式）。router 判為需要的題目升級（escalate）給完整推理；判為不需要的題目，再用一次單 token 決策作答，直接採用那個答案。這個位置典型地在 agent 向人提出選項之前：agent 先問自己這一題的前提要不要查證，再決定要不要花一次完整推理。

把問題從「選哪個答案」改成「要不要查證」，理由在證據的位置：前提錯誤的題目上，作答需要的證據本來就在輸入以外，單 token 決策答錯是結構上預期得到的結果。router 要的是另一種能力——辨認出「這題的前提可能有問題」，而辨認需要的線索寫在輸入裡：題目裡是否有未經確認的事實宣稱、選項是否全部依賴同一個前提。CREPE 的結果支持 router 需要的這種辨認能力：模型找得出問句帶了哪些預設。CREPE 同時量到模型難以判斷那些預設是不是事實，而 router 不需要做這個判斷，判斷交給 System 2。router 本身也是一次單 token 決策，面對寫得很肯定的錯誤前提，它同樣可能有把握地判為「不需要」。被它放行的題目直接採用答案，不會進到查證那一層，所以放行錯誤不會自己浮現；要量它，得從放行的題目裡抽樣送去查證，這就是〈System 1、System 2 與確定性工具的分工〉說的隨機抽樣稽核。

量 router 值不值得用，要跟一個便宜的對照比較：一條確定性的規則（例如「題目含有『已經涵蓋』『已經實作』這類未附證據的宣稱，一律判為需要查證」）。比較的指標要把放行錯誤（該查證的題被判為不需要）與多餘升級（不需要查證的題被判為需要）分開算。規則沒有門檻可調，所以比較時調整 router 的門檻，讓兩者升級的題數相同，再看 router 放行的該查證題是否比規則少；或者讓兩者放行的該查證題一樣多，再看 router 升級的題目是否比規則少。這兩個比較只要有一個是 router 勝出，多付的模型成本才有回報。準確率把兩種錯誤加在一起，一個準確率較高的 router 可能放行更多該查證的題。另一個要防的情形，Workflow 編排模式一章的 router 失敗模式稱為「classifier 比下游還複雜」：分流這一步本身要用強模型，它的成本抵銷了它要省下的成本。

### 弱模型可用性測試：把低階模型的失誤當成介面設計的訊號

這一類題型把方向反過來：**刻意用辨識能力較弱的模型，把它找不到、認不出的地方當成介面設計上的警訊**。例如畫面上的主要按鈕寫著「新增專案」，問句寫成「要建立一個新的工作空間，該點哪個編號？」，弱模型在一個畫面上反覆找不到這個按鈕，可能代表它的對比、尺寸或層級不夠突出。這裡期待的是模型犯錯：弱模型的失誤比強模型多，同樣的取樣次數拿到的失誤樣本也多，而失誤的位置正是量測對象。

這類測試有一個難處：模型找不到的原因很多，設計不佳只是其中之一——圖片解析度、問句用詞、語系、模型對某類元件的先天盲點都會造成失誤。區分的方法是**成對變體**：同一個畫面做一個原版、一個只破壞一項設計性質的壞版本（例如把主要按鈕與次要按鈕改成同樣的視覺權重），兩版用同一份資料、同樣的元件數量。解析度與用詞這類因素在兩版之間相同，失敗率的差距大到超出取樣誤差時，才可以歸給被破壞的那一項性質。這樣歸因到的是這個模型對該性質的敏感度；要說它代表人的使用體驗，還要經過〈與人工裁定的一致率和正確率的差別〉一節說的人工驗證。

兩個設計條件讓這個訊號不被稀釋：問句不和畫面上的標籤共用字詞（例子裡的問句用「建立一個新的工作空間」，不重複按鈕上的「新增專案」；共用字詞時模型比對字串就能答對，層級好壞都答得出來），以及選項裡固定放一個「找不到」，讓模型有地方表達失敗，不必硬猜一個編號。

同一個想法也用在寫作審查：多份低階模型獨立讀同一段文字、回報讀到什麼，讀錯的位置就是文字要修的訊號，做法與量測見〈[理解檢查用低階 model 取樣讀者的實際理解，不靠單一 reviewer 的判斷](/report/comprehension-sampled-not-judged/)〉。那篇記錄觀察到推理能力較強的讀者會自動補完殘缺的句子、因而看不出缺陷，這個觀察來自單篇稿件、單一模型家族，還沒有在其他稿件與其他模型家族上重測。

## 單 token 決策的侷限

下面五項侷限都會讓結果看起來正常而數字失準。選項的洩漏與正解落在選項之外，來自選項設計；一致率、小樣本上界與門檻方向，來自統計判讀。

### 選項寫法造成的答案洩漏

選項是輸入的一部分，模型會從選項的寫法讀到答案的線索。常見的兩種洩漏：

- **推薦標記**：選項旁標了「建議」或「Recommended」，模型會被拉向那一項。量的若是模型自己的判斷，送出前要把這類標記機械地移除；量的若是「標記對決策的影響」，就把有無標記當成一個獨立的實驗因子。
- **措辭的事後修飾**：用過去的決策紀錄建題目時，選項若是在知道結果之後才整理寫成的，措辭會不自覺地把正解寫得更完整、更具體。題目與選項要保留決策當下實際出現的原文。

選項代碼本身的偏差與這兩種不同：它和答案內容無關，處理方式見〈取得單 token 分布的方式〉的打亂順序。

### 正解落在選項之外的題目

單 token 決策只能在給定的選項裡挑，而很多決策的最終答案是查證之後才浮現的新方案，第一輪的選項裡根本沒有它。這時單 token 決策最好的表現是選出「現有選項都不夠，需要再分析」，所以選項裡要固定放這一項，並且把「模型選出這一項」單獨統計：這個比例偏高的題型，整類交給 router 或 System 2，不交給快速決策，「偏高」的門檻寫進事先登記的決策表。〈驗證 System 1 用法前要預先登記的實驗條件〉記錄了一次量測，資料是一個 AI agent 在工作對話裡向人提出的 63 題封閉選項問答，其中 9 題做最後決定的人（下文稱裁定者）否決了全部選項、要求重新分析。

固定放這一項也會改變校準：Kadavath 等人量到把一個選項換成「以上皆非」會明顯降低準確率與校準。所以信心門檻要在含這一項的格式下重新量，不沿用不含它的格式量到的數字。

### 與人工裁定的一致率和正確率的差別

拿模型的選擇跟人的裁定比對，得到的是**與裁定的一致率**（agreement rate）：模型和人選了同一項的比例，[LLM-as-Judge](/llm/04-applications/llm-as-judge/#calibration校準) 一章的 calibration 步驟（比對 judge 評分與人的評分）量的也是這個量。它和同一題多次取樣給出同一答案的比例（取樣一致性）是兩件事。一致率要換算成正確率，還取決於人的裁定本身是否正確，而人的裁定也受選項寫法影響（同一個推薦標記也會拉動人），也有事後更正的時候。所以報告要寫「與裁定一致的比例」，並另外報兩個基準：永遠選推薦項的一致率，以及隨機猜中的機率。模型的一致率勝不過「永遠選推薦項」，代表模型的選擇可能只是跟著推薦標記走（題目保留了標記時），或者它的判斷沒有比提問方的建議多提供任何資訊。

正解若是實驗者自己構造的（例如成對變體的壞版本「應該」較難找），還有循環論證的風險：構造者認為難的地方，未必是使用者覺得難的地方。這類結果要再由不參與設計的人驗證，例如請使用者實際操作同一組畫面，比對他們卡住的位置與模型找不到的位置，才能說它代表真實的使用體驗。

### 小樣本的信賴上界

少量樣本的「零失誤」只能證明失誤率不高於某個上界，而這個上界比直覺寬得多。n 次裡失誤 0 次時，失誤率的單尾 95% 信賴上界是 1 − 0.05^(1/n)：失誤率為 p 時連續 n 次零失誤的機率是 (1 − p)ⁿ，令它等於 5% 解出 p。n = 5 時上界約為 45%，資料只排除了「失誤率高於 45%」，45% 以下全部都還可能；n = 10 約為 26%，n = 20 約為 14%。樣本數 n 較大時，這個上界近似 3/n（rule of three）；n = 5 時近似值 60% 比精確值 45% 寬，小樣本要用精確算法。

把信賴區間變成結論，要先定這個用途可接受的失誤率 r，再看區間落在 r 的哪一側（有失誤時，上界與下界用同一種精確算法算）：

- 上界已低於 r：資料排除了不可接受的失誤率，可以採用這個用法。
- 下界已高於 r：資料排除了可接受的失誤率，結論是不採用。
- 區間跨過 r：資料和兩種結論都相容。觀察到的失誤率低於 r 時，值得擴大樣本，做一次題數依上界反推、條件事先登記的正式實驗；觀察值已經高於 r 時，擴大樣本之前要先問這個用途值不值得再投入，這是成本取捨，不是統計結論。

所以 5 次零失誤落在區間跨過 r 的那一格，只夠支持「值得做正式實驗」；從它推論「這個方法可靠」，等於把一個 45% 的上界讀成接近零。

### 判定門檻的方向

用多次取樣做判定時，門檻要對**失效的方向**要求更多證據。以「找出有缺陷的截圖」為例，這個用途的失效方向是放行——有缺陷的圖被判為正常。

假設每次取樣有一半的機率把一張有缺陷的圖標記出來，判定規則是「5 次裡至少 4 次標記才算抓到」，那麼抓到的機率是「恰好 4 次」與「5 次全中」兩種情形的總和：(5 + 1) / 2⁵ = 6/32 ≈ 19%，漏判約 81%。一般式是 5p⁴(1 − p) + p⁵，p 是每次標記的機率。這條規則看起來嚴格，但它把較高的證據要求放在「判為有缺陷」這一側，結果是多數有缺陷的圖被放行。

修正方式是把判定對象換成放行：「5 次裡至少 4 次判為正常才放行」，其餘的一律交給下一層（更強的模型或人）。同樣假設每次標記的機率是一半，有缺陷的圖被放行的機率從約 81% 降到約 19%。這一步的代價落在正常的圖上：一張正常的圖若每次有 10% 的機率被誤標，它在新規則下約有 8% 被升級，下一層每 100 張正常的圖要多看約 8 張。門檻偏向哪一側，由兩種錯誤哪一種代價高決定：代價高的方向要求更多證據，而這個偏向的成本落在另一側，用有缺陷與正常兩類圖各自被升級的機率，可以算出下一層多承擔多少張。

## System 1、System 2 與確定性工具的分工

四層在同一條流程裡的位置，取決於各自的成本與能判斷的事項：

| 層                                               | 能判斷的事項                                                                   | 成本                                               | 適合的位置                                                                         |
| ------------------------------------------------ | ------------------------------------------------------------------------------ | -------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 確定性工具（測試斷言、像素比對、幾何檢查、規則） | 有明確判斷標準的事項：文字或元件有沒有超出容器、兩張圖哪裡不同、元件有沒有重疊 | 幾乎為零，結果可重現                               | 最前面，先把能確定判斷的部分全部處理掉                                             |
| System 1（單 token 決策）                        | 證據在輸入裡、答案在封閉選項裡的判斷；要不要升級的分流                         | 讀 token 機率時一次 prefill；重複取樣時是 K 次取樣 | 處理確定性工具留下的題目                                                           |
| System 2（完整推理、可查證）                     | 需要查證前提、答案可能在選項之外的問題                                         | 生成大量 token，可能還要呼叫工具                   | 處理 router 判為需要查證的題目，以及 System 1 沒把握的題目                         |
| 人                                               | 價值取捨、正解本身有爭議的問題                                                 | 最高                                               | 最後一層：前面各層沒把握的部分，加上依代價強制審查的決策與隨機抽樣稽核的一部分題目 |

這張表的排序原則是**越便宜、越可重現的工具放越前面**，每一層處理前一層留下的題目。「System 1 沒把握才升級」這條規則依賴信心能預測對錯，只在量過機率校準的題型上可靠；前提可能錯誤的題型上，信心是否預測對錯正是〈單 token 分布的量測對象〉那個待驗證的假設，那裡的升級要靠題目性質（分流題與確定性規則），不靠信心。另外兩類決策不受「只處理前一層留下的題目」限制：代價高、不可逆的決策照 [4.5 人機協作拓樸](/llm/04-applications/human-ai-collaboration/#三個時機的選擇) 的代價分級強制送人審查；有把握而直接採用的題目也要隨機抽一部分給人稽核，人機協作拓樸一章〈Falling asleep at the wheel〉（人長期看到自動化結果都正確，就不再仔細審查）的緩解做法正是這一項，它用來發現模型有把握而選錯的那一類。下面三個分工細節需要展開。

**確定性工具先行，模型只判剩下的題目**。以截圖回歸檢查為例：有基準圖時，像素比對可以零模型成本找出「哪裡變了」，沒有差異的截圖直接免看；模型只需要回答確定性工具答不了的那一題——「這個差異是缺陷，還是預期內的修改」。把整張截圖丟給模型問「有沒有問題」，等於讓模型重做像素比對已經做完的事，還多了漏判的風險。模型只拿到新版截圖時，分不出「缺陷存在但被縮放掉了」和「它不知道這個位置原本該長什麼樣」，所以交給模型時要附上基準圖與新版在同一位置的裁切；沒有基準圖的截圖，判斷所需的證據不在輸入裡，這一題就落在證據完整的封閉選項題之外，交給 System 2 或人。

**System 1 當 System 2 的 router**。router 放在 System 2 前面，是因為它的成本是一次 prefill，而它要省下的是一次完整推理。它判為需要查證的題目進 System 2；判為不需要的題目，再用一次單 token 決策作答：這一類題目量過校準、而且作答的信心高於門檻時直接採用，量過校準但信心低於門檻時送 System 2，沒有量過校準時改依確定性規則決定要不要升級。router 的門檻怎麼訂，取決於兩種錯誤的代價：把該查證的題目放行，代價是一次錯誤的決策；把不需要查證的題目送去查證，代價是一次 System 2 的推理成本。這一題需要查證的機率（用量過校準的 router 機率，或這類題目在歷史資料裡前提錯誤的比例）乘上錯誤決策的代價，就是放行它的期望損失；期望損失大於一次 System 2 的成本時，升級就划算。涉及前提的決策錯了，代價多半遠高於一次推理的成本，所以這類用途的門檻偏向「有疑慮就升級」；大量、低風險的分類（例如替工單貼標籤），錯一筆的代價接近一次推理的成本，門檻就不必往升級那一側偏。這和〈判定門檻的方向〉一節是同一個推導。

**System 2 刻意質疑 System 1 的直覺答案**。這是一個要量過才採用的設計，預期修的是 System 2 沿著第一個想到的答案找理由、沒有認真考慮其他選項的情形，這個效益還沒有量過。單 token 決策可以把「直覺答案」明確地標出來，拿到它之後，System 2 的任務多一項：針對這個答案找反例，或者反向假設它是錯的再推一次。風險在同一個機制上：把 System 1 的答案放進 System 2 的輸入，等於在輸入裡放了一個推薦標記，而〈選項寫法造成的答案洩漏〉說過推薦標記會把模型拉向那一項。所以同一批題目要跑兩種 System 2——一種拿到 System 1 的答案並被要求找反例，一種沒拿到——拿到 System 1 答案的那一種正確率較高，才保留這個設計；兩者的改判率一併記錄，用來看質疑是否實際改變了答案。

## 驗證 System 1 用法前要預先登記的實驗條件

團隊要判斷一個 System 1 用法是否值得採用，得靠實驗，而這類實驗最容易出錯的地方是**看到結果之後才調整條件**。調整的動作本身未必有惡意，但每一次「這題不算」「門檻改成 3/5 比較合理」都讓結果往預期的方向移動。下面四件事要在取樣之前寫下來，提交進版本控制或交給預先登記（pre-registration）的平台，讓之後的修改都留下紀錄：

- **資料集**：題目、選項、正解的來源。題目與選項取決策當下的原文，不由知道結果的人重寫——後見之明會讓措辭不自覺地偏向正解。
- **排除規則**：哪些題目不納入、理由是什麼，在看到模型的答案之前決定。依結果排除題目（例如「模型和人都答錯的題目算資料不足」），會讓假設永遠無法被否證。
- **判定門檻與決策表**：取樣次數、信心高於多少算有把握、樣本數不足時的結論。計數單位要先定好：同一件事被反覆提問的多題（例如第一次的選項被否決後，針對同一個決定再問一次）彼此不獨立，計成一個題組。題組數的門檻由可接受的失誤率 r 反推：n 組全部判對時上界是 1 − 0.05^(1/n)，r = 30% 時 n 至少要 9 組，所以決策表可以寫成「少於 9 組只描述、不下結論；9 組以上才依門檻判定」。
- **對照組**：便宜的基準（永遠選推薦項、確定性規則、隨機猜中），以及成對變體的原版。

另外有一個常被跳過的零成本步驟：**先量流程裡既有的建議選項**。這一類流程的共同長相是「先由一方產出選項與建議，再由另一方裁定」，例如 coding agent 向人提出幾個做法並標出建議項、由人決定。那個建議本身就扮演 System 1 的角色：它也是在查證之前給出的傾向。統計建議被推翻的題目各是因為什麼原因被推翻，不呼叫任何模型就能知道「因為前提錯誤而被推翻」在這個流程裡有多常見。這個統計同時供兩個決定使用：前提錯誤的普遍度乘上錯誤決策的代價，決定值不值得建 router；前提錯誤的題組數，決定後續的模型實驗能不能下結論，門檻見上方的決策表。

一次量測照這個做法跑過，可以用來看決策表怎麼套在一份實際的資料上。資料是一個 AI agent 在一段工作對話裡向人提出的 63 題封閉選項問答，agent 在其中 37 題標了建議選項，人是唯一的裁定者。量測沒有拿模型去模擬建議選項；逐題標註裁定者改答原因的，是一個沒參與任何決策、也沒讀過研究假設的標註者（另一個模型實例，質性研究稱 coder），它依照事先登記的分類表（coding scheme）作業。37 題裡有 22 題的建議選項與最後裁定一致（59%），這就是〈與人工裁定的一致率和正確率的差別〉一節說的「永遠選推薦項」基準在這份資料上的值。改答原因屬於「前提更正」的有 7 題，分屬 4 個題組；提問那一方的 agent 覆核分類定義有沒有一致套用之後，改判了其中一組，剩 6 題、3 組。這次覆核只檢查定義的套用，不是第二位標註者的獨立標註。這份資料事先登記的門檻是 6 組（照〈判定門檻與決策表〉那一項的公式反推，6 組全部判對時上界約 39%），3 組與 4 組都低於它，依決策表，這份資料不足以進入模型實驗。〈單 token 分布的量測對象〉那個假設在這份資料上因此沒有被檢驗到，既沒有支持也沒有否定它。

同一份資料裡有一個描述性的觀察：前提更正的題目全部走同一條路徑——裁定者先否決全部選項、要求重新分析，重新分析的過程中經過查證、前提改變，裁定者再做裁定；沒有一題是裁定者直接在選項之間改選、理由是前提錯誤。在這個樣本裡，錯誤的前提主要是在裁定者要求重想時才浮現，第一輪的選擇沒有把它暴露出來。這份資料來自單一段工作對話、單一裁定者、單一標註者（沒有讓第二位標註者獨立標一次再比對），要把這個觀察當成假設的依據，需要另一個來源的資料重做一次。

## 延伸閱讀：取樣、推理與評估的相鄰章節

本篇的判斷建立在幾個可以替換的前提上，換掉其中一個會走到不同的章節：

- **把「單 token」換成「允許推理」**：題目需要多步推理時，走 [3.8 Reasoning models](/llm/03-theoretical-foundations/reasoning-models/) 的〈適合 reasoning model 的任務〉，那一節的判斷標準是「有客觀正確答案、需要多步推理」；需要讀檔、跑工具去查證前提時，走同一章的〈[Reasoning model + tool use](/llm/03-theoretical-foundations/reasoning-models/#reasoning-model--tool-use)〉。
- **把「封閉選項」換成「開放式評分」**：要評的是一段生成內容的品質時，走 [4.21 LLM-as-Judge](/llm/04-applications/llm-as-judge/)，那一章處理 rubric 設計、pairwise 比較與三種偏見的緩解。
- **把「取樣分布」換成「確定性輸出」**：需要每次結果完全一致時，[3.5 Sampling 與 Decoding 策略](/llm/03-theoretical-foundations/sampling-and-decoding/)講 temperature、seed 與 greedy decoding 各自的效果。
- **把「模型判斷」換成「人介入的時機」**：要決定最後一層的人在什麼時候、以什麼方式介入，走 [4.5 人機協作拓樸](/llm/04-applications/human-ai-collaboration/)。
- **把「單次實驗」換成「長期評估」**：要讓一個已採用的 System 1 用法持續被監控，評估軸與 [frozen baseline](/llm/knowledge-cards/frozen-baseline/) 的設計在 [4.13 Eval 設計座標系](/llm/04-applications/eval-design-framework/)。
