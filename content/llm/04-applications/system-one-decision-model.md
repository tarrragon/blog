這篇整理一種把 LLM 當成快速決策器的用法：題目附上一組封閉選項，每個選項用一個單 token 代碼表示，模型只輸出一個 token，決策直接取這個 token 的機率分布，不讓模型生成任何推理過程。本篇涵蓋這個分布在量什麼、怎麼取得、哪幾類題目適合交給它、它在選項設計與統計判讀上的侷限，以及它跟完整推理、確定性工具怎麼排在同一條流程裡。Sampling 參數本身的機制在 [3.5 Sampling 與 Decoding 策略](/llm/03-theoretical-foundations/sampling-and-decoding/)，推理模型怎麼把思考時間變成可擴展的維度在 [3.8 Reasoning models](/llm/03-theoretical-foundations/reasoning-models/)，本篇引用它們的結論、不重講機制。

## System 1 與 System 2 的類比與本篇採用的定義

System 1 與 System 2 是心理學的雙歷程（dual-process）理論用語，Daniel Kahneman 在《快思慢想》（*Thinking, Fast and Slow*，2011）把它們推廣開來：System 1 是快速、自動、不費力的直覺判斷，System 2 是緩慢、需要專注、可以逐步檢查的推理。類比到 LLM，System 1 對應「模型讀完輸入之後直接給答案」，System 2 對應「模型先生成推理過程、查證、再給答案」——完整推理在推論端多花的計算叫 [test-time compute](/llm/knowledge-cards/test-time-compute/)。

本篇的 **System 1 決策模型**指一個具體的操作：題目與選項全部放進輸入，模型的輸出上限設為 1 個 token，決策取那一個位置上各選項代碼的機率。這個操作的計算量是一次完整的 [prefill](/llm/knowledge-cards/prefill/) 加上一步 decode：模型照樣用全部的層讀完整個輸入，所以它的「快」來自省掉生成中間 token 的步驟，模型讀輸入時用的計算量和平常相同。成本因此幾乎只剩輸入 token，延遲接近 [TTFT](/llm/knowledge-cards/ttft/)。

類比的邊界要先劃清楚：人的 System 1 有自己的記憶與經驗，模型的 System 1 只有輸入裡的文字加上訓練時學到的分布。〈單 token 決策的侷限〉一節列出的項目，多數來自這個差別。

## 單 token 分布的量測對象

單 token 分布量到的是**模型在不做任何查證時，根據輸入文字對各選項的傾向**。模型只輸出一個 token 時讀不到檔案、跑不了工具、也沒有機會生成「先確認一下這個前提」的推理，所以輸入裡寫了什麼，它就以什麼為前提作答。

這個性質決定了它在哪裡可靠、在哪裡危險：

- **輸入就是全部證據的題目**，傾向等於判斷。例如問一張截圖裡哪個按鈕是主要操作，截圖本身就是全部的證據，沒有輸入以外的事實需要查證。
- **輸入含有未經查證前提的題目**，傾向會忠實地繼承那個前提。假設輸入寫著「這個檢查已經在測試裡涵蓋」，而測試裡並沒有這項檢查，模型會依這句話選出「不需要額外處理」，而且可能選得很有把握。完整推理在這裡的價值是有機會先去讀那份測試、發現前提是錯的；單 token 決策結構上沒有這個機會。

第二點可以寫成一個可檢驗的假設：**前提錯誤的題目上，單 token 決策會以高信心選錯，而信心高低預測不了對錯**。這個假設要靠實驗驗證（做法見本篇〈驗證 System 1 用法前要凍結的實驗條件〉）。在驗證之前，高信心只能讀成「模型對這個前提很一致」，它和答對的機率有多接近要另外量。信心與正確率之間的對應關係叫[機率校準](/llm/knowledge-cards/probability-calibration/)，單 token 分布在前提錯誤的題目上，正是校準最容易失效的地方。

## 取得單 token 分布的方式：token 機率與重複取樣

取得分布有兩條路，差別在 API 給不給 token 機率。

**直接讀 token 機率**：部分 API 與多數本地推論伺服器可以回傳每個輸出位置上機率最高的幾個 token 與它們的對數機率（logprobs）。輸出上限設為 1、讀回各選項代碼的機率，一次呼叫就拿到完整分布。這條路的前提是每個選項代碼恰好是一個 token——代碼若被 [tokenizer](/llm/knowledge-cards/token/) 切成兩個 token，第一個位置上的機率只代表代碼的前半段，不同選項的前半段又可能相同，分布就失去意義。選項代碼用單一字母或單一數字，送出前先用該模型的 tokenizer 確認過，是這條路的基本功。

**重複取樣近似分布**：API 不回傳 token 機率時，把同一題在 [temperature](/llm/knowledge-cards/sampling-constraint/) 1.0 下獨立取樣 K 次，各選項被選中的比例就是分布的估計值。Temperature 要用 1.0，理由是這個值不改動模型原本的 [softmax](/llm/knowledge-cards/softmax/) 分布；設成 0 會讓每次都選同一個選項，量到的只剩眾數。代價是成本乘上 K，而且分布的解析度是 1/K：K=5 時只分得出 0%、20%、40% 這幾格，K=20 才分得出 5% 的差距。

兩條路共用一個設計：**每次取樣都重新打亂選項順序**，並記錄當次的順序。模型對選項位置有偏好，位置偏見在 [LLM-as-Judge](/llm/04-applications/llm-as-judge/) 的 pairwise 比較裡已經有完整的討論；固定順序時，這個偏好會和模型對內容的判斷混在一起，事後分不開。

## 適合單 token 決策的題型

適合交給單 token 決策的題目有一個共同條件：**判斷所需的證據全部在輸入裡，或者要問的是答案以外的事**。下面三類題型各自用不同的方式滿足這個條件。

### 證據全在輸入裡的封閉選項題

封閉選項題指證據完整、答案落在選項內的題目，例如「這張截圖裡的錯誤訊息出現在哪個編號的區塊」「這段 log 屬於哪一類錯誤」。這類題目沒有輸入以外的前提要查證，單 token 決策的弱點只剩模型本身的辨識能力。

截圖類題目常用 [Set-of-Mark](/llm/knowledge-cards/set-of-mark-prompting/) 的做法：在圖上候選元件的位置疊上編號，選項就是這些編號。疊編號會帶來一個副作用：編號框本身把「這裡有一個元件」標了出來，模型不用自己找到元件也能答對一部分題目。要量模型自己找不找得到，就要另外準備沒有編號、改用座標或描述作答的版本當對照。

這類題目的另一個邊界是視覺解析度。小模型看小字、1 到 2 像素的對齊誤差、相近的顏色，明顯比大模型差；在「找出渲染缺陷」這種漏判代價高的用途上，這個弱點直接變成漏判，判定規則要依失效方向設計（見〈判定門檻的方向〉一節）。

### 分流題：判斷這一題要不要升級給 System 2

分流題不問答案，只問「**這一題需不需要先查證再決定**」，選項是「需要」與「不需要」兩個代碼。單 token 決策在這裡扮演分流器（router，見 [4.7 Workflow 編排模式](/llm/04-applications/workflow-patterns/)的 router 模式）：判為需要的題目交給完整推理，判為不需要的題目才直接採用快速答案。

把問題從「選哪個答案」改成「要不要查證」，是因為單 token 決策在查證前選錯答案是預期內的結果——它沒有查證的機會，量這件事得到的資訊很少。分流器真正需要的能力是辨認出「這題的前提可能有問題」，而這個能力是可以在查證之前發揮的：題目裡有沒有未經確認的事實宣稱、選項是否全部依賴同一個前提，這些線索都寫在輸入裡。

分流器要跟一個便宜的對照比較才知道值不值得用：一條確定性的規則（例如「題目含有『已經涵蓋』『已經實作』這類未附證據的宣稱，一律判為需要查證」）。模型分流器的準確率要勝過這條規則，多付的模型成本才有回報；4.7 把「分類器比下游還貴」列為 router 的退化條件。

### 弱觀察者：把低階模型的失誤當成訊號

弱觀察者題把方向反過來：**刻意用辨識能力較弱的模型，把它找不到、認不出的地方當成設計上的警訊**。例如問「要開啟專案，該點哪個編號？」，弱模型在一個畫面上反覆找不到主要操作，可能代表那個按鈕的對比、尺寸或層級不夠突出。這裡期待的是模型犯錯，犯錯的位置就是量測對象。

弱觀察者有一個難處：模型找不到的原因很多，設計不佳只是其中之一——圖片解析度、問句用詞、語系、模型對某類元件的先天盲點都會造成失誤。區分的方法是**成對變體**：同一個畫面做一個原版、一個只破壞一項設計性質的壞版本（例如把主要按鈕與次要按鈕改成同樣的視覺權重），兩版用同一份資料、同樣的元件數量。解析度與用詞這類因素在兩版之間相同，失敗率的差距才可以歸給被破壞的那一項性質。

兩個設計條件讓這個訊號不被稀釋：問句不和畫面上的標籤共用字詞（否則模型比對字串就能答對，層級好壞都答得出來），以及選項裡固定放一個「找不到」，讓模型有地方表達失敗，不必硬猜一個編號。

同一個想法在寫作審查上也有應用：本站用多份低階模型獨立讀同一段文字、回報讀到什麼，把讀錯的位置當成文字需要修的訊號，推導見 [#281](/report/comprehension-sampled-not-judged/)。兩者共用的前提是：推理能力越強的讀者越會自動補完殘缺的地方，缺陷因此被填平而看不出來。

## 單 token 決策的侷限

下面五項侷限都會讓結果看起來正常而數字失準。選項的洩漏與正解落在選項之外，來自選項設計；一致率、小樣本上界與門檻方向，來自統計判讀。

### 選項寫法造成的答案洩漏

選項是輸入的一部分，模型會從選項的寫法讀到答案的線索。常見的三種洩漏：

- **推薦標記**：選項旁標了「建議」或「Recommended」，模型會被拉向那一項。量的若是模型自己的判斷，送出前要把這類標記機械地移除；量的若是「標記對決策的影響」，就把有無標記當成一個獨立的實驗因子。
- **措辭的事後修飾**：選項若是在知道結果之後才整理寫成的，措辭會不自覺地把正解寫得更完整、更具體。題目與選項要保留當時實際出現的原文。
- **位置**：見上文，靠每次取樣重新打亂順序處理。

### 正解落在選項之外的題目

單 token 決策只能在給定的選項裡挑，而很多決策的最終答案是查證之後才浮現的新方案，第一輪的選項裡根本沒有它。這時單 token 決策最好的表現是選出「現有選項都不夠，需要再分析」，所以選項裡要固定放這一項，並且把「模型選出這一項」單獨統計——這個比例本身就是一個有用的訊號，代表這一類題目不該交給快速決策。

### 一致率與正確率的差別

拿模型的選擇跟人的裁定比對，得到的是**一致率**：模型和人選了同一項的比例。一致率和正確率之間隔著人的裁定本身對不對，而人的裁定也受選項寫法影響（同一個推薦標記也會拉動人），也有事後更正的時候。所以報告要寫「與裁定一致的比例」，並另外報兩個基準：永遠選推薦項的一致率，以及隨機猜中的機率。模型的一致率勝不過「永遠選推薦項」，代表它學到的可能只是推薦標記。

正解若是實驗者自己構造的（例如成對變體的壞版本「應該」較難找），還有循環論證的風險：構造者認為難的地方，未必是使用者覺得難的地方。這類結果要再由不參與設計的人校準，才能說它代表真實的使用體驗。

### 小樣本的信賴上界

少量樣本的「零失誤」只能證明失誤率不高於某個上界，而這個上界比直覺寬得多。5 次裡失誤 0 次，失誤率的單尾 95% 信賴上界約為 45%（失誤率為 p 時連續 5 次零失誤的機率是 (1 − p)⁵，令它等於 5% 解出 p ≈ 0.45）：資料只排除了「失誤率高於 45%」，45% 以下全部都還可能。同一個算法下，20 次零失誤的上界約為 14%。

45% 這個上界讓小規模試驗能下的結論只剩兩種：「值得進入正式階段」或「不做」。從 5 次零失誤推論「這個方法可靠」，等於把一個 45% 的上界讀成接近零。

### 判定門檻的方向

用多次取樣做判定時，門檻要對**失效的方向**要求更多證據。以「找出有缺陷的截圖」為例，這個用途的失效方向是放行——有缺陷的圖被判為正常。

假設每次取樣有一半的機率把一張有缺陷的圖標記出來，判定規則是「5 次裡至少 4 次標記才算抓到」，那麼抓到的機率是「恰好 4 次」與「5 次全中」兩種情形的總和：(5 + 1) / 2⁵ = 6/32 ≈ 19%，漏判約 81%。這條規則看起來嚴格，但它要求更多證據的是「判為有缺陷」，結果是多數有缺陷的圖被放行。

修正方式是把判定對象換成放行：「5 次裡至少 4 次判為正常才放行」，其餘的一律交給下一層（更強的模型或人）。同樣的取樣結果，在這條規則下，模型沒把握的圖全部會被攔下來。判斷標準是先問「這個用途錯在哪個方向的代價最高」，再讓門檻對那個方向要求更多證據。

## System 1、System 2 與確定性工具的分工

三者在同一條流程裡的位置，取決於各自的成本與能判斷的事項：

| 層                                               | 能判斷的事項                                                     | 成本                             | 適合的位置                                               |
| ------------------------------------------------ | ---------------------------------------------------------------- | -------------------------------- | -------------------------------------------------------- |
| 確定性工具（測試斷言、像素比對、幾何檢查、規則） | 有明確判斷標準的事項：有沒有溢位、兩張圖哪裡不同、元件有沒有重疊 | 幾乎為零，結果可重現             | 最前面，先把能確定判斷的部分全部處理掉                   |
| System 1（單 token 決策）                        | 證據在輸入裡、答案在封閉選項裡的判斷；要不要升級的分流           | 一次 prefill，或乘上取樣次數 K   | 處理確定性工具留下的殘差                                 |
| System 2（完整推理、可查證）                     | 需要查證前提、答案可能在選項之外的問題                           | 生成大量 token，可能還要呼叫工具 | 處理分流器判為需要查證的題目，以及 System 1 沒把握的題目 |
| 人                                               | 價值取捨、正解本身有爭議的問題                                   | 最高                             | 最後一層，只看前面各層都沒把握的部分                     |

這張表的排序原則是：**每一層只處理前一層答不了的部分**，越便宜、越可重現的工具放越前面。下面三個分工細節需要展開。

**確定性工具先行，模型只判殘差**。以截圖回歸檢查為例：有基準圖時，像素比對可以零模型成本找出「哪裡變了」，沒有差異的截圖直接免看；模型只需要回答確定性工具答不了的那一題——「這個差異是缺陷，還是預期內的修改」。把整張截圖丟給模型問「有沒有問題」，等於讓模型重做像素比對已經做完的事，還多了漏判的風險。沒有基準圖時，模型也分不出「看不見」和「不知道這裡應該長什麼樣」，所以殘差的形式（基準與新版的同位置裁切）是讓模型能答對的前提。

**System 1 當 System 2 的分流器**。流程是：先讓 System 1 判斷要不要查證，需要的交給 System 2，不需要且 System 1 有把握的直接採用。這個組合的收益取決於分流器的兩種錯誤代價不對稱：把該查證的題目放行，代價是錯誤的決策；把不需要查證的題目送去查證，代價只是多花的推理成本。所以分流器的門檻要偏向「有疑慮就升級」，這和〈判定門檻的方向〉一節是同一個道理。

**System 2 刻意質疑 System 1 的直覺答案**。完整推理有一個常見的失敗：選項在一開始就被直覺圈定，後面的分析只是在替直覺答案找理由。單 token 決策剛好可以把「直覺答案」明確地標出來——拿到它之後，System 2 的任務多了一項：針對這個答案找反例，或者反向假設它是錯的再推一次。這時 System 1 的價值不在答對，在於把需要被質疑的那個答案提早具體化。

## 驗證 System 1 用法前要凍結的實驗條件

一個 System 1 用法值不值得採用，要靠實驗回答，而這類實驗最容易出錯的地方是**看到結果之後才調整條件**。調整的動作本身未必有惡意，但每一次「這題不算」「門檻改成 3/5 比較合理」都讓結果往預期的方向移動。下面四件事要在取樣之前寫下來並提交凍結，凍結的時間點要早於第一次取樣：

- **資料集**：題目、選項、正解的來源。題目與選項取當時的原文，不由知道結果的人重寫——後見之明會讓措辭不自覺地偏向正解。
- **排除規則**：哪些題目不納入、理由是什麼，在看到模型的答案之前決定。依結果排除題目（例如「模型和人都答錯的題目算資料不足」），會讓假設永遠無法被否證。
- **判定門檻與決策表**：取樣次數、什麼比例算高信心、樣本數不足時的結論。例如「可用題數少於 6 題就結論為不做；6 到 9 題只做描述；10 題以上才依門檻判定」。
- **對照組**：上文提過的便宜基準（永遠選推薦項、確定性規則、隨機猜中），以及成對變體的原版。

另外有一個常被跳過的零成本步驟：**先量既有的第一層決策**。如果流程裡已經有人或系統在產出「建議選項」，那個建議本身就是一個現成的 System 1——它也是在查證之前給出的傾向。先統計建議被採納的比例、被推翻的題目是因為什麼原因被推翻，不呼叫任何模型就能知道「查證之前選錯」在這個流程裡有多常見。這個比例很低，就不需要再花成本去模擬；比例夠高，才有足夠的題目支撐後續的模型實驗。

## 延伸閱讀：取樣、推理與評估的相鄰章節

本篇的判斷建立在幾個可以替換的前提上，換掉其中一個會走到不同的章節：

- **把「單 token」換成「允許推理」**：題目需要查證時，答案會走到 [3.8 Reasoning models](/llm/03-theoretical-foundations/reasoning-models/)，那一章講推理模型怎麼把思考時間變成可擴展的維度，以及適合交給它的任務。
- **把「封閉選項」換成「開放式評分」**：要評的是一段生成內容的品質時，走 [4.21 LLM-as-Judge](/llm/04-applications/llm-as-judge/)，那一章處理 rubric 設計、pairwise 比較與三種偏見的緩解。
- **把「取樣分布」換成「確定性輸出」**：需要每次結果完全一致時，[3.5 Sampling 與 Decoding 策略](/llm/03-theoretical-foundations/sampling-and-decoding/)講 temperature、seed 與 greedy decoding 各自的效果。
- **把「模型判斷」換成「人介入的時機」**：要決定最後一層的人在什麼時候、以什麼方式介入，走 [4.5 人機協作拓樸](/llm/04-applications/human-ai-collaboration/)。
- **把「單次實驗」換成「長期評估」**：要讓一個已採用的 System 1 用法持續被監控，評估軸與 [frozen baseline](/llm/knowledge-cards/frozen-baseline/) 的設計在 [4.13 Eval 設計座標系](/llm/04-applications/eval-design-framework/)。
