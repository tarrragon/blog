## 論述基礎與限制

這張卡來自一次 API 規格的撰寫：分頁回應裡記錄「下一頁從哪一筆接續」的那個字串，英文叫 cursor，文件裡直接寫成「游標」。讀者讀到時先想到的是滑鼠游標，問這是不是翻錯了。

量測是一批三份的術語探針（term probe：讓同一個低階模型的幾個獨立實例讀一組詞、各自回報它指什麼，指令逐字相同，混入「主鍵」「交易」兩個已知術語當控制詞），加上兩家雲端廠商繁體中文官方文件的查閱（其中一家的譯名在事後查證時發現與量測用的候選詞不同，見〈修法〉）。限制有三：探針是語言模型而不是台灣讀者；只量了一個術語；控制詞收斂，但這批沒有放[安慰劑詞](../probe-reads-the-prompt-that-defines-the-term/)（只出現在專案規範檔裡的詞，用來確認探針有沒有讀到規範檔），所以無法排除探針讀到規範檔而受影響；資料庫意義的譯名「查詢結果的讀取物件」沒有量測。這張卡的結論主要靠機制推導支持，探針的數字只是佐證。

## 核心原則

**一個外來術語的中文譯名，借用了中文裡已經有日常意思的詞時，讀者讀到的是日常意思。** 英文的 cursor 至少指三樣東西：畫面上的滑鼠或文字游標、資料庫逐筆讀取查詢結果的物件、分頁回應裡記錄接續位置的字串。共通點是「標記目前位置」，所以英文讀者用同一個字不覺得有問題。中文的「游標」在日常與軟體介面裡已經固定指畫面上的游標，把它拿來譯資料庫的讀取物件或分頁的接續字串，詞面帶來的是畫面上那個箭頭。這跟 [#307](../term-already-owned-inside-the-domain/) 的「詞在同一個領域裡已經有主人」是同一類：在軟體這個領域，「游標」的主人是畫面上的游標。

**只寫英文是把翻譯工作交給讀者。** 它避開了錯的譯名，代價落在讀者身上：每次讀到都要自己把英文對回一個中文概念，而不熟這個英文詞的讀者連對回的起點都沒有。站內的術語規範是第一次出現寫「中文（original term）」（[#107](../terminology-keeps-original-anchor/)），中文負責讓讀者讀懂，英文負責讓讀者查得到、對得上程式碼裡的名稱（`next_cursor`），兩者各有工作，不能只留一個。

**譯名要讓詞面直接說出這個東西做什麼。** 找不到既有譯名時，可以自己組一個描述功能的短語，甚至寫成一句話；重點是讀者第一次讀到就知道它是什麼。分頁的 cursor 在這次選定的譯名是「接續標記」：它是伺服器給的一個標記，記錄下一頁從哪裡接續。三個意思各自的譯名與分辨方式整理在 [Cursor 知識卡](/backend/knowledge-cards/cursor/)。

## 反模式：沿用查得到的譯名就當成已經查證

「游標」不是憑空想出來的：微軟繁體中文版的 SQL Server 文件就用它當頁面標題，所以它看起來是有出處的譯名。但查得到不等於它在中文裡讀得通。

這次查到的官方文件本身就有破綻：微軟繁體中文版 SQL Server 的 cursor 頁，標題與多數段落用「游標」，同一頁裡也出現「資料指標」（例如「Transact-SQL 游標」那一列的說明寫「Transact-SQL 資料指標是以 DECLARE CURSOR 語法為基礎」）；頁面的中繼資料標示整頁是機器翻譯（`ms.translationtype: MT`）。所以查得到的譯名可能只是機器翻譯的產物。「官方文件這樣寫」要先看兩件事：同一頁裡用法一不一致，以及頁面是不是機器翻譯；任一項成立，那個譯名就不能當依據。

## 修法

1. **先查承載這個概念的知識卡有沒有本站定案的寫法**，有就照用；這次的定案寫回了 [Cursor 知識卡](/backend/knowledge-cards/cursor/)。
2. **把英文詞在這個情境裡指的東西寫成一句話。** 寫不出這句話，代表還沒弄清楚要譯的是哪一個意思；英文詞有好幾個意思時，每個意思各自找譯名（這次的查詢結果的讀取物件與分頁接續標記就是分開處理的）。
3. **列出候選譯名**：既有的譯法（包括看起來可疑的那個）、其他廠商繁體中文文件的用法（這次量的「分頁標記」來自搜尋摘要，回到 AWS 繁體中文詞彙表原文核對時，正式譯名其實是「分頁符記」，定義為「表示 API 回應包含較大記錄清單子集的標記」；所以出處要回原文核對，摘要裡的譯名不能當廠商用法）、以及照「這個東西做什麼」那句話自己組的短語。
4. **用術語探針量測候選**：同一批混入至少兩個已知通用的術語當控制詞，問每個詞在這個情境裡指什麼、沒把握就寫沒把握，並要它指出哪一個最快讀懂、哪一個最容易誤解（設計條件見 [#289](../term-probe-measures-register-not-invention/)）。
5. **讀有把握那幾份寫的定義，不只看份數。** 這次的候選是游標、資料指標、分頁標記、接續標記，關鍵差別在定義：「分頁標記」有一份把頁碼與位移量（offset）也算進去，會模糊「用接續標記而不用頁碼」這個對照；「接續標記」三份都讀成「從這裡接續往下拿」。
6. **選定的譯名再過一次同一個問句**，替代譯名也可能讓讀者先想到別的東西。
7. **寫回時第一次出現加英文附註**，之後以中文為主，程式識別字與討論英文詞本身時用英文；同一個英文詞的其他意思不要一起被替換掉（畫面上的游標仍然是游標）。既有譯名在其他中文資料裡流通時附一句「其他中文資料常寫作 X」。

量過之後候選中譯仍全部分歧的詞（例如 #289 的 test oracle），第一次出現寫一句中文描述再附英文原詞，之後可以沿用英文。這和只寫英文不同：讀者第一次讀到時手上有中文說明。

## 判讀徵兆

- 讀者問「這是不是翻錯了」，或者讀完之後用日常意思複述那個術語。
- 譯名在軟體或介面裡已經是另一個東西的名字（游標、把手、書籤、捷徑）。只看字典第一個意思跟技術概念無不無關會誤判：「交易」的日常意思是買賣、「旗標」是旗子，而軟體與介面裡沒有另一個東西叫這兩個名字，讀者不會讀錯。
- 某個譯名只在少數教材或官方文件裡出現，而同一頁裡還有另一個譯法。
- 討論中出現「那就都寫英文吧」，作為避開爭議譯名的方法。

## 探針結果要扣掉的偏差

這次的三份探針裡，有兩份對「游標」的判斷相反：一份認為它是最快讀懂的詞，理由是它在分頁情境「高度約定俗成」；另一份認為它最容易誤解，第一反應是滑鼠游標。兩份相反的結論來自同一個模型。模型覺得「約定俗成」，反映的是它在訓練語料裡常看到這個用法；比較可能的解釋是簡體中文的資料庫與 API 文字普遍把 cursor 寫成「游标」，把模型的熟悉度拉高了（這是推測，這次沒有對照組能排除其他解釋）。目標讀者是台灣讀者時，這一份的結論不能採信，真人讀者若第一個聯想到滑鼠游標，只會比模型更吃力。

推廣成一條判讀規則：探針報告某個譯名「很常見、很快讀懂」時，要先問它常見在哪一種中文的語料（繁中或簡中）。站內另有 [#112](../regional-terminology-alignment/) 處理繁中與簡中的用詞差異，那張卡管的是單一詞彙的對照（螢幕與屏幕），這張卡補的是量測工具本身帶有的語料偏差。

## 跟其他抽象層原則的關係

- [#107 術語翻譯要保留原文錨點](../terminology-keeps-original-anchor/)：規定第一次出現寫「中文（original term）」。這張卡說明為什麼不能退回只寫英文，以及中文譯名要怎麼選。
- [#109 術語翻譯要保留概念角色](../translation-must-preserve-concept-role/)：管的是譯名的名詞頭要對得上概念角色。「游標」的名詞頭沒有錯在角色，錯在它已經是另一個東西的名字，兩條檢查彼此獨立。
- [#289 一個詞是不是通用術語，用多份獨立定義的收斂度量，控制詞決定這批算不算數](../term-probe-measures-register-not-invention/)：提供這次量測的設計條件。這張卡補上一個它沒處理的偏差：模型對某個譯名的熟悉度可能來自另一種中文（簡中）的語料。
- [#307 探針的收斂度分不出無主的詞與已經有主人的詞，要讀有把握那幾份給的定義](../term-already-owned-inside-the-domain/)：「游標」屬於它說的已經有主人的詞，處置同樣是換掉而不是就地定義。這張卡多出的是換成什麼：用詞面描述功能的譯名，並逐一量測候選。
- [#112 地區用語對齊：寫作前先確定讀者的中文語料](../regional-terminology-alignment/)：管繁中與簡中的詞彙對照；這張卡處理的偏差落在量測工具裡，而不是落在作者的用詞裡。
