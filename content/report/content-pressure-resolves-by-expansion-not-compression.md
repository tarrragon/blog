## 結論

教學文章的內容超出容器的自然大小時（判準裝不進表格格、概念裝不進標題、範例讓段落過長）、合法的出口有兩個、壓縮內容遷就容器在這兩個出口之外：

| 出口         | 做法                                                           | 適用條件                                       |
| ------------ | -------------------------------------------------------------- | ---------------------------------------------- |
| 就地展開     | 表格下方加延伸段、判準在正文攤開、標題只承載結論由正文交付推導 | 內容是本篇專屬、其他文章用不到                 |
| 外部化成卡片 | 概念拆成知識卡、範例寫進卡片、文章引用卡片承接論證             | 概念會被多篇引用、或概念自身值得獨立的討論空間 |

壓縮內容遷就容器不在出口之列：判準裁成殘語、範例被砍、推導縮成口訣、都是把裁決權交給容器——容器該服務內容、內容裝不下時換出口或換容器、內容量不是可裁的變數。

出口選擇的判準是**概念角色**：主線概念（本篇論證繞著它轉）必須就地展開——外部化會讓讀者跳出去讀卡、論證線斷裂、術語分級的既有規則在這裡優先；支撐與背景概念可以拆卡、卡片自帶範例、文章保留「什麼情境用哪張卡」的判讀敘事。

**擴充的對象是結構、每句的字數另有裁決者**：卡片盒筆記法的擴充彈性指的是卡片數、範例數、討論空間可以長——句子的長短仍由消費單位分配管（單句消費位要自足、敘事位可壓縮）、metadata 仍由精簡規範管。把本卡讀成「全域加長」跟把容器壓力讀成「該壓縮」是同一類錯：都把裁決權交給了錯的層。

## 為什麼內容會被裁去遷就容器

生成端的**容器形狀先驗**：生成文字時、標題傾向固定的長度帶、表格格傾向短語、段落傾向固定節奏——這個規律在輸出端可直接觀察（歸因到訓練材料組成無從驗證、本卡的宣稱停在可觀察的輸出分布）。形狀先驗讓因果方向反轉：本該由內容決定容器、實際上內容被裁切去符合容器的預期形狀——一個需要三句話的判準放進表格格時被裁成殘語、或者更隱蔽：作者根本沒展開、因為容器的形狀暗示「這裡只該放這麼多」。

人工寫作有同構的推力：「讓文章乾淨」「表格對齊好看」是正當的追求、但用壓縮實現它就走錯了出口——文章變短的合法方式是外部化（細節住進卡片、每篇自然短）、不是把每句削薄。

## 反模式：簡報式文章

壓縮遷就容器的終點形態：標題句化、表格當主體、格內塞判準殘語、段落退化成條列的連綴——讀者拿到的是談話要點（talking points）、缺推導與範例。簡報這個文體的正當性主要來自**有講者在場補完**：投影片上的殘語由講者的口頭展開承接。文章沒有講者、把文章寫成簡報等於把補完責任丟給不存在的人。

判讀訊號：

| 訊號                                     | 判定                                             |
| ---------------------------------------- | ------------------------------------------------ |
| 表格是段落的主體、正文只有表格前後各一句 | 違反既有的「表格不是終點」、每格需要延伸段或拆卡 |
| 表格格裡是判準殘語（無主詞、指涉懸空）   | 同時命中單句消費位的自足要求、展開或外部化       |
| 段落由條列連綴、沒有推導句銜接           | 條列間的推導被壓掉了、讀者拿到結論拿不到理由     |
| 讀者反映「像簡報、不像文章」             | 整篇的補完責任落空、逐段跑出口選擇               |

邊界：**簡報式的判定看消費單位、不看表格密度**。skill reference 的 checklist、audit 清單、規格表的表格形態合法——消費單位是逐項執行；教學與檢討內容裡的**查表型段落**（判讀徵兆表、關係表、「訊號 → 判定」對照表）同一機制豁免——消費單位是逐列查詢、每列的自足義務由句自足規則承接、逐列補延伸段反而製造重複。簡報式違規的精確形態是：承載推導的內容被塞進表格、推導句從正文消失——判定問「推導還在不在正文」、不問「表格佔比多少」。

## 內容壓力是拆卡訊號

文章寫作中撞到「這個概念展開會讓本段過長、但砍了讀者接不住」時、這個壓力本身就是建卡訊號——跟既有建卡判準（讀者缺這個術語就難以理解教材）互補：那條從讀者缺口出發、這條從內容壓力出發、兩條指向同一個動作。卡片的規格本來就裝得下範例：範例是卡片的正當組成、概念加範例住進卡片、文章引用卡片、討論空間靠增加卡片成長。

淨收益有一個未驗證的變數：拆卡對搜尋落地的讀者有利（聚焦落點）、對順讀模組的讀者是跳轉成本。這個取捨的實際方向需要試點驗證（挑既有模組的一兩章實際拆卡改寫、冷讀對照）、在試點結果之前、本卡的拆卡建議停在「支撐與背景概念」這個保守邊界。

## 判讀徵兆

| 訊號                               | 該做的事                                                   |
| ---------------------------------- | ---------------------------------------------------------- |
| 判準寫進表格格時裝不下、想刪字     | 停——選出口：本篇專屬就加延伸段、跨篇可用就拆卡、內容量不動 |
| 概念展開會讓段落過長、想砍範例     | 內容壓力是建卡訊號：概念加範例住進卡片、文章引用           |
| 文章讀起來像簡報                   | 逐段跑出口選擇；先確認文體——checklist 型內容的表格形態合法 |
| 想拆卡的概念是本篇論證的主線       | 就地展開、外部化會斷論證線——術語分級的行內展開規則優先     |
| 拆卡改寫後冷讀反映跳轉過多、論證斷 | 收緊拆卡判準、把誤拆的主線概念收回正文                     |

**核心**：容器該服務內容。內容裝不下時、換出口（延伸段）或換容器（卡片）、內容量本身不是可裁的變數——文章要短、讓細節搬家、別讓細節消失。
