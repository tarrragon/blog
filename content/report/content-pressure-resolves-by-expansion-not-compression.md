## 結論

教學文章的內容超出容器的自然大小時（判準裝不進表格格、概念裝不進標題、範例讓段落過長）、合法的出口都在結構層、壓縮內容遷就容器在這些出口之外：

| 出口         | 做法                                                                   | 適用條件                                                                                                                                                                                                         |
| ------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 就地展開     | 表格下方加延伸段、判準在正文攤開；標題只承載結論、推導由正文交付       | 內容是本篇專屬、其他文章用不到                                                                                                                                                                                   |
| 外部化成卡片 | 概念拆成知識卡、範例寫進卡片、文章引用卡片承接論證                     | 概念會被多篇引用、或概念值得擁有獨立的討論空間；前提是內容集合已有可被引用的卡片層                                                                                                                               |
| 換成連結     | 刪掉格內的壓縮重述、格子改放指向既有落點的連結、正文只留本篇專屬的判讀 | 概念已經有卡或有專章承載、而格內那句是它的 gloss（**限 gloss**：本篇的程序要逐項消耗的列舉不適用，見下方冷讀段）。這一格是外部化在「卡已存在」時的分支、不是另一個獨立機制——它重用既有結構、既沒有擴充也沒有壓縮 |

壓縮內容遷就容器不在出口之列：判準裁成殘語、範例被砍、推導縮成口訣、都是把裁決權交給容器——容器該服務內容、內容裝不下時換出口或換容器、內容量不因容器形狀而可裁。內容自身冗餘、誤置或過時時、刪除是合法的處置——但它的觸發源是內容的性質、由[重述型總結段該刪](../summary-section-signals-scattered-prose/)這類既有規範管、跟容器形狀無關。第三個出口（換成連結）與它不同源：那裡刪的是自身冗餘的內容、這裡刪的是**容器誘發**的冗餘——表格三欄的形狀讓作者填一句自撰的簡述（gloss）而不是放一條連結、即使那個概念在同一個內容集合裡已經有完整落點。實測的出口分布見下方試點段（分布會隨卡層覆蓋與跨章關係變動、不是通則）。這一格有一個已知的偵測缺口：判定條件寫成「格內那句是它的 gloss」時、抓得到的是缺連結；**連結齊備而 gloss 也齊備**的形態不觸發任何檢查、而它比缺連結更常見（作者連了卡、順手又把卡的內容抄一段進格子，兩者還可能不同步）。掃描要問的是「這一句的內容在被連的那一頁裡有沒有」、不是「這一格有沒有連結」。

選出口有一個前置檢查：**確認這個概念在內容集合裡只有一個版本**。同一個概念在兩篇以上有互不相容的定義時，三個出口都會把矛盾保留下來——展開會寫出兩套更詳細的版本、連結會把讀者送到一個用不同語彙描述同一件事的地方、外部化成卡則會把其中一套固化成被多篇引用的權威而另一套繼續存在。處置的順序是先指定單一權威載體、其餘各篇沿用它的語彙，再對剩下的內容選容器出口。判定與選載體的做法見[同一個對象的兩套分解](../incompatible-decompositions-look-complementary/)——那張卡管的正是這裡描述的形態（兩套平行發明、修法是選載體）；兩份有共同起源而單向漂移的副本是另一個機制、修法是同步，見[原則層與操作層是兩份會漂移的副本](../principle-operationalization-drifts/)。**兩者的修法相反，所以這個檢查要先分辨是哪一種**。本卡只補一條位置要求：這個檢查在選出口之前，不在之後。

出口選擇的判準是**概念角色**：主線概念（本篇論證繞著它轉）必須就地展開——外部化會讓讀者跳出去讀卡、論證線斷裂、術語分級的既有規則在這裡優先；支撐與背景概念可以拆卡——知識卡是承載單一術語或概念、可被多篇文章引用的獨立短頁——卡片自帶範例、文章保留「什麼情境用哪張卡」的判讀敘事。

**擴充的對象是結構、每句的字數另有裁決者**：卡片盒筆記法的擴充彈性指的是卡片數、範例數、討論空間可以長——句子的長短仍由消費單位分配管（哪些句子會被單獨抽離消費、哪些嵌在敘事裡靠鄰句、見 [#261](../sentence-self-sufficiency-by-consumption-unit/)）、metadata 仍由精簡規範管。把本卡讀成「全域加長」跟把容器壓力讀成「該壓縮」是同一類錯：都把裁決權交給了錯的層。

## 為什麼內容會被裁去遷就容器

生成端的**容器形狀先驗**是文體先驗在容器層的形態（文體先驗的機制以 [#259](../rewrite-preserves-claim-intensity/) 的「文體先驗接管」段為準）。它的可觀察形式是：生成文字時標題傾向固定的長度帶、表格格傾向短語、段落傾向固定節奏。本卡只依賴這個輸出端可直接觀察的分布，所以結論在任何訓練材料組成的假設下都成立。形狀先驗讓因果方向反轉：本該由內容決定容器、實際上內容被裁切去符合容器的預期形狀——一個需要三句話的判準放進表格格時被裁成殘語、或者更隱蔽：作者根本沒展開、因為容器的形狀暗示「這裡只該放這麼多」。

人工寫作有同構的推力：「讓文章乾淨」「表格對齊好看」是正當的追求、但用壓縮實現它就走錯了出口——文章變短的合法方式是外部化（細節住進卡片、每篇自然短）、不是把每句削薄。

## 反模式：簡報式文章

壓縮遷就容器的終點形態：標題句化、表格當主體、格內塞判準殘語、段落退化成條列的連綴——讀者拿到的是談話要點（talking points）、缺推導與範例。簡報這個文體的正當性主要來自**有講者在場補完**：投影片上的殘語由講者的口頭展開承接。文章沒有講者、把文章寫成簡報等於把補完責任丟給不存在的人。

審查時的形態辨識（讀者端收到的訊號歸判讀徵兆表）：

| 形態                                             | 違反什麼                                                                                                |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| 承載推導的內容住在表格裡、正文只有表格前後各一句 | 「表格不是終點」——承載推導的表格每格要有延伸段或拆卡（查表型與 checklist 型段落不適用）                 |
| 標題句化：段標把完整判準壓成短句、正文不再展開   | 標題只承載結論、推導由正文交付——段標壓縮判準且正文不接、是容器壓縮的段標形態                            |
| 表格格裡是判準殘語（無主詞、指涉懸空）           | 同時命中單句消費位（[#261](../sentence-self-sufficiency-by-consumption-unit/)）的自足要求——展開或外部化 |
| 段落由條列連綴、沒有推導句銜接                   | 條列之間的推導被壓掉、讀者拿到結論拿不到理由                                                            |

邊界：**簡報式的判定看消費單位、不看表格密度**。skill reference 的 checklist、audit 清單、規格表的表格形態合法——消費單位是逐項執行；教學與檢討內容裡的**查表型段落**（判讀徵兆表、關係表、「訊號 → 判定」對照表）同一機制豁免——消費單位是逐列查詢、每列的自足義務由句自足規則承接、逐列補延伸段反而製造重複。簡報式違規的精確形態是：承載推導的內容被塞進表格、推導句從正文消失——判定問「推導存在的段落、它的推導還在不在正文」、不問「表格佔比多少」；推導本來就不存在的純參考內容（環境變數表、API 對照）不觸發。

## 內容壓力是拆卡訊號

文章寫作中撞到「這個概念展開會讓本段過長、但砍了讀者接不住」時、這個壓力本身就是建卡訊號——跟既有建卡判準（讀者缺這個術語就難以理解教材）互補：那條從讀者缺口出發、這條從內容壓力出發、兩條指向同一個動作。卡片的規格本來就裝得下範例：範例是卡片的正當組成、概念加範例住進卡片、文章引用卡片、討論空間靠增加卡片成長。

淨收益有一個未驗證的變數：拆卡對搜尋落地的讀者有利（聚焦落點）、對順讀模組的讀者是跳轉成本。這個取捨的實際方向需要試點驗證（挑既有模組的一兩章實際拆卡改寫、冷讀對照）、在試點結果之前、本卡的拆卡建議停在「支撐與背景概念」這個保守邊界；試點若顯示冷讀者的論證跟得上、跳轉成本可接受、再議把邊界放寬。試點的登記狀態見 [backend 分類首頁的橫向工作段](/backend/#橫向工作簡報式段落拆卡試點)。

## 試點結果：逐列判定與處置分診

這一段記的是判定協議實跑兩輪的結果：哪些處置實際被用到、以及分布可不可以推廣。逐列判定之後決定該列走哪一個處置，本卡稱這個動作為**分診**。

第一輪試點取一個資安模組裡相鄰且互為必連的兩章（設計輸入、發版關卡），兩章同屬一組 24 篇共用的樣板——每節一句話、表格當主體、路由欄是裸模組編號。改寫前對兩章的四張表逐列跑 [#261](../sentence-self-sufficiency-by-consumption-unit/) 的抽離重讀（消費單位是一列含鍵欄、輸出復原命題再與原意比對），20 列全數判定資訊不足。兩輪的分診結果並排如下：

| 主處置（每列只計一次）                                                      | 首輪（兩章、20 列） | 第二輪（一章、9 列） |
| --------------------------------------------------------------------------- | ------------------- | -------------------- |
| 先收斂載體（見 [#263](../incompatible-decompositions-look-complementary/)） | 0                   | 5                    |
| 換成連結（概念已有卡或專章承載）                                            | 7                   | 0                    |
| 就地展開（本篇主線、需要延伸段）                                            | 4                   | 0                    |
| 外部化成新卡（概念全站無落點）                                              | 1                   | 0                    |
| 補句內成分（查表型段落，見本卡邊界段）                                      | 8                   | 4                    |

表列的是五種主處置，而出口表上的出口只有三個：多出來的兩項一個是前置檢查（先收斂載體）、一個歸句層（補句內成分由 [#261](../sentence-self-sufficiency-by-consumption-unit/) 的四條件收），兩者都不是容器出口。每列只計一次，所以收斂與容器出口是先後兩層、不是並列的選項：第二輪那 5 列收斂之後還要再走一次容器分診，殘餘內容裡 3 列改放連結、1 列就地展開，最後一列隨階段表整體移除（階段名沿用另一章之後那一列不再有內容），二次分診不另外計數。

首輪有三項可轉為規格的觀察。**第一**、該輪最大的一類是換成連結、而它在試點前不在本卡的出口表上——上一段因此增列。**第二**、主線與支撐的分界在實作時比預期清楚：兩章各自的欄位表就是該章的主線（論證繞著它們轉）、必須就地展開；欄位內部引用的概念（信任邊界、濫用情境、證據包、放行決策、例外協議）都是支撐、全部連出去。改寫後兩章的主線判準都不需跳轉即可讀完、跳轉全部落在支撐概念上——這正是[術語解釋分層](/record/term-explanation-layering-methodology/)預測的分布。**第三**、判讀訊號表（訊號 → 缺口 → 下一步）確認落在查表型豁免內：那 8 格的修法全部是補句內成分與把裸編號換成語意連結、逐列補延伸段會製造重複。

同源在兩個地方削弱這一輪的結論。判定端：20 列全數判定不足這個飽和率要打折看——判定者與改寫者是同一個人、門檻可能過鬆，而協議只要求輸出復原命題、沒有要求對照組，下一輪要對同批未改寫章節隨機抽列跑同一協議當對照。讀者端：跳轉成本的方向沒有被回答，因為冷讀對照也由改寫者本人執行，而「這裡需要先讀那張卡嗎」正是作者最容易通過的判斷。可複驗的只有逐列判定與分診這個程序本身；讀者體驗那一半要等異源冷讀或實際落地行為才算數，所以保守邊界維持不動。

第二輪刻意挑一篇會反駁首輪結論的：同批樣板裡的組織與流程題材（成熟度的組織節奏），它的主線概念在卡層零覆蓋。九列的判定分布因此完全不同——最大的一類是首輪不存在的**跨章矛盾**（整張階段表五列）：該章自訂一套五階成熟度階段，而同模組另有一章定義四階，兩套的切點不同（「可量測」獨立成一階、或者折進可稽核閉環），而該章的判讀訊號表還把另一章當成下一步路由。單獨讀任一篇都不會顯示這件事。處置是把階段定義收斂到既有的那一章、本章沿用它的階段名並補反向指標，剩下的內容才進出口分診。

兩輪的對照是這個試點最可轉為規格的部分：**出口分布不可推廣，而分診程序的可推廣性只驗到一半**。驗到的是程序對輸入敏感（同一位執行者在兩批性質不同的輸入上得到不同分布，所以它不是形式審查）；執行者之間的一致性後來也測了，結果見下方的第二人分診段。首輪的「換成連結」佔多數來自那兩章的概念剛好都有卡；第二輪卡層對主線概念零覆蓋，主處置因此全落在先收斂載體與補句內成分兩類，連結與展開只出現在收斂後的二次分診裡。因此上表列出的分布是一次觀察、不是預期值；每次改寫要重跑分診，而不是套用上一次的比例。

## 冷讀結果：翻轉點在「程序消耗的列舉」

上一段掛著的問題（外部化對搜尋落地讀者是收益還是成本）由一次獨立冷讀回答。執行方式是把三篇改寫後的章節交給一個不知道審查脈絡的讀者、禁止他讀原則卡與 skill、給三個帶著具體問題的落地情境，只要求他記錄卡在哪裡與哪些跳轉是必須的。

結果分得很乾淨。三篇合計約 56 條對外連結，**判定為「不點就接不下去」的只有 6 條（約 11%）**，其餘 50 條（所有知識卡、判讀訊號表右欄的跨章路由、案例引用）都判可選——理由是那些概念在句子裡已經就地講清楚，「合法功能被重新組合成非預期用途」加上匯出那個例子就夠，不需要開卡。支撐與背景概念的外部化因此得到支持。

而那 6 條必須點的全是同一種東西：**這篇文章自己的程序要消耗的一份列舉被放在別處**（資產類別六類、證據包八個欄位、每一類要驗什麼、階段名）。沒有一條是背景術語。翻轉點因此可以寫成一條判準：

> 被外部化的內容若是本篇的程序要逐項消耗的列舉，連結不能取代它——那份列舉要在本篇，定義可以留在卡。

這條判準與第三出口（換成連結）直接衝突過一次，而衝突的實例來自本卡自己的試點：審查依第三出口把兩處「連結齊備而 gloss 也齊備」的重述刪成純連結，冷讀者隨即在那兩處被迫跳出去。兩者的分界是**重述**與**列舉**——刪掉一個概念的壓縮定義是對的（讀者不需要它也接得下去），刪掉一份要逐格填的清單是錯的（讀者的下一個動作就是填它）。第三出口的適用條件因此限縮到 gloss。

冷讀另外指出一個與內容無關的成本：**目的地的語域落差**。兩個被連到的頁面屬於還沒改寫的樣板叢集（開頭「本篇的責任是」、結尾「完稿判準」），冷讀者兩次判斷自己「點進了作者的規劃文件不是給我讀的文章」並退回原文，而他的結論是落地讀者對連結的信任是一次性的——被帶到兩個看起來不是給自己讀的頁面之後，後面的連結不會再點。外部化的收益因此依賴目的地的語域一致，這是拆卡的隱性前提。

一個限制要寫下來：這次冷讀由一個獨立的模型執行、不是人類讀者，它與作者不同源（沒有作者的意圖與脈絡）但仍與作者同類。跳轉成本的方向由它給出，實際落地行為的驗證還沒有做。

## 第二人分診：一致率高而分歧有方向

分診程序的執行者一致性用同一批列量測：把三篇改寫前的六張表（29 列）交給另一個執行者，協議全文寫在指示裡而不讓它讀本卡（本卡有第一位執行者的結果），並禁止它讀 skill 與 git 紀錄。

逐列比對的一致率是 **25/29（86%）**，而四處分歧全部不是隨機落點：

| 分歧的列                       | 第一位     | 第二位     |
| ------------------------------ | ---------- | ---------- |
| 交接路由（設計輸入的最後一欄） | 換成連結   | 先收斂載體 |
| 必備控制（放行前要驗什麼）     | 就地展開   | 換成連結   |
| 例外窗口（帶範圍放行的紀錄）   | 換成連結   | 先收斂載體 |
| 「依賴個別經驗判讀」那一列     | 補句內成分 | 先收斂載體 |

三處的方向相同：第二位判先收斂載體、第一位判了別的，而三處都成立——第一位漏掉了跨章不相容。交接要填什麼在四處各有一套分解（設計章的 routing sheet、模組路由章的交接模板、控制面地圖的兩個 target 欄位、控制面交接章的六個英文欄位）；例外紀錄有三處（放行章自列四項、例外協議章六欄、知識卡六欄）。這兩個數字在分診當時各記錯一次、方向相反，修正過程與計數規則在 [#263](../incompatible-decompositions-look-complementary/)。兩者都是本卡系譜裡[不相容的分解](../incompatible-decompositions-look-complementary/)的實例，而第一位在對這兩列選「換成連結」時，只確認了目的地存在、沒有比對目的地的分解與自己的是否對得上。

這暴露一個協議缺口，而它可以修：**換成連結與先收斂載體在外觀上無法分辨**——兩者都是「這個概念別處已經有了」，差別在別處那一套與本篇這一套是不是同一個切法。所以選「換成連結」之前要多一個動作：打開目的地、把成員並排、確認對得上。少了這一步，分診會系統性地把不相容誤判成可連結，而誤判的方向是單一的（永遠偏向連結）。

第四處分歧（必備控制）是主線與支撐的邊界，兩位的判準不同：第一位問「這是本篇論證繞著轉的東西嗎」，第二位問「這份產出的權威在誰那裡」。這一處有第三方證據可以斷——[上一段的冷讀](#冷讀結果翻轉點在程序消耗的列舉)顯示讀者在那個位置被迫跳出去，而它是讀者要逐項對照的列舉，所以就地展開是對的。兩個判準因此不是等價的替代品：**論證承重測試在「讀者要不要逐項消耗它」這個問題上比權威歸屬測試準**。

第二位執行者另外寫出它實際用的排序規則，值得收進協議：論證承重壓過跨篇重用（既承重又跨篇的概念，判準留在本篇、定義連出去），而兩者都後於「這個對象在別篇有沒有不相容的分解」這個前置檢查——載體未定之前做容器決策，是在對一個還會被改寫的對象選容器。

## Case：章節被容器壓扁的觀察

一批既有教學章節被讀者判定「用字簡潔到辨識不出議題與關心重點」、後續寫作被要求補足引導與舉例。拆開看、問題分兩層：句層是殘語與缺成分（歸 [#261](../sentence-self-sufficiency-by-consumption-unit/)）；容器層是判準被塞進表格格、推導句從正文消失——章節的骨架是「表格 + 前後各一句」、讀者拿到分類拿不到論證、正是簡報式的形態。這個觀察止於讀者判定；改寫端的證據由上方的試點段承接——它證明的是判定可操作（逐列判定與處置分診跑得出結果）、不是修法對讀者有效（冷讀那一半同源）。

## 判讀徵兆

| 訊號                               | 該做的事                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 判準寫進表格格時裝不下、想刪字     | 停——選出口：本篇專屬就加延伸段、跨篇可用就拆卡、已經有卡或專章承載的改放連結、內容量不動                     |
| 概念展開會讓段落過長、想砍範例     | 內容壓力是建卡訊號：概念加範例住進卡片、文章引用卡片承接                                                     |
| 文章讀起來像簡報、或讀者這樣反映   | 逐段跑出口選擇；先判消費單位——checklist 型與查表型段落的表格形態合法                                         |
| 想拆卡的概念是本篇論證的主線       | 就地展開——外部化會斷論證線、[術語解釋分層](/record/term-explanation-layering-methodology/)的行內展開規則優先 |
| 拆卡改寫後冷讀反映跳轉過多、論證斷 | 收緊拆卡判準、把誤拆的主線概念收回正文                                                                       |

**核心**：容器該服務內容——內容裝不下時、換出口（延伸段）或換容器（卡片）、內容量不因容器形狀而可裁。
