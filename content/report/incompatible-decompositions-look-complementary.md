## 結論

同一個對象在兩篇平行章節各自被分解一次時（階段表、欄位組、責任清單、分類法），兩篇單獨讀都自洽，而讀者跨篇移動時判讀結果失效——帶著一篇的分類走到另一篇，找不到對應的那一格。判定用**雙向對映測試**：兩套的成員能不能互相對映完整。不能完整對映就是不相容，而不相容經常長得像互補——兩篇互相連結、語彙不同、各自宣稱處理另一半。

互相連結不是分工的證據。分辨要用**動作測試**：讀者會不會為這件事做同一個動作兩次。一篇的產出是另一篇的輸入時（填完前者的欄位就得到後者需要的材料）是互補；兩篇是同一個動作的兩份指示時（讀者只會分解一次，而兩篇各要求一套）是衝突。

對映測試的產出是候選、不是判決（沿用[命中是候選不是判決](../keyword-bank-hit-is-candidate-not-verdict/)的兩步驟分工），因為它有四種誤判形態：異名同義（「關閉責任」對 exit criteria）與粒度差（一套的一格對另一套的兩格）會給假陽性；同名異義的方向相反、它給假陰性——兩套都有「觸發」而一指自動門檻、一指人工升級時，測試會回報對得上。所以對映之前先對齊兩件事：粒度（責任對欄位、內含對並列）與層級（同一層的分解才比得起來）。

有一個形態不觸發本卡：其中一套**明示自己是子集或簡化**並指回權威處。目錄頁的三類路由表對章節的六類分類法是正當的導航層，[引用要用被引卡自己的分類詞彙](../cite-cards-with-their-own-taxonomy/)那條規則也明說「自己的簡化標明是簡化」合法。外部標準要求的固定分解（法規欄位、稽核框架的控制分類）同理——它改不了、也不該被收斂，處置是與內部分解之間維護一張對照表。判別線在那條規則給的邊界：讀者要不要同時用到兩套。

修法是選單一載體——**載體是這組成員的權威所在，其餘各篇沿用它的名稱、不再自己列一套**——其餘各篇並重新界定自己承擔哪一段。「兩套並陳讓讀者對照」與「同步成一套新的」都不是修法：前者把選擇丟給手上材料最少的人，後者見下方的誤診段。

## 為什麼平行發明是預設

分解是生成內容時最自然的動作。要寫一張表就要有一組欄位，而欄位在需要它的那一刻就地被發明——這是[容器形狀先驗](../content-pressure-resolves-by-expansion-not-compression/)的一個後果：容器（表格）要求一組成員，成員就在填表的當下被造出來。

「去查別篇是不是已經分解過同一個對象」不在寫作流程裡，因為寫作流程的檢查單位是本篇：本篇自洽、本篇有判斷標準、本篇的路由有效。兩套分解由同一個人在不同時間寫下，各自從當下那一篇的需要出發，所以兩套都合理、都完整、也都不知道對方存在。審查也接不到：逐篇審查對這個問題結構性不可見，而跨篇審查的既有維度查的是連結有效性與引用準確性，兩者在這裡都通過。

## 誤診成漂移的代價

這個形態最容易被歸成[原則層與操作層的漂移](../principle-operationalization-drifts/)，而兩者的機制與修法都不同。漂移的兩份副本有共同起源、差異是單向累積的、修法是同步。平行發明沒有共同起源——兩套從來沒有相同過——所以同步做的是在兩套切法之間下一個沒有人設計過的取捨，而不是合併兩份差異。成員數不同不是因為一套漏了：一套切出某一格、另一套把同一件事移到集合之外的段落（下方 case 有實例）。硬要合併時，這些**單側成員**（只出現在其中一套裡的成員）該掛進哪一格沒有答案，而各自的分界邏輯——為什麼切五份、為什麼切六份——在合併後不屬於任何一套，而那條邏輯正是判斷標準可驗收的部分。

偵測方式也不同。漂移查版本與時間順序（哪一份停在舊版）；平行發明要跨篇並置同一對象的分解方式，時間順序在這裡不提供資訊——後寫的那篇不必然是錯的那篇。

## 修法：選載體，重新界定另一篇

載體選的是內容，住址是另一個問題。**判斷標準完整度決定哪一套內容留下**：帶可驗收成員的那一套（有到期日、有關閉條件、有具名 owner）是載體的內容，因為殘缺的那套當載體會把殘缺擴散到每一處引用。**引用數決定住址留在哪裡**，它承擔的是遷移成本而不是品質。引用多而內容殘缺時保留住址、把完整那套的內容搬進去（換內容不換位址）；引用少而內容完整時要先估重導反向連結的成本，成本高於改寫時同樣是搬內容。

兩篇的引用數相當時由讀者路線上的位置決定——收束處那一篇通常已經被下游當成定義處引用。教學內容的章節之間很常見這種平手：本卡實例裡的那幾篇章節，各只有索引與彼此一條入連。而住址候選不限於章節：同一個對象若已經有一張卡，載體的位址通常就在卡層、章節各自沿用它。理由是成員定義本來就是卡的責任，不是卡的入連數比較高——實測過一組相反的（章節十五、卡九），因為整頁入連是由該頁的主題帶來的，與這組成員無關。

非載體那一篇的處置是重新界定 scope，不是刪除。它多半有一面獨立的價值——節奏、凍結流程、可套用的模板——保留那一面、拿掉重複的分解、沿用載體的語彙。剩下的內容不足以成篇時才併篇；只留一個路由殼的後果是殼會繼續出現在索引與路線裡，而讀者到站拿不到實質內容。

收斂之後要補反向指標：載體那篇明寫「分解在這裡、下游的某一段在那一篇」。少了這一條，下一個作者在下一次需要一張表時會再發明一次，因為那個人的檢查單位仍然是本篇。

順序上這件事在容器決策之前。[內容超出容器時的三個出口](../content-pressure-resolves-by-expansion-not-compression/)都預設格內的內容是對的而只是裝錯位置，對不相容的兩套分解，任何出口都會把矛盾一起保留。

## 觸發 case

實例來自同一個資安教學模組，橫跨三種住址組合。

**章對章（成熟度階梯）**：一篇定義四階（人工判斷 / 穩定流程 / 可稽核閉環 / 自動化治理），另一篇定義五階（Manual / Structured / Measured / Auditable / Adaptive）。切點不同——後者把「可量測」獨立成一階，前者折進可稽核閉環——而後者的判讀訊號表還把前者當成下一步路由。讀者用後者判出自己在第三階，走過去對不到任何一格：判讀結果在交界處直接失效。

**章對章（資產類別）**：同一個模組的設計章把服務資產分成三類（資料、入口、憑證），發版章分成五類（認證與授權路徑、對外暴露面、秘密與憑證、資料分級的流向、供應鏈與部署路徑），而發版章明寫「設計階段列出的清單就是發版預檢要對照的那一份」。雙向對映的結果是三類全部對得上、而五類裡的兩類在三類裡沒有格子——照設計章列完清單的人，到發版章會發現預檢要對照的類別有兩類從來沒被列舉過。這一組由審查發現、修法是把兩處收斂成同一套類別（設計階段填得出具體項目的那幾類、其餘先列意圖）。

**章對卡（證據包欄位）**：兩章各自把證據包的欄位重述一次為七項，而卡本身是八項——多一個信心水準。兩章都宣告「欄位規格由卡承載」，所以這一組的外觀是最完整的分工，而讀者照章節填完會少一欄。它同時是[容器壓力那張卡](../content-pressure-resolves-by-expansion-not-compression/)第三出口的漏網形態：連結齊備、gloss 也齊備，而那條規則抓的是缺連結。修法是刪掉章節裡的清單、只留連結與本篇專屬的判讀。

**卡對卡（術語分工）**：一張既有卡描述它與鄰卡的分工時用了「抽象風險分類」這個詞，而鄰卡（後來才建）的自我定義是列舉框架、並把固定分類歸給外部分類法——那個詞在鄰卡裡沒有對映格。四張同族卡各自寫一次四者的關係時，這種出格只有並置才看得出來。

**五處與三處（交接欄位與例外紀錄）**：同一批後來又找出兩組成員數更分散的。「交接要填什麼」在五處各有一套——設計輸入章的 routing sheet、模組路由章的六項交接模板、控制面地圖的 Handoff target 加 Write-back target、控制面交接章的六個英文欄位、案例回寫章的四欄 workflow 契約；「例外紀錄要填什麼」在三處各有一套——放行章自列四項、例外協議章六欄、知識卡六欄。

這兩組的住址數各自被數錯過一次，兩次的錯法相反、都值得記。交接那組漏算兩處，原因在下方的搜尋方法段——搜尋範圍是夠的，寫錯的是搜尋條件，而且錯了兩次（先把載具形式當判斷標準、修正後又把某個成員的名字當宣告樣式的代理）。例外那組多算一處：治理章的五條責任一度被算成第四套，而它描述的是誰要確保什麼、不是紀錄要填什麼，屬於下方邊界示範那一段判定的不同層分解。**同層才計數、不同層要對齊語彙而不是收斂**，兩者混算會讓收斂範圍多出一個不該進去的對象。這兩組的發現方式值得記：它們是第二位執行者對同一批列跑分診時抓到的，而第一位在同樣的列上判了「換成連結」——因為連結的目的地確實存在，只是那裡的分解與本篇的對不上。

兩組後來都收斂了，過程給出修法側的第一份證據。**例外紀錄**的載體判給卡，理由是欄位定義本來就是卡的責任。選的時候另外拿了一個理由——「三個住址裡卡的入連數最高」——而它是錯的：以連進來的檔案數計，治理章十五、卡九、例外協議章六。錯在量測單位而不在數字：入連數量的是整頁被引用幾次，而要選載體的對象是頁裡那張欄位表，治理章的十五條入連幾乎都指向它的治理主題、沒有一條是為了拿欄位定義。**要挑載體時，入連數要數的是指向那組成員的引用、不是指向那一頁的引用**，而兩者在多數情況下差一個量級。這個誤用是本卡判定步驟第一條（對映之前先對齊粒度與層級）的同型錯誤，只是發生在下游的載體選擇上，所以第一條要延伸涵蓋整個修法而不只判定。載體選擇的實際判斷標準仍然是判斷標準完整度與責任歸屬；入連數只決定住址搬不搬得動（遷移成本），不決定哪一套內容留下。卡把六欄各自的判斷標準寫開，填寫協議那一章保留六欄在文內（讀者要逐項填、不能只給連結）但把定義權指回卡，治理那一章的五條責任重新界定成「誰要確保什麼」並逐條標出對應的欄位——它的第四項（掛 tripwire）明寫沒有對應欄位，因為 tripwire 是並列物件。收斂順帶修掉一處異名同義：卡寫 close criteria、章節寫 exit criteria，而全站其他四處都用後者。

**交接欄位**的載體判給模組路由那一章（它是交接的定義處、六項最完整），而收斂時發現兩套互不為子集——載體缺「主責角色」這一項，那一項只有控制面地圖有。所以載體先補上缺的那一項變成七項，控制面地圖再沿用同一組名稱、只保留它獨有的那一軸（控制面歸屬決定主責是誰），設計輸入那一章的交接物格式也指向同一份模板。這一步值得單獨記下來：**收斂不是挑一套刪掉另一套**——兩套各有對方缺的成員時，載體要先補齊才有資格當載體，否則收斂會丟掉內容。

同一條規則在第四處被找出來之後立刻用了第二次，而這次的單側成員比第一次重要：控制面交接章有「該輪任務完成條件」，載體的七項沒有。載體的風險邊界寫的是升級與停止條件，講的是何時中止；完成條件講的是何時可以結案並把責任交回，缺了它交接會停在「已經交出去」而沒有人宣告收到。載體因此補成八項。補的時候沒有沿用原處的名字（`Exit condition`）——例外那組已經有一個 `exit criteria`，兩者是不同物件（一個問這一輪算不算接完、一個問例外能不能關），照抄會在載體上留下一組同名異義。**補齊載體時要順手檢查新成員的名字在載體上有沒有已經被佔用的近義詞**，收斂的目的是讓讀者只查一處，而一處裡有兩個 exit 等於把歧義搬進了唯一的住址。

還有一組**較弱的同型觀察**，它的限度值得寫下來：例外協議在一篇是五條治理責任、在另一篇是六個紀錄欄位。表面上兩側各有單側成員：觸發不在六欄位裡、關閉條件不在五責任裡。逐項核對原文之後兩者都站不住——六欄位那篇把 tripwire 提升成並列物件、自帶四欄協議，而關閉條件在五責任那篇當時寫在同章的判讀流程裡（收斂已把它提升成第五條責任、這裡描述的是收斂前的狀態）。所以這一組是責任對欄位的粒度差加上一個成員被提升層級，不是同層的兩套分解；後果也弱一級——讀者照六欄填完仍會在同章讀到 tripwire 協議，屬於部分閱讀下的漏格，不是判讀結果失效。它留在這裡當**判定的邊界示範**：對映之前沒有對齊粒度與層級的話，這一組會被誤判成一個實例——上方的住址計數就誤判過一次。不同層的處置與同層不同：五責任那篇不必放棄自己的分解，逐條標出對應的欄位就夠了，因為讀者要做的動作只有一次（依責任確認有沒有人在管），欄位表是他確認完之後才去填的東西。

證據的共同限制寫在這裡：所有實例來自同一個模組、同一位作者、同一批寫作，而且多數在審查中被發現。機制（容器要求一組成員、成員在填表當下被就地發明、而寫作流程的檢查單位是本篇）在多作者環境更容易成立，所以普遍性的方向不受威脅；受威脅的是修法——多作者環境裡「誰有權指定載體」是本卡沒有定價的成本。

搜尋方法可重用，而它的第一版寫錯了條件，值得連同錯法一起記：**掃的對象是「帶固定成員清單的段落」、不是「帶表格的段落」**。第一版寫成掃表格，因為最早那幾個實例（資產類別、證據包欄位）恰好都用表格承載，於是歸納時把載具形式當成了判斷標準。照那份條件跑一遍會漏掉全部六個欄位住址——它們全是編號清單或項目清單，沒有一個是表格。交接那組的第四處就是這樣被漏掉的。修正後的條件是：找出所有「宣告一組固定成員、要求逐項填寫」的段落，不論它排成表格、編號清單或連續散文，再把描述同一類對象的那些並置。

**條件改對之後又漏了第五處，而這次錯在執行不在規則。** 改對的條件是「宣告一組固定成員的段落」，而實際跑的搜尋用了某個成員的名字當代理（拿「回寫」這一欄去掃），於是沒有回寫欄的那一套整個不在視野裡——它的四個成員是觸發、負責人、證據、完成條件。這是同一個代理錯誤的第三次：載具形式代理宣告樣式（掃表格）、頁面入連代理成員入連（選載體）、成員名代理宣告樣式（這次）。三次的共同形狀是**拿一個容易 grep 的東西代理一個要讀懂才能判定的條件**，而代理與被代理者分岔的那些案例，正好是這個搜尋要找的目標。可操作的防線是：搜尋條件寫成「宣告樣式」時，執行也要對著宣告樣式跑——掃的是「都要包含 / 至少要有 / 要填 / 欄位如下」這類宣告句，不是任何一個成員的名字。

並置之前先用鍵欄（表格最左欄，或清單裡各成員的名稱）對齊粒度，這一步會擋掉外觀相似而對象不同的組。同一批裡有四個章節各有一張五列表、最後一列都叫回寫，並置起來很像同一個對象的四套分解；鍵欄描述的是**階段**而不是**欄位**，而三者的階段主體各不相同（處理一起進行中的事故、設計一次驗證演練、建一張情境卡），所以不成立。這個否定結果與上方那組邊界示範是同一條判斷標準的兩次應用。

## 判讀徵兆

| 訊號                                         | 該做的事                                                                                                                                                       |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 兩篇的標題含同一個名詞、各自有一張表         | 並置兩張表的鍵欄，比對成員與成員數                                                                                                                             |
| 想把格內的自撰解釋改成一條連結               | 先打開目的地把成員並排——連結與收斂在外觀上無法分辨，差別在目的地那一套與本篇是不是同一個切法；少了這一步會系統性地把不相容誤判成可連結，而誤判方向永遠偏向連結 |
| 收斂完成、要在紀錄裡寫住址數                 | 逐處重數一次而不是沿用發現時的數字。實測兩組都數錯、方向相反：一組漏算兩處（搜尋條件錯了兩次，見搜尋方法段）、一組多算一處（把不同層的分解算進同層集合）       |
| 要挑載體而其中一處的入連數明顯較高           | 數的是指向那組成員的引用、不是指向那一頁的引用。整頁入連通常由該頁的主題帶來、與這組成員無關，兩者差一個量級                                                   |
| 兩套成員數不同而語意重疊                     | 跑雙向對映，兩個方向都跑——各自單側的成員是損失最大的，讀另一篇的人拿不到它                                                                                     |
| 兩篇互相連結、語彙不同、各自說對方處理另一半 | 互連不是分工的證據，跑動作測試：讀者會不會為這件事做同一個動作兩次                                                                                             |
| 想把兩套同步成一份、或並陳讓讀者對照         | 停——那是漂移的修法。平行發明要選載體，並陳把選擇丟給手上材料最少的人                                                                                           |
| 選好載體後，另一篇剩下的內容不足以成篇       | 併篇。只留路由殼會讓它繼續出現在索引與路線裡，而讀者到站拿不到實質內容                                                                                         |
| 想在寫作流程裡加一條「先查別篇」的自我提醒   | 檢查單位是本篇的流程接不到這個問題，把它放在跨篇並置的那一輪（改寫前的分診或批次審查）                                                                         |

**核心**：分解方式也有住址。同一個對象的兩套分解不是兩個視角，除非讀者會同時用到兩套。
