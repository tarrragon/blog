## 結論

同一個對象在兩篇平行章節各自被分解一次時（階段表、欄位組、責任清單、分類法），兩篇單獨讀都自洽，而讀者跨篇移動時判讀結果失效——他帶著一篇的分類走到另一篇，找不到對應的那一格。判定用**雙向對映測試**：兩套的成員能不能互相對映完整。不能完整對映就是不相容，而不相容經常長得像互補——兩篇互相連結、語彙不同、各自宣稱處理另一半。

互相連結不是分工的證據。分辨要用**動作測試**：讀者會不會為這件事做同一個動作兩次。一篇的產出是另一篇的輸入時（填完前者的欄位就得到後者需要的材料）是互補；兩篇是同一個動作的兩份指示時（讀者只會分解一次，而兩篇各要求一套）是衝突。

修法是選單一載體、其餘各篇沿用它的語彙並重新界定自己承擔哪一段。「兩套並陳讓讀者對照」與「同步成一套新的」都不是修法：前者把選擇丟給最沒有材料選的人，後者見下方的誤診段。

## 為什麼平行發明是預設

分解是生成內容時最自然的動作。要寫一張表就要有一組欄位，而欄位在需要它的那一刻就地被發明——這是[容器形狀先驗](../content-pressure-resolves-by-expansion-not-compression/)的一個後果：容器（表格）要求一組成員，成員就在填表的當下被造出來。

「去查別篇是不是已經分解過同一個對象」不在寫作流程裡，因為寫作流程的檢查單位是本篇：本篇自洽、本篇有判準、本篇的路由有效。兩套分解由同一個人在不同時間寫下，各自從當下那一篇的需要出發，所以兩套都合理、都完整、也都不知道對方存在。審查也接不到：逐篇審查對這個問題結構性不可見，而跨篇審查的既有維度查的是連結有效性與引用準確性，兩者在這裡都通過。

## 誤診成漂移的代價

這個形態最容易被歸成[原則層與操作層的漂移](../principle-operationalization-drifts/)，而兩者的機制與修法都不同。漂移的兩份副本有共同起源、差異是單向累積的、修法是同步。平行發明沒有共同起源——兩套從來沒有相同過——所以同步會產出一個兩邊都不像的第三套：把五個責任與六個欄位合成一份十一項的清單，讀者拿到的是沒有人設計過的東西，而原本各自完整的判準在合併中損失（每一套的成員之間有它自己的分界邏輯，混在一起之後那條邏輯不在了）。

偵測方式也不同。漂移查版本與時間順序（哪一份停在舊版）；平行發明要跨篇並置同一對象的分解方式，時間順序在這裡不提供資訊——後寫的那篇不必然是錯的那篇。

## 修法：選載體，重新界定另一篇

載體的判準有三項，依序套用：被多少處指向（引用數）、判準的完整度（有沒有帶可驗收的成員，例如到期日與關閉條件）、以及在讀者路線上的位置（收束處的那一篇通常已經被當成定義處引用）。

非載體那一篇的處置是重新界定 scope，不是刪除。它多半有一面獨立的價值——節奏、凍結流程、可套用的模板——保留那一面、拿掉重複的分解、沿用載體的語彙。剩下的內容不足以成篇時才併篇；只留一個路由殼是最差的結果，因為殼會繼續出現在索引與路線裡，而讀者到站拿不到東西。

收斂之後要補反向指標：載體那篇明寫「分解在這裡、下游的某一段在那一篇」。少了這一條，下一個作者在下一次需要一張表時會再發明一次——他的檢查單位仍然是本篇。

順序上這件事在容器決策之前。[內容超出容器時的三個出口](../content-pressure-resolves-by-expansion-not-compression/)都預設格內的內容是對的而只是裝錯位置，對不相容的兩套分解，任何出口都會把矛盾一起保留。

## 觸發 case

兩個實例來自同一個資安教學模組，surface 不同。

**成熟度階梯**：一篇定義四階（人工判斷 / 穩定流程 / 可稽核閉環 / 自動化治理），另一篇定義五階（Manual / Structured / Measured / Auditable / Adaptive）。切點不同——後者把「可量測」獨立成一階，前者折進可稽核閉環——而後者的判讀訊號表還把前者當成下一步路由。讀者用後者判出自己在第三階，走過去對不到任何一格。

**例外協議**：一篇分五個責任（決策 / 期限 / 補償 / 觸發 / 關閉），另一篇分六個欄位（風險範圍 / 到期日 / 補償控制 / owner / 關閉條件 / 回寫目標）。雙向對映跑下來只有一項只存在於一側：關閉條件——它在五責任那一側被折進期限責任的「重評估條件」裡，所以照五責任填的人不會產出一個可驗收的關閉條件，而那正是例外治理最容易失效的一格。兩篇互為必連章節，第三篇同時路由兩者，外觀完全是分工。

第一個實例在一次逐列改寫的判定中浮現；第二個是為了判斷該不該立這張卡而做的反例搜尋找到的。兩者不是同一個 artifact 被數兩次——一個是狀態分類法、一個是欄位組——所以[第二個實例](../two-occurrence-threshold/)的訊號成立。搜尋方法本身可重用：對同一個模組列出所有帶表格的章節，把鍵欄描述同一類對象的表並置。

## 判讀徵兆

| 訊號                                         | 該做的事                                                                               |
| -------------------------------------------- | -------------------------------------------------------------------------------------- |
| 兩篇的標題含同一個名詞、各自有一張表         | 並置兩張表的鍵欄，比對成員與成員數                                                     |
| 兩套成員數不同而語意重疊                     | 跑雙向對映，找出只存在於一側的成員——那一項是損失最大的，讀另一篇的人拿不到它           |
| 兩篇互相連結、語彙不同、各自說對方處理另一半 | 互連不是分工的證據，跑動作測試：讀者會不會為這件事做同一個動作兩次                     |
| 想把兩套同步成一份、或並陳讓讀者對照         | 停——那是漂移的修法。平行發明要選載體，並陳把選擇丟給最沒有材料選的人                   |
| 選好載體後，另一篇剩下的內容不足以成篇       | 併篇。只留路由殼會讓它繼續出現在索引與路線裡，而讀者到站拿不到東西                     |
| 想在寫作流程裡加一條「先查別篇」的自我提醒   | 檢查單位是本篇的流程接不到這個問題，把它放在跨篇並置的那一輪（改寫前的分診或批次審查） |

**核心**：分解方式也有住址。同一個對象的兩套分解不是兩個視角，除非讀者會同時用到兩套。
