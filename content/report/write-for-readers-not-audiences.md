## 論述基礎與限制

這則檢討處理教學與檢討內容的敘事姿態：標題該用什麼形式、內容以什麼視角組織。觸發案例是一篇 work-log 檢討文章——標題是問句（「寫註解前先問：這件事能不能讓程式自己講？」）、段標帶懸念（「追問下去：我到底在怕什麼」）、全文以第一人稱事件敘事組織（第一版被退、第二版還是被退、追問之後才想清楚），核心判準被壓到全文後半。這篇與同批的 report 卡經過多輪審查，敘事姿態問題零 finding，由使用者讀後指出。

限制有兩項。**單一案例**：一篇文章、一種文體背景（LLM 生成的教學敘事），對其他作者群的推廣是機制類比。**受眾狀態的斷言沒有量測**：「讀者自帶問題來」是從內容的抵達路徑（搜尋、站內路由）推導的，沒有讀者行為資料佐證；這條斷言錯的話，本卡的判準要重新檢討。

## 核心原則

**演講與教學文章面對的受眾狀態不同，姿態因此不同。** 演講面對的是注意力隨時會流失的聽眾，hook、懸念、個人故事是維持注意力的合法工具。教學與檢討內容的讀者由搜尋或路由帶來、自帶問題與動機，他要的是判準與脈絡，被扣住的答案對他是額外成本。把演講技巧搬進教學內容，代價全部落在資訊結構上。

兩類具體形態：

### 懸念型修辭

問句標題、懸念段標、三幕劇遞進（第一次失敗、第二次失敗、轉折、頓悟）。三者共同點是**把結論扣住、逼讀者陪跑完整個過程**：

- 標題是檢索錨，錨要承載結論。問句標題把一篇文章唯一保證被讀到的 surface 用來提問，讀者掃過標題列表時拿不到這篇的立場。
- 懸念弧把核心判準壓到文末，正面違反「核心原則先行」——讀者跳讀時先撞到案例、最後才拿到定義。

判別線是**位置**：操作型自問句（判準的執行步驟，如「把型別名稱唸出來、還剩什麼資訊」）合規，它是讀者要執行的動作；出現在標題、段標或結論位、答案被扣在後文的問句是懸念型，要改成直述。

**修懸念的方向是壓平敘事、不是搬運結論。** 把判準抽成開頭一段直接給、推導擺後面，讀者拿到的是一段沒有支撐的話、只能硬記——概念要由讀者沿著推導自己長出來，不是被交付。灌輸與懸念是同一個缺陷的兩個方向：都讓結論與推導脫節。分工是標題承載結論（檢索錨、給掃列表的讀者）、開頭承載情境定位（讓讀者判斷自己在不在射程內）、判準在推導走完的位置浮現。文首的「觸發場景 / 整理目的 / 本文邊界」欄位組同理——它把各段結論先摘出來放在推導之前，是灌輸的欄位化形態；需要交代事件來源時一句話就夠。

### 第一人稱事件敘事

檢討內容以「我做了、我被退、我才想清楚」的個人時間線組織。問題有兩層：可重用的判斷被包在一次性的個人經歷裡，讀者要自己做一次抽象才能套用；而「reviewer 說了什麼、我當下怎麼想」這類敘述把判斷的成立條件藏進對話重現裡，條件本身沒有被陳述。

修法是**把事件單位換成條件單位**：「reviewer 問了 X」改成「若對這個做法問 X 而答不出來，就該重新檢討」。脈絡照樣保留——做錯了什麼、為什麼錯、為什麼要糾正——但載體從個人時間線換成客觀條件，人物以角色出現（reviewer、修改者），順序以推導組織而非經歷組織。內容來自實際事件這件事，開頭一句話交代就夠。

## 為什麼多輪審查抓不到

三層，由深到淺：

**規範缺位。** 「檢討內容用客觀視角」「標題是直述句」在事發當下不存在於任何規範。compliance reviewer 的工作是對照規範找違規，一條不存在的規範產生不了 finding——零 finding 與「沒有問題」在報告裡是同一個訊號，這是「規則存在不等於規則涵蓋」在審查 frame 層的形態。

**frame 射程。** 字句層 keyword bank 是現象枚舉（喊話、口語、誇飾、必然性框架），問句標題、懸念弧、第一人稱都不在枚舉內；而 register 類的 persona 檢查掛在教學模組批次審查的讀者旅程 frame 下，單篇 work-log 通常不進那條流程。問題落在所有 frame 的射程之外。

**同源文風默認。** 問句標題勾興趣、三幕劇遞進是教學流派的常見手法、也是 LLM 生成的高頻默認文風；同源 reviewer 共享「故事帶入是好教學」的直覺，讀到懸念弧覺得自然。這一層與 register 同源盲區同構——就算前兩層修好，同源判定仍會放行一部分，異源冷讀是殘餘的防線。

---

## 修法：防線的主力在生產側

規範缺位的修法不是往審查加枚舉。敘事姿態是**寫的當下決定的文風默認**，靠審查撈是逆風；把規則寫進生產側規範（寫作 skill、模板），生成時就不產生。審查側的 keyword 是補位：

```bash
rg "^title:.*[？?]" content/          # 問句標題
rg "^#{2,} .*[？?]" content/          # 問句段標
rg "才想清楚|還是被退|我到底|我於是" content/   # 敘事轉折詞
```

命中是候選不是判決：操作型自問句、引用「」內的原句、以敘事為目標的內容合規。第一人稱密度是輔助訊號——檢討類文章的「我」密度顯著高於同資料夾其他篇時，值得逐處判定。

模板也要跟著修：內容模板若寫成「問題情境 → 範例 → 解法」，「問題情境」會被最省力地填成個人事件劇。模板要明定情境的單位是條件（什麼樣的程式、什麼操作會遇到），「這來自實際事件」的宣告開頭一句話帶過——展開成「觸發場景 / 整理目的 / 本文邊界」欄位組是灌輸的欄位化形態。

## 沒這樣做的麻煩

**判準的可達性打折。** 跳讀的讀者在文章前半只拿到故事，判準在文末；搜尋落地的讀者看到問句標題無法判斷這篇有沒有立場。內容本身是對的，包裝讓它難以被取用。

**問題持續留著。** 這類語氣問題不觸發任何既有檢查，每一篇新文章都可能再產生一次，且每次都會通過審查——直到某個異源讀者指出。事發案例正是這樣：問題存在於已發布的文章裡，審查跑了多輪，指出它的是使用者。

## 跟其他抽象層原則的關係

- **[#166 重點優先陳述是跨語言的資訊結構原則](../lead-with-the-point-cross-language/)**：本卡是它的篇章層形態。#166 處理句子層的重點後置（「不是 X、而是 Y」），本卡的懸念弧是同一個缺陷放大到篇章——判準被壓到文末、問句標題把重點完全扣住。#166 的「不適用：敘事 / 懸念類寫作」豁免由本卡限定：豁免屬於以敘事為目標的文體（小說、演講稿、隨筆），教學與檢討內容即使取材自事件也不落在豁免內。
- **[#165 register 違規：偵測可機械化、判定要靠文體異源](../register-violation-needs-cross-style-eyes/)**：本卡第三層根因（同源文風默認）是 #165 的實例，但本卡的第一層根因在它上游——#165 處理「規則存在、同源判定放水」，本卡的案例連規則都不存在，審查失效不需要走到判定那一步。兩層要分開修：先立規範、再談判定的異源防線。
- **[#221 檢查規則的作用域要顯式列舉](../lint-scope-must-be-explicit-fact/)**：同構在審查 frame 層。#221 講 lint 的零 error 與「沒被涵蓋」訊號相同，本卡的多輪審查零 finding 與「該維度不在任何 frame 射程內」訊號相同——審查報告不會標示自己沒看什麼。
- **[#170 description 是 recall trigger、不是摘要](../description-as-recall-trigger/)**：同族——兩張卡都把 metadata surface 當功能件而非修辭位。#170 規定 description 回答「什麼情境下需要回來讀」，本卡規定標題承載結論；問句標題在這個分工下是把功能位挪去做修辭。
- **[#255 讀者重建不了的斷言清單，展開成讀者位置的走查](../assertion-list-needs-reader-walkthrough/)**：本卡「灌輸」那一半的段落層形態與修法範式。本卡指出未經推導的結論讀者只能硬記，#255 把它落到段落單位——條列式斷言逐條跑重建測試（讀者用文中材料能不能自己得出這條）、重建不了就展開成走查（讀者位置、動作加材料、結論後置）。

## 判讀徵兆

| 徵兆                                             | 該做的行動                                                        |
| ------------------------------------------------ | ----------------------------------------------------------------- |
| 標題或段標以問號結尾                             | 把答案寫進標題，問句降到正文當操作步驟                            |
| 核心判準出現在全文後半、前半是遞進的失敗敘事     | 敘事壓平成條件推導，判準在推導走完的位置浮現                      |
| 開頭有一段未經推導的結論摘要或結論欄位組         | 抽掉，開頭改承載情境定位，結論交給標題與推導                      |
| 檢討文章的「我」密度顯著高於同資料夾其他篇       | 逐處判定：事件來源開頭一句話帶過，正文改條件視角                  |
| 正文重現「某人說了什麼、我當下怎麼想」的對話場景 | 抽出那句話背後的條件，改寫成「若 X 則該重新檢討」                 |
| 審查多輪零 finding 但異源讀者一眼指出語氣問題    | 先查該維度在不在任何規範與 frame 的射程內，缺位就先立規範再補檢查 |

## 適用範圍與邊界

- **適用**：教學文章、work-log 檢討、report 卡、知識卡——一切以「讀者帶問題來取用」為抵達模式的內容。
- **邊界**：
  - **以敘事為目標的文體**：演講稿、簡報、隨筆、故事性寫作。懸念與第一人稱在那裡是設計，本卡不適用。
  - **一句話的事件來源交代**：「這來自一次實際的兩輪退件」這類開頭一句話合規，它宣告內容的來源，正文才是判準的載體；展開成多欄位的結論摘要組就越界了。
  - **操作型自問句**：判準的執行步驟寫成問句（「唸出型別名稱後還剩哪幾個字」）合規，它是讀者要執行的動作、答案由讀者自己的材料產生，沒有被扣住的結論。
