## 論述基礎與限制

本卡從一次用詞對齊抽出。一篇講 schema 變更管理的 backend 文章在開場界定：「退回」指交易的 `ROLLBACK`，「回滾」指部署之後把程式或 schema 撤回前一版。後續把兩篇 Go 文章的用詞對齊到這個約定時，發現站上沒有任何一張知識卡定下這兩個詞：Transaction 卡只用英文 rollback，Rollback Strategy 卡用「回滾」而沒有跟交易的 rollback 分開，devops 的同名卡寫「回退」。

接著把四個中文候選送術語探針（低階模型四份，指令逐字相同；控制詞「交易隔離等級」四份收斂，安慰劑詞「交易回填序」四份都答沒聽過，這一批可採用）：

- 「退回」四份有把握，第一個意思都是把工作項目送回給作者（審核退回、PR 退回），沒有一份把交易的 `ROLLBACK` 放在第一個。
- 「回滾」四份有把握，第一個意思是把已上線的系統撤回前一版，兩份另外列出資料庫交易的 `ROLLBACK`。
- 「回退」三份不確定，跟回滾分不清，還可能指 fallback。
- 「回復」指從備份還原、從故障恢復，是 recovery。

限制是一則個案、一組詞、四份探針。推翻方式：找一個英文原詞一詞多義、而中文社群已經用兩個不同的詞分開它的術語，若只寫中文就能讓讀者穩定對到正確的定義，本卡「兩個名字都要寫」的要求對那一類詞是多餘的。

## 核心原則

**一張知識卡的所指是英文術語與中文名稱這一對，不是其中任何一邊。** 英文原詞與中文名稱各自都可能有好幾個定義：rollback 在英文裡同時指資料庫的交易回滾與部署之後的撤回，「回滾」在中文裡也同時指這兩件事，「退回」在同一個領域裡已經被審核流程佔用。只寫英文、或只寫中文，讀者拿到的是一個多義的詞，他會用自己第一個想到的意思去讀，而那個意思不一定是作者連到的那張卡。

**成對才指得定，前提是這一對在站上只對到一張卡。** 兩邊都多義的時候（Rollback（回滾）），成對也還是兩個意思，要在至少一邊加上分辨的限定：交易回滾（transaction rollback）、部署回滾（deployment rollback）。判斷這一對夠不夠的問句是：把它當成連結文字讀，站上有沒有第二張卡也配得上這兩個名字。

**原文錨點的前提在這裡不成立。** 「術語翻譯要保留原文錨點」把英文原詞當成概念的單一真實來源，中文譯名可以調整、原文不漂移。這個前提假設英文原詞只有一個所指；rollback 這一類英文本身多義的詞，原文錨點同樣指不定，要靠英文與中文成對、至少一邊加上限定來分開，所以兩邊缺一不可。

## 反模式：拿一篇文章的約定當全站的定案

一篇文章在開場界定兩個詞的分工，在那一篇裡讀者讀得懂。別篇要對齊用詞時，最省力的做法是照那篇的約定改，看起來是在統一用詞，做的事是把一篇文章的局部約定推成全站的寫法，而那個約定沒有量過讀者會怎麼讀。

本次的實例：兩篇 Go 文章照那篇的約定把「退回的方法」改成「回滾到前一版」之後才發現，那個約定裡的「退回」對讀者來說是審核退回。對齊做完了、提交也推上去了，錯的是被對齊的那個基準。

## 修法

**定詞之前先量，量的是中文候選，不是英文原詞。** 把幾個中文候選連同控制詞、安慰劑詞送術語探針，讀有把握那幾份寫的定義，判斷每個詞第一個被讀成什麼；英文原詞在探針那裡多半收斂，量它只會得到「通用」，看不出它本身多義。

**定案寫進知識卡，卡的標題就是那一對。** 標題寫「英文（中文）」，定義段寫出這一對指的是哪一個定義，以及同名的另一個定義是什麼、寫在哪一張卡。兩個意思都已經有卡在講時（交易回滾在 Transaction 卡、部署回滾在 Rollback Strategy 卡），改既有卡的標題與定義段，不另建重疊的卡。

**文章連到卡時，連結文字寫成卡標題的那一對。** 正文寫「交易回滾（transaction rollback）」、連結文字寫 [Transaction（交易）](/backend/knowledge-cards/transaction/)，讓讀者在離開本文之前就知道要讀的是哪一個定義；卡的標題與文章的寫法是同一對，讀者用英文或中文搜尋都找得到這張卡。

**同一對名字已經是另一張卡的標題時，這張卡的名字寫出它講的是哪一件事。** backend 與 devops 原本各有一張 `Rollback Strategy（回滾策略）`，講的都是部署回滾；分工之後 backend 那張寫事故當下判斷要不要回滾，devops 那張寫靜態站、後端服務與 App 各自怎麼撤回前一版，兩張各自承擔不同的語意責任，而標題仍是同一對，連結文字照標題寫也分不出連到哪一張。把模組寫進連結文字，讀者看得到，但規則要多一種連結文字的格式，用完整名稱搜尋時兩張仍然都會出現；只靠網址區分，讀者在點進去之前看不到。所以 devops 那張改名，候選名連同控制詞、安慰劑詞送術語探針（控制詞「交易隔離等級」四份收斂、安慰劑詞「發布回填序」四份都答沒聽過，這一批可以採用）：「回滾機制」「Rollback Mechanism」四份都同時列出交易回滾與部署回滾，「版本回滾」另被讀成文件版本還原與 git revert；「Release Rollback」四份都讀成把一次發布撤回前一版，「發布物回滾」四份都標不確定、猜的意思都是把已發布的產物換回前一版。定案為 `Release Rollback（發布物回滾）`。

**正文裡既有的大量舊用詞不批次改。** 本次全站有數百個檔案寫著「回退」「退回」「回滾」，各自的意思要逐處判斷；批次替換會把審核退回、fallback 這些正確的用法一起改錯。定案寫進卡之後，改到哪一篇再對齊那一篇的用詞。卡的標題與連結文字的補齊不屬於這一條：連結文字照卡的標題寫不會改錯意思；替標題補中文時要選譯名，照術語探針的條件定名。全站的補齊記成待辦，跟自動把專有名詞連到卡的工具一起做。

## 跟其他抽象層原則的關係

**限定 [#107 術語翻譯要保留原文錨點](/report/terminology-keeps-original-anchor/) 的前提。** 那張卡讓英文原詞負責鎖定概念邊界、當跨譯名的單一真實來源；本卡補英文原詞本身多義的情形：rollback 的原文錨點同樣指不定，所以卡的身分是英文與中文這一對，必要時再加限定。

**套用 [#307 探針的收斂度分不出無主的詞與已經有主人的詞](/report/term-already-owned-inside-the-domain/) 的判讀。** 「退回」四份都有把握，收斂度看起來是通用詞，讀有把握那幾份的定義才看出它在同一個領域裡已經歸審核流程所有。

**與 [#370 借用中文日常詞當術語譯名的誤讀](/report/borrowed-everyday-word-as-translated-term/) 互補。** 那張卡處理中文那一邊撞到介面上的同名元素（游標）；本卡處理兩邊各自多義、只能靠成對與限定分開的情形。

**沿用 [#289 術語探針量的是語域不是自創](/report/term-probe-measures-register-not-invention/) 的控制詞設計。** 本卡的量測靠同批的控制詞收斂、安慰劑詞全數沒聽過，才把四個候選的回報當成可以採用的證據。
