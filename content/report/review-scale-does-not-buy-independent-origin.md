## 論述基礎與限制

本卡從一次併行寫作抽出，事件在 2026-08-28。兩個 session 同時在同一個模組工作，各自跑完四輪審查——一邊派出 31 個 agent、涵蓋 15 個 frame（含 13 份低階模型探針），另一邊派出 16 個 reviewer 與 13 份探針。兩邊各自的字句層掃描都回報乾淨。

交換檢視時，各自一眼看到對方一處違規：前者的小節標題「融資部位的緩衝被三日跌停吃穿」是物理化錯配，後者新增的「量最大的一類不是詐騙而是流通的操作手法」是否定起手。兩處都在對方跑過多輪掃描之後仍然存在。

限制：實例只有兩處，樣本小，而且兩邊都不是隨機取樣的獨立觀察者——它們是同一套規範下的兩個執行者。本卡的機制論述不依賴樣本量，但「外部一次就抓到」這個效果量不該從這兩個實例外推。

**第二個實例（2026-09-02）的來源比第一個乾淨。** 一個 session 對四篇稿件跑完三輪、派出六個 reviewer 與六份低階模型探針，字句層十七類逐類跑過、逐格抽離重讀做過、術語探針有控制詞。而使用者一次閱讀指出一句「機械不了」——把「機械」這個沒有動詞義的名詞當動詞用。它躲過每一個 frame 的原因逐一可指認：字句層 bank 裡用詞搭配那一類的 pattern 是 `說完的話|想告訴|潛台詞|訊號.{0,4}很直接`，抓不到動詞化；冷讀 reviewer 讀得懂所以放行；理解探針讀的是另一篇；術語探針測的是名詞的通用度，不測詞性。**這一次的觀察者確實在派發樹之外**，而漏掉的那一類正是本卡點名依賴來源的那一類。

本卡談的是 register 與用詞搭配這一類——判定要讀懂「讀起來對不對」、無法完全 regex 化的違規。形式違規（裝飾符號、broken link、編號錯位）不適用，那一類加工具就解決。

## 核心原則

一個 session 派出的所有 reviewer 與探針構成單一來源。它們讀的是同一份稿、拿的是同一個人寫的 prompt、繼承同一個 context 建立起來的框架。增加數量提高的是**覆蓋的面**，不是**視角的來源數**。

而 register 類違規的偵測依賴的正是來源。「讀起來自然」這件事由文體先驗決定，同一個先驗底下讀幾次都自然；派十個 reviewer 去讀，得到的是同一個先驗的十次執行。

## 實例：同一個判斷標準，套在自己的文字上通過、套在別人的文字上不通過

物理化錯配這一類有一個可機械執行的判斷標準：問這個動詞照字面成立需要什麼物理條件，需要重量或支點的就是借來的。

寫下「緩衝被三日跌停吃穿」的那一邊，那一輪跑過三次物理化錯配的 grep（清單裡有「啃」而沒有「吃穿」，所以三次都零命中），也在同一輪用判斷標準逐句掃過自己的文字——包括這個小節標題——並判定通過。另一邊拿到同一份稿，套用同一個判斷標準，當場判定不通過：緩衝是百分點，沒有可被咬穿的材質。

差別不在標準，也不在誰比較仔細。差別在寫的人讀到那個標題時取回的是自己的意圖（這一節在講緩衝不夠用），而讀者取回的是字面。

同一輪裡還有一個對照組能說明清單不是主因：同一邊的翻譯探針抓出了另一處清單外的物理化錯配（「承擔不了雙向的論證重量」）。所以那個 session 對這一類是有偵測力的，它只是對**自己下的標題**沒有。

## 為什麼這個缺口在自審時看不見

小節標題、文章標題與 description 是作者對內容的濃縮，作者重讀時讀到的是被濃縮的那個東西，不是濃縮出來的字。正文的句子還有機會被當成陌生文字重讀，標題不會——它是作者自己剛剛決定的那個意思的代號。

派出去的 reviewer 不解決這件事，因為它拿到的 prompt 由作者撰寫。prompt 裡的用語、舉的例子、劃定的範圍，全部來自同一個文體先驗；一個把「吃穿」讀成自然的人，寫出來的審查指令也不會把它列為要注意的形態。

## 修法

**把併行的另一個 session 當成異源視角，而不只是衝突來源。** 兩個 session 同時動到同一批檔案時，第一反應通常是協調提交邊界。提交邊界要協調，而那個場合同時提供了平常拿不到的東西：一個讀同一份稿、而不繼承你的 context 的讀者。

**交換的單位是掃描而不是評價。** 請對方「掃我的、我掃你的，用同一份規範」會得到可判定的結果；請對方「看看我寫得好不好」會得到同源的評價，因為對方會用你的框架回答你的問題。

**不要用加輪次或加 agent 數來補這一類。** 那買到的是更多同源的執行。沒有併行 session 時，退回既有的異源手段（外部冷讀、低階模型探針），並且記得自己派的探針仍然是同一棵派發樹的一部分——它們的價值在於不會自動補完殘缺的句子，不在於來源不同。

**優先掃自己濃縮過的位置。** 標題、小節標題、description、表格的鍵欄，這些是作者意圖與字面最容易分岔的地方。

## 跟其他原則的關係

跟 [#165 register 違規需要異源視角](/report/register-violation-needs-cross-style-eyes/) 是同一條線的延伸。那張卡指出同源 reviewer 對 register 類有結構上限；本卡把「同源」的範圍畫大——不只是作者與他的 reviewer，**整棵派發樹連同它跑的探針都是同一個來源**。所以「我派了三十個 agent」不構成異源已經覆蓋的證據。

跟 [#267 關鍵詞清單只收違規義項占多數的詞](/report/keyword-list-needs-dominant-violating-sense/) 處理的是相鄰而不同的問題。那張卡回答「漏抓了要不要擴充清單」，答案是看該詞的違規義項比例；本卡補的是即使不擴充清單、改用判斷標準逐句掃，**同源的人套用同一個判斷標準在自己的文字上仍會通過**。換偵測方式解決不了換來源才能解決的事。

跟 [#234 用詞要貼合概念的屬性](/report/word-choice-fits-concept-attributes/) 的關係是實例與母題。本卡的兩處實例都落在那張卡描述的錯配類型裡，而本卡不處理怎麼判定錯配，只處理誰判定得出來。

- [#300 查證回報的單位是宣稱，而失效的單位可能是整個框架](../verification-reports-claims-but-failures-are-framed/) 記的是本卡的一次正向應用。把事實查核整批轉派給另一個 session 之後，回報裡有三項是本側跑完多輪審查都沒有動搖過的判斷，其中一項推翻了整篇的軸。轉派買到的不只是視角，還有額度——搜尋額度按執行者計算而不累計，所以耗盡的一方轉派出去，同一批工作仍然做得完。
- [#301 限制類宣稱的錯誤會自我保存，因為它勸阻的正是唯一能推翻它的那個動作](../capability-limits-suppress-their-own-refutation/) 是本卡的另一次應用。錯誤的限制宣稱對寫下它的人不再可疑（那次失敗是他親眼看到的），而併行的另一個執行者沒有那段記憶、照常去試，於是四則錯誤宣稱是被互相指認出來的，兩個 session 各出兩則。
- [#311 reviewer 給的數字要用被審對象宣告的口徑重跑一次](../reviewer-measurement-needs-the-audited-scope/)：本卡的推論之一。派再多 reviewer 也不會讓量測自動可信，而複驗那一步無法靠增加 reviewer 完成——它要由讀報告的人回被審對象做。

## 判讀徵兆

自己的掃描回報乾淨，而外部一次就指出違規——這是最直接的訊號，出現時要問的是「我的掃描為什麼漏了」而不是「這次比較不小心」。

「這一句我讀過很多遍」本身是訊號而不是保證。重讀次數多代表同一個先驗被執行了很多次。

違規集中在標題、小節標題、description 這些位置，而正文相對乾淨。

跑完多輪審查之後，回頭問「這幾輪裡有哪一輪的執行者不是我派的」——答案是零時，register 這一層的結論要標「未經異源抽查」。
