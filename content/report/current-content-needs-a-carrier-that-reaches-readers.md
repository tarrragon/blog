## 論述基礎與限制

本卡處理的是一段內容該放在哪個載體上，判斷標準是兩問：這段內容的正確性會不會隨時間失效，以及這個載體改完之後到不到得了讀者。它從一次內容規劃的提問失誤抽出。規劃一條財務書單線時，選書判定有一個維度問「讀者具不具備這本書預設的環境」，而財務書的環境差異最大的一塊是稅制與退休制度。當時給出的三個選項是：只描述書預設什麼制度、對本地制度做實質判定、或折衷只在整章失效時點名——三個都預設問題出在判定的強度不夠。否掉整組選項的回應是：那類知識變化太快，根本不該指望從書上讀到。

這句話改變的是問題的層級。判定強度是對單一實例的調節，而稅制與書之間是一組固定的條件：讀者手上那一本印出來之後不會再變，而稅制每年修正——判定做到多細，下一次修法之後仍然全錯。

站內另有兩個獨立到達的實例，而它們落在不同形態的載體上，這一點比實例數重要：

- **資安標準的引用**（[#104](../security-citation-currency-and-precision/)）：NIST 的密碼政策 2014 版要求定期更換、2017 版明示不要，引用未標版本的讀者套用的是反向的規範。載體是自家文章、改得動也送得到讀者，所以那張卡的修法是版本與年份標記加 review trigger。
- **LLM 安全的案例庫**（[#118](../standard-driven-vs-case-driven-domain-judgment/)）：該領域的案例半衰期約六個月，而建一座案例庫要八到十二小時，六個月後整批過時。載體是自己維護的內容集合、改得動而更新成本高於收益，所以那張卡的修法是換成標準框架。
- **本次的稅制與書**：載體是別人寫的、印出來的，改不動也送不到讀者手上，所以修法是不承接、只留指標。

這三個實例的修法各不相同，而差異落在同一個地方：那個內容有沒有人負責維護、維護完到不到得了讀者。這是本卡把判別拆成兩問、而不是給一個變動速率比值的直接理由——三個實例裡只有兩個算得出比值。

限制有四項，第二項最重要。

三個實例都來自內容生產，沒有一個來自軟體或營運。

**三個實例分不出這個判斷標準的軸與它的代理變數。** 第二問拆成「有沒有人負責維護」與「維護完到不到得了讀者」，而三個實例裡這兩件事總是同進同出，各自做了多少工分不出來。分得出來的是另外兩種情形：有人負責而送達路徑很弱（勘誤表掛在官網、沒有人會去看），以及送達良好而無人維護（自家頁面隨時改得動，但沒有任何人的工作項目包含它）。兩種都不在手上的實例裡，本卡對它們給的答案未經檢驗。這跟本卡取代的那個說法（變動速率的比值）失敗的位置不同——那個說法的病是問了算不出答案，這裡的病是答案有了、而分格的邊界沒有實例落在上面——成因則相同，都是實例太少。

**三個實例的進入條件是「載體錯配後來被辨識出來」。** 此刻仍在靜默過期、從未被任何人指認的段落不在樣本裡。因此本卡說明得了這類錯配的形狀，說明不了它的發生率或漏檢率——這正是 [倖存者偏誤](/business/knowledge-cards/survivorship-bias/) 的形態，篩選發生在「有沒有被指認出來」這一關，而那張卡與本卡同一批寫成。

修法側未驗：指出承接者之後讀者實際會不會走過去、以及「路徑弱」那一格的門檻要多高才算走得完，都沒有數字。

## 核心原則

**一段內容能不能放在一個載體上，由兩問依序決定**，而順序有作用：第一問答完就決定要不要問第二問。

**第一問：這段內容的正確性會不會隨時間失效。** 最快的訊號是問這一段的主體是規則本身、還是讀規則的方法——稅率、額度、當期價格、版本號、資格門檻是前者，報表各項目之間的關係、某個機制為什麼成立，是後者。答「不會」時第二問不必問：過時的語法示範不影響它示範的那條主張，那屬於時效判定而不屬於這裡。

這個訊號有兩處會漏，兩處都要單獨接住。**讀規則的方法會跟著規則的結構一起失效**：認列模型換掉（營運租賃搬進表內之後，「怎麼從附註推估表外負債」整段作廢，連帶動到負債比的讀法）、主管機關改揭露版式，這時方法那一側也落回「會失效」。**還有一類既不是規則、也不是讀規則的方法**——世界狀態的觀測值：這個市場上有沒有那類工具、當年的資訊不對稱程度到什麼地步、某個做法現在還有多少人在用。它們沒有條文可以查，判斷要回到第一問本身：這句話描述的那個狀態，五年後還會是同一個嗎。

**第二問：這一份到讀者手上之後，有沒有一條會被實際走完的更新路徑。** 它拆成兩件事，兩件都成立才算有：**有沒有人負責維護那個內容**，以及**維護完之後那一份到不到得了讀者**。

| 更新路徑 | 例                                                             | 判定                               |
| -------- | -------------------------------------------------------------- | ---------------------------------- |
| 沒有     | 一般的印刷書、發布後不再送達的文件、別人維護而你只能引用的內容 | 讀者手上那一份不因為出了新版而改變 |
| 弱       | 有勘誤表或線上修訂而要讀者主動去查、逐年出新版而讀者未必換     | 存在但要估到達率，不能當成已經走完 |
| 有       | 自家的線上頁面、訂閱制推送更新的電子書、活頁式加替換頁的彙編   | 看維護頻率跟不跟得上內容的變動     |

「印出來就等於沒有路徑」是這條線收的那類書的實情，不是印刷品的本質——法規彙編做成活頁加替換頁訂閱、專業出版的線上版推送修訂，都是為了這個問題長出來的形態。判定要看實際的出版節奏與讀者換版行為，兩者都是會變的商業與行為事實。

兩問合起來給四種處置。第一問答「不會」就照寫。第一問答「會」時看第二問：路徑「有」就落回 [#256](../doc-sync-needs-mechanism-or-demotion/) 的分級（給它機制或誠實降級）；路徑「沒有或弱」時有兩條路——把當期值搬到自己維護得動的載體、這一份指過去（**自建承接者**），或者不承接、只留一個指向外部權威的指標（**路由**）。兩條的選擇條件寫在下面。

**單一個比值算不出答案，這是這裡拆成兩問的理由。** 書的改版以年計、稅制的修正也以年為單位，比值接近一、看起來不算失衡；改用讀者手上那一本去算則週期是無限大，於是每一本書都失衡，連過時的語法示範都被掃進來。路徑不存在時比值沒有定義，第一問才是那裡唯一在做工的判斷標準；路徑存在時比值才有意義，而那時它問的是「維護頻率夠不夠」而非「該不該放這裡」。

路徑「沒有」時的處置固定是兩步，而第二步常被省略——上面四種處置裡的後兩種，就是這第二步的兩個選項。路徑「弱」的走哪一邊由估出來的到達率決定：估得出多數讀者會走完就當「有」、按 [#256](../doc-sync-needs-mechanism-or-demotion/) 分級，估不出來或明顯偏低就當「沒有」、照這兩步做，而「沒查過」要記成「沒有」。

1. **內容層只留規則的讀法**——機制、關係、怎麼讀那類資料。具體的值不寫。
2. **指出承接者**——自建一份自己維護得動的，或指向外部有維護承諾的來源。

讀者拿這段去做決定確實需要那個值時，只做第一步是把問題丟掉。降級一段稅務章節成「撰稿當時的快照」在紀錄上誠實，而讀者要的是現在的稅率，於是那個問題落地無人接手。這是本卡跟 [#256](../doc-sync-needs-mechanism-or-demotion/) 分工的位置：那張卡的三級處理「這份文件該被怎麼讀」，降級到 scaffold 或記錄就結案；本卡處理「讀者的問題誰來回答」，降級之後還欠一個承接者。具體值只是舉例而非讀者要拿去用的東西時，刪掉即完整修好，不欠第二步。

**判定的單位是「這段內容加上判定者手上所有可用的載體」，不是眼前那一個。** 這一點要寫成選擇，因為它最容易在沒有人決定的情況下被跳過：改不動的常常只是引用來源那一層，而做判定的人自己往往握有一個改得動的載體。書單引用的書印出來就定了，書單自己卻是一個可更新的頁面——它完全可以自建一段每年更新的制度摘要。選擇不自建的理由是維護成本與職責範圍（一份書單不是稅務網站），那是 [#256](../doc-sync-needs-mechanism-or-demotion/) 的成本論證，要明講，不能寫成「載體不允許」。自建與路由之間怎麼選，看兩個量：自己維護那一份要花多少、以及路由過去之後讀者實際走完的比例有多高。

外部也找不到承接者時（見解只散在個案函釋、當期值鎖在付費終端），那本身就是一則要寫下來的判定：**明說這個問題目前沒有可指的承接者**，比留一個過期的數字或一句「自己查一下」誠實。路由並非零成本——指向公告頁同樣把成本轉給讀者，只是少一步搜尋；那是程度差，不是把成本消掉了。

這條規則往上會產出範圍規則。一個載體確認承接不了要維持當期的內容之後，**整批以當期值為主體的內容就不進這個載體**——整本講當期稅務規劃、當期補助方案或當期商品比較的書不收進書單，理由是載體選錯而非品質不足；那類內容的正確形態是每年更新的官方文件，做成書只是讓它以更難察覺的方式過期。

## 反模式

**把載體問題當判定深度問題。** 症狀是某一項判定總是不準，回應是加維度、加細則、加查證流程。代價有兩層：成本上升，而且判定框架看起來變完整了——加完之後那一格填得滿滿的，沒有任何訊號顯示它下一版就會全錯。兩問存在的理由就是在加深之前先問一次。

**把有人在維護的內容複製一份到沒有更新路徑的地方，理由是讀者需要。** 讀者確實需要，而複製產生的是一份沒有機制守著的副本，也就是 [#256](../doc-sync-needs-mechanism-or-demotion/) 的錯配格。原本只需要一個指標的位置，變成一份會靜默過期的具體數字。

**用免責聲明換取照寫。** 「以撰稿時為準」讓作者免責，讀者拿到的仍是可能已經錯的具體值，而且具體值比留白危險——它足夠具體到被直接拿去用。免責聲明處理的是責任歸屬，不是讀者手上那個數字的正確性。

**判定框架遇到不適用的維度時留空。** 空白與「查過而沒有依賴」在頁面上長得一樣，而兩者導出的動作方向相反：讀成「還沒查」的人會去查一次，讀成「查過沒依賴」的人直接跳過——同一格一個增加工作、一個取消工作。跳過那一側還有一層不直觀的後果：那一格從此不會再被查，而覆蓋率的統計把它算成已完成，於是維護狀態的數字比實際好看，錯的方向還是往好的那邊。不適用要寫成一句明確的宣告（「本維度對這一類主題不適用，原因是這個載體沒有更新路徑」），這跟 [#256](../doc-sync-needs-mechanism-or-demotion/) 對降級要明示、以及處境判定要三分（有限制 / 查過沒依賴 / 尚未檢查）是同一個機制。

## 修法

1. **先答第一問，再答第二問。** 順序不能顛倒：主體是讀規則的方法而規則的結構沒在變時，更新路徑不必問。
2. **答第二問之前先盤點手上所有的載體**，不只眼前這一個。引用來源改不動，不等於判定者自己沒有改得動的地方。
3. **沒有更新路徑時，內容層只留規則的讀法。** 具體值換成一句「這一段的推導依賴一套會變的制度」加一個承接者。這句話不會過期，任何一個具體稅率都會。
4. **承接者要指名，並估一下讀者走不走得完那條路。** 「自己查一下」不指名任何人，效果接近沒有處置；指到主管機關的公告頁或年度報告要一併說明那裡多久更新一次。
5. **在收錄或範圍規則上寫下這條界線。** 判定是逐篇的，而範圍規則讓下一個人不必重新判一次。界線的形式是「以當期值為主體的內容不進這個載體」，並註明理由是載體而非品質——不註明的話，下一個維護者會把它讀成品質判斷並在遇到寫得好的那一本時推翻它。
6. **不適用的維度要留下宣告而不是空白。** 一併寫出不適用的是哪一類主題、以及承接者在哪。

## 判讀徵兆

| 訊號                                                         | 該做的事                                                                   |
| ------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 判定的內容裡出現了一個具體數字（稅率、費率、額度、資格門檻） | 寫下的當下就先答兩問，不必等它失準                                         |
| 某一項判定每次改版都要重做，而改完仍然很快失準               | 停止加深判定，先答兩問                                                     |
| 想在一段內容後面加「以撰稿時為準」                           | 那是第二問答否的訊號；具體值路由出去、只留規則的讀法                       |
| 某個維度第一次對某一類主題給不出判定                         | 當場分辨是這個維度對這類主題不適用、還是這一本的資料不足，不要等到「總是」 |
| 判定框架裡某個維度對某一類主題總是給不出有用的答案           | 寫成明確的不適用宣告並指出承接者，不要留空、也不要填一個弱判定             |
| 準備把每年更新的官方資料整理進一份印出來或不再送達的文件     | 只寫讀那份資料的方法，不複製它的值                                         |
| 把這一段當成讀者手上唯一的材料時，它不足以做出那個決定       | 那一段的內容層應該只剩指標與方法                                           |
| 一批內容以當期值為主體（當期稅務、當期價格、當期商品比較）   | 在收錄或範圍規則上寫下界線，並註明理由是載體而非品質                       |
