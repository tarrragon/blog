## 論述基礎與限制

本卡基於一次多輪審查中、兩處中文搭配問題由人類冷讀 catch 的事故。背景：一批退場決策文章，agent reviewer 跑完 register / cadence / 冷讀多輪都沒抓到兩處「順口但語義錯位」的搭配——「綜合評估那句『勞動報酬而非資本報酬』背後沒說完的話」（把一個分析角度擬人化成會說話的主體）、「判讀訊號很直接」（用「直接」形容訊號的可辨識度）。兩處都由作者以外的人類當場指出。第三種錯配（物理化）由後續一次書單審查補上，成因相同而規模大得多：使用者在十二個 agent reviewer 跑完三輪之後指出「撐得住」這個寫法，全站掃描命中三百多處。第四種錯配（範疇）與擬人化的主體條件判斷標準由再後續一次書單條目的使用者逐字修訂補上：「書裡沒有自述」改「沒有明說」、「前提在讀者這裡不存在」改「不適用於一般讀者」、四頁共用的「在讀者這裡存不存在」改「讀者具不具備」，同批確認全站「作者自述／課程頁自陳」類第一方出處標記合法、差一步就被誤殺。2026-10-14 修訂物理化錯配的修法：一位讀者指出「撐」這一族與「問題」這個詞是同一類，佔著需求與判斷標準的位置而沒有填進內容，修法要寫出需求、判斷標準與機制，換成「足以支持」這類關係動詞不算修好；同一次取消了系統負載的豁免（見〈足夠性斷言要寫出需求、判斷標準與機制〉）。限制：case 是中文寫作，但原則（描述抽象概念要選屬性相符的謂語）跨語言成立；且它是 register 類問題、agent 同源自審對它有結構盲區（見 #165）——物理化那一種是例外，它有穩定關鍵詞、可以進自動掃描的候選層。

## 核心原則

**描述抽象概念時，選跟該概念真實屬性相符的動詞與形容詞，不套用習慣上順口、但語義錯位的搭配。** 抽象概念（分析角度、框架、訊號、指標）沒有人的行為屬性、也沒有具體物的物理屬性——給它配上不相符的謂語，句子讀起來順、但語義是錯的。判別方法只有一個問題：這個謂語真的描述了這個名詞的屬性嗎，還是只是順口。順口是語感慣性、不是語義正確。

四種常見錯配：

- **擬人化錯配**：把分析角度或框架當成會說話、有意圖的主體——「這個角度沒說完的話」「數字想告訴我們」「框架背後的潛台詞」。角度不會說話；它的屬性是涵蓋範圍，精確的說法是「這個角度沒有涵蓋／沒有提到的問題」。
- **形容詞錯配**：用一個習慣性但屬性不符的形容詞——「訊號很直接」。「直接」描述的是方式或態度（直接說、直接處理），不是訊號的可辨識度；訊號的可辨識度屬性用「清晰／明確／明顯」。
- **範疇錯配**：給概念配上另一個範疇的謂語或介詞框架——「前提在讀者這裡不存在」（命題沒有存在與否、只有適用與否）、「在讀者這裡」（人不是地點、進不了處所框架）。精確的說法是「不適用於讀者」「讀者具不具備」。
- **物理化錯配**：給抽象概念配上承重、支撐、懸掛類的動詞——「這個證據撐不撐得住」「論證掛在哪個前提上」「這套說法會垮」。證據跟結論之間沒有重量、沒有支點、沒有材料強度，那些動詞不帶進任何資訊，只是把讀者對物理世界的直覺借過來蓋住「這裡實際上是什麼關係」。修法依句子在做什麼而分兩種：描述關係的（論證掛在前提上、責任由誰扛）換成關係動詞——論證**依賴**前提、責任由某人**負責**；足夠性斷言（宣稱某個對象足以或不足以滿足某個需求的句子：證據撐不撐得住、方法撐不久、這套說法會垮）要寫出需求、判斷標準與機制，見〈足夠性斷言要寫出需求、判斷標準與機制〉。

物理化錯配有一個可以機械執行的偵測方法：**問這個動詞如果照字面成立，需要什麼物理條件**。它用來找出候選、不決定修法。需要重量、支點、材料強度、上下方位、身體部位的，就是借來的——抽象概念不具備那些屬性。「撐得住」需要一個承受力量的結構，「掛在」需要一個掛點，「垮」需要一個會倒塌的體積，「咬得最深」需要牙齒；證據、論證、判斷標準都沒有。

這個判斷標準可以一般化到全部四種錯配：**問這個謂語（動詞、形容詞、介詞框架）照字面成立，需要主詞或賓語具備什麼屬性**——物理化要的是物理條件（重量、支點），擬人化要的是**主體條件**（一個自我、意圖、發話能力），範疇錯配要的是**範疇條件**（命題要有存在性才能「不存在」、人要是地點才進得了「在～這裡」的處所框架），形容詞錯配問的是同一個問題的形容詞版（「直接」要描述的對象有迂迴程度可言）。

主體條件的判定沿轉喻鏈問：「作者自述」「課程頁自陳」「FAQ 自陳」合法——頁面是作者的發話面、主體在鏈上；「書自述」「角度沒說完的話」違規——鏈上沒有能發話的主體。「自 X」動詞另有一個極性軸：「自」承載第一方出處訊號，正面宣告時它做工（「在該社頁面上自陳為節選本」＝是它自己說的、不是第三方評的），否定句裡它不做工——「書裡沒有自述」要說的只是「沒有明說」，而「自述」的名詞義（自傳式陳述）讓否定句再多一層「沒附自述文件」的誤讀。同一個詞正面合法、否定違規，命中是候選不是判決的又一個軸。

替換時還有一層：**原句描述的若是關係的程度（多深、多緊、多重），替換要用狀態詞而不是另一個動作動詞**。動作動詞會帶進一個施力的主體與一個承受的對象，而抽象關係之間沒有施力方向——「這本書跟協作形態咬得最深」換成「與協作形態耦合最緊」是對的，換成「咬合最深」只是換一個動作、缺陷原封不動。判斷方式是問這句在講什麼：講**關係本身**（證據與結論之間怎麼連上）用關係動詞（支持、依賴），講**關係的程度**（連得多緊）用狀態詞（耦合最緊、依賴程度最高）。

例外是**明示並就地展開的類比**：把它寫成類比、而且在同一段裡把物理意象逐項對應回真實機制（「團隊認知負荷有上限，因此邊界是承重結構而非官僚產物」——上限對應承重、超過會塌對應交付失效），那是刻意建立的模型，而不是隨手借詞。判斷標準是那個物理意象有沒有被展開成可以逐項檢查的對應關係；沒有展開的就是借詞。

## 反模式：順口的搭配蓋過語義的正確

**Instance 1（擬人化）**：原句「這正是綜合評估那句『勞動報酬而非資本報酬』背後沒說完的話」。「勞動報酬而非資本報酬」是一個判讀角度，被寫成「說了一半、還有話沒說完」的說話者。角度沒有「說」或「沒說完」這個行為屬性，它的屬性是「涵蓋了什麼、漏掉了什麼」。修正：「綜合評估用『勞動報酬而非資本報酬』這個角度時沒有提到的問題」。

**Instance 2（形容詞錯配）**：原句「判讀訊號很直接：如果……」。訊號的屬性是可辨識度（清不清楚、明不明顯），不是「直不直接」——「直接」形容的是行為的迂迴程度。修正：改用「訊號很明確」，或直接陳述訊號本身、拿掉這個評價性套語。

**Instance 3（物理化）**：原句「取證據來源撐得住『被拿去支持實際決定』這個用途的那本」「這本書的結論能撐多重的決定」。書的結論沒有重量，這裡實際發生的關係是「這個結論可以支持多大範圍的主張」——換成「支持」之後，句子還多回答了一件原句迴避掉的事：支持什麼、支持到什麼範圍。**借來的物理動詞不只是不精確，它還讓作者不必回答那個問題**，因為「撐得住」聽起來已經像個答案。這是它跟前兩種錯配的差別：擬人化與形容詞錯配是說錯了，物理化錯配是繞過了。

### 足夠性斷言要寫出需求、判斷標準與機制

Instance 3 已經指出「撐得住」讓作者不必回答支持什麼、支持到什麼範圍，而先前的替換表把它換成「足以支持／不足以支持」，換完之後那個缺口還在：「足以支持」一樣沒說要支持哪個決定、到什麼程度算足夠。「撐」這一族在這種句子裡與「問題」這個詞是同一類（見 [#374](/report/question-answer-frame-blurs-problem-issue-request/)）：它佔著需求與判斷標準的位置，聽起來像答案，而內容沒有填進去。換成另一個動詞，只是把同一個空位換個詞佔著。

所以足夠性斷言改寫時寫出三件事：

- **需求**：要支持哪一個決定、承受什麼負載、維持多久。
- **判斷標準**：滿足到什麼程度算夠——門檻、範圍、條件。
- **機制**：靠什麼屬性滿足，或在哪一點不再滿足。

| 原句                         | 句子實際要交代的                       | 改寫要寫出的內容                                                                                    |
| ---------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 這本書的結論撐得起實際決定嗎 | 結論能用在哪些決定上                   | 結論的資料來源與期間，足以判斷哪一類決定、不足以判斷哪一類，理由是資料涵蓋什麼                      |
| 這個證據撐不住               | 證據不足以支持某個主張                 | 主張是什麼、需要什麼樣的證據才成立、這個證據少了哪一項（樣本、對照、時間範圍）                      |
| 這套說法會垮                 | 論證在某個條件下不成立                 | 哪一個前提在什麼情形下不成立、不成立之後結論變成什麼                                                |
| 方法撐不久                   | 方法無法持續執行                       | 持續執行需要什麼資源或條件、哪一項會先耗盡、大約在什麼規模或時間點                                  |
| 單台資料庫撐得住這個流量     | 單台資料庫在預估負載下能否符合服務目標 | 預估的負載（尖峰每秒寫入數）、判斷標準（例如 p99 延遲門檻）、瓶頸在哪一項資源，以及這些數字從哪裡量 |

描述關係、不是足夠性斷言的句子，換成關係動詞就完整：

| 借來的物理動詞     | 實際的關係               | 改寫                   |
| ------------------ | ------------------------ | ---------------------- |
| 論證掛在某前提上   | 論證與前提之間是依賴關係 | 依賴／取決於           |
| 資料支撐某個結論   | 資料為結論提供佐證       | 佐證／支持             |
| 某人扛某個責任     | 責任歸屬                 | 負責                   |
| 跟某個條件咬得最深 | 關係的**程度**           | 耦合最緊／依賴程度最高 |

兩種的分界問一句：**這句話是否在宣稱某個對象足以或不足以滿足某個需求**。是，就寫出需求、判斷標準與機制；不是，換成關係動詞。「資料支撐」在「這份資料支撐這個結論到什麼程度」的句子裡是足夠性斷言，同一個詞落在哪一種要看句子。

**系統負載不再豁免。** 先前的掃描規則把主詞是系統負載的句子列為合規（「撐住尖峰流量」「拖垮 OLTP」），理由是那裡的「撐」有實際的物理對應。物理對應存在，需求與判斷標準照樣被省略：「單台資料庫撐得住這個流量」沒說是在什麼延遲門檻、多少請求量之下撐得住，讀者拿它去做容量決定時缺的正是那兩個數字。所以系統負載的足夠性斷言同樣要寫出負載量、判斷標準與瓶頸機制。結構上的實際連接仍然合規（「route table 掛在 subnet 上」描述的是設定裡的關聯，不是足夠性斷言）。

**Instance 4（範疇錯配）**：原句「那幾條建議的前提在讀者這裡不存在」與四頁共用的「它預設的環境在讀者這裡存不存在」。兩個問題疊在一起：前提是命題、命題的屬性是適用範圍而不是存在與否；「在～這裡」的處所框架需要地點，讀者是人。修正各自回到屬性相符的謂語：「這些建議的前提不適用於一般讀者」「讀者具不具備它預設的環境」。這一組的來源可以指認——上游的權威定義寫的是「在採用它的那個**組織**裡存不存在」，組織是容器、環境在組織裡存在文法成立；把組織代換成讀者的那一步沒有跟著換謂語，錯配是代換的殘留。

四個 instance 的共同機制：作者走完思考、要下一個謂語時，抓了語感上最順的那個詞（沒說完的話、很直接、撐得住、在讀者這裡），而沒有回頭問它是否真的描述了主語的屬性。順口的搭配在同源自審裡讀起來完全自然——因為作者跟 agent reviewer 共享同一套語感慣性，這正是它需要異源冷讀的原因（見 #165）。物理化錯配是四者裡唯一有一組高密度關鍵詞可掃的（撐／扛／掛／垮／頂），所以它可以進 grep bank；另外三種不行。但那組清單是抽樣、不是這一類的全部——違規義項只佔該詞用法少數的（滑坡、拿）漏在清單外，判斷標準與清單的分工見 [#267](../keyword-list-needs-dominant-violating-sense/)。

## 跟其他原則的關係

[#296 同一個 session 派出的 reviewer 共用它的盲區](/report/review-scale-does-not-buy-independent-origin/) 處理的是本卡的判定由誰執行。本卡給出四種錯配的辨識方式，而那張卡的兩處實例都落在這裡描述的類型裡，它要說的是同一套辨識方式在自己的文字上與在別人的文字上會得到不同結果——尤其在標題、小節標題、description 這些作者濃縮過的位置，作者重讀時取回的是自己的意圖而不是字面。

| [#285 連貫靠句句推進](/report/coherence-by-advancing-not-recapping/)                                                      | 限定本卡的譬喻適用邊界：本卡問譬喻**配得對不對**（謂語貼不貼合概念的屬性），#285 問**這個位置該不該有譬喻**（概念在領域裡已經有現成術語了嗎）。一個譬喻可以在本卡的判斷標準下完全合格，而它佔的位置早就有名字——只讀本卡的人拿到的是半張譬喻規則           |
| [#375 物理動詞佔住的內容](/report/physical-verbs-stand-in-for-content/)                                                   | 下游。本卡的物理條件問法找出候選、修法只寫到「撐」；#375 把「先判斷它佔住哪一格」推到清單裡每一個動詞，補上失效結果（拖垮、壓垮）、負擔（硬扛）、可信度（站得住）各自要寫出的內容，以及負載情境裡容量、過載、故障擴散、突發緩衝與耗盡時間的對照與分類腳本 |
| [#374 「問題」與「回答」當框架詞](/report/question-answer-frame-blurs-problem-issue-request/)                             | 同一類詞的另一個成員——「問題」與足夠性斷言裡的「撐」都佔著內容的位置而沒有填進去：一個沒說是問句、故障還是需求，一個沒說需求與判斷標準。修法相同，寫出它佔住的那個內容，換成同義詞不算修好                                                                |
| [#387 結構譬喻頂替主詞與動詞](/report/structural-metaphor-replaces-actor-and-verb/)                                       | 同一類錯配在內容集合組織詞上的形態——「這本書承擔的角色是」是本卡的擬人化（書不具備承擔角色的主體條件），而「這條線」「各接一個面」「走 [某篇]」是組織者的結構地圖寫進了正文；那張卡給這組詞的 pattern 與合規邊界，主詞是物的「承擔」兩邊都適用            |
| [#289 一個詞是不是通用術語，用多份獨立定義的收斂度量](../term-probe-measures-register-not-invention/)                     | 補本卡的偵測層。本卡給的是判斷標準（問這個動詞照字面成立需要什麼物理條件），而判斷標準要先有人把某個詞列成候選才會被套用——作者對自己寫過幾百次的詞列不出候選。「站得住」97 處存活多年，靠探針才現形                                                       |

[#299 文章寫題目本身，不寫作者怎麼認識它](../article-writes-the-topic-not-the-authors-path-to-it/) 處理同一批詞（撐得住、站得住）的更前面一步——多數時候可信度這句話根本不必寫。兩條規則互補而不互相取代：那張卡減少這類句子的數量，本卡管住留下來的那些。留下來的並不罕見——文章的題目本身就是證據品質或查證方法時，非寫可信度不可，而那裡動詞仍然要貼合屬性。順序是先問這句話該不該寫，決定要寫之後才輪到本卡。
