## 論述基礎與限制

本卡基於一次多輪審查中、兩處中文搭配問題由人類冷讀 catch 的事故。背景：一批退場決策文章，agent reviewer 跑完 register / cadence / 冷讀多輪都沒抓到兩處「順口但語義錯位」的搭配——「綜合評估那句『勞動報酬而非資本報酬』背後沒說完的話」（把一個分析角度擬人化成會說話的主體）、「判讀訊號很直接」（用「直接」形容訊號的可辨識度）。兩處都由作者以外的人類當場指出。第三種錯配（物理化）由後續一次書單審查補上，成因相同而規模大得多：使用者在十二個 agent reviewer 跑完三輪之後指出「撐得住」這個寫法，全站掃描命中三百多處。限制：case 是中文寫作，但原則（描述抽象概念要選屬性相符的謂語）跨語言成立；且它是 register 類問題、agent 同源自審對它有結構盲區（見 #165）——物理化那一種是例外，它有穩定關鍵詞、可以進自動掃描的候選層。

## 核心原則

**描述抽象概念時，選跟該概念真實屬性相符的動詞與形容詞，不套用習慣上順口、但語義錯位的搭配。** 抽象概念（分析角度、框架、訊號、指標）沒有人的行為屬性、也沒有具體物的物理屬性——給它配上不相符的謂語，句子讀起來順、但語義是錯的。判別方法只有一個問題：這個謂語真的描述了這個名詞的屬性嗎，還是只是順口。順口是語感慣性、不是語義正確。

三種常見錯配：

- **擬人化錯配**：把分析角度或框架當成會說話、有意圖的主體——「這個角度沒說完的話」「數字想告訴我們」「框架背後的潛台詞」。角度不會說話；它的屬性是涵蓋範圍，精確的說法是「這個角度沒有涵蓋／沒有提到的問題」。
- **形容詞錯配**：用一個習慣性但屬性不符的形容詞——「訊號很直接」。「直接」描述的是方式或態度（直接說、直接處理），不是訊號的可辨識度；訊號的可辨識度屬性用「清晰／明確／明顯」。
- **物理化錯配**：給抽象概念配上承重、支撐、懸掛類的動詞——「這個證據撐不撐得住」「論證掛在哪個前提上」「這套說法會垮」。證據跟結論之間沒有重量、沒有支點、沒有材料強度，那些動詞不帶進任何資訊，只是把讀者對物理世界的直覺借過來蓋住「這裡實際上是什麼關係」。精確的說法各自不同：證據**支持**結論、論證**依賴**前提、方法**適用於**某處境、責任由某人**負責**。

物理化錯配有一個可以機械執行的判準：**問這個動詞如果照字面成立，需要什麼物理條件**。需要重量、支點、材料強度、上下方位的，就是借來的——抽象概念不具備那些屬性。「撐得住」需要一個承受力量的結構，「掛在」需要一個掛點，「垮」需要一個會倒塌的體積；證據、論證、判準都沒有。

例外是**明示並就地展開的類比**：把它寫成類比、而且在同一段裡把物理意象逐項對應回真實機制（「團隊認知負荷有上限，因此邊界是承重結構而非官僚產物」——上限對應承重、超過會塌對應交付失效），那不是隨手借詞，是刻意建立的模型。判準是那個物理意象有沒有被展開成可以逐項檢查的對應關係；沒有展開的就是借詞。

## 反模式：順口的搭配蓋過語義的正確

**Instance 1（擬人化）**：原句「這正是綜合評估那句『勞動報酬而非資本報酬』背後沒說完的話」。「勞動報酬而非資本報酬」是一個判讀角度，被寫成「說了一半、還有話沒說完」的說話者。角度沒有「說」或「沒說完」這個行為屬性，它的屬性是「涵蓋了什麼、漏掉了什麼」。修正：「綜合評估用『勞動報酬而非資本報酬』這個角度時沒有提到的問題」。

**Instance 2（形容詞錯配）**：原句「判讀訊號很直接：如果……」。訊號的屬性是可辨識度（清不清楚、明不明顯），不是「直不直接」——「直接」形容的是行為的迂迴程度。修正：改用「訊號很明確」，或直接陳述訊號本身、拿掉這個評價性套語。

**Instance 3（物理化）**：原句「取證據來源撐得住『被拿去支持實際決定』這個用途的那本」「這本書的結論能撐多重的決定」。書的結論沒有重量，這裡實際發生的關係是「這個結論可以支持多大範圍的主張」——換成「支持」之後，句子還多回答了一件原句迴避掉的事：支持什麼、支持到什麼範圍。**借來的物理動詞不只是不精確，它還讓作者不必回答那個問題**，因為「撐得住」聽起來已經像個答案。這是它跟前兩種錯配的差別：擬人化與形容詞錯配是說錯了，物理化錯配是繞過了。

替換對照（左邊是借詞、右邊是該關係本身的動詞）：

| 借來的物理動詞     | 實際的關係               | 改寫                 |
| ------------------ | ------------------------ | -------------------- |
| 證據撐得住／撐不起 | 證據與結論之間是支持關係 | 足以支持／不足以支持 |
| 論證掛在某前提上   | 論證與前提之間是依賴關係 | 依賴／取決於         |
| 這套說法會垮       | 論證不成立               | 不成立／推不下去     |
| 資料支撐           | 資料為結論提供佐證       | 佐證／支持           |
| 某人扛某個責任     | 責任歸屬                 | 負責                 |
| 方法撐不久         | 方法無法持續執行         | 維持不久／執行不下去 |

三個 instance 的共同機制：作者走完思考、要下一個謂語時，抓了語感上最順的那個詞（沒說完的話、很直接、撐得住），而沒有回頭問它是否真的描述了主語的屬性。順口的搭配在同源自審裡讀起來完全自然——因為作者跟 agent reviewer 共享同一套語感慣性，這正是它需要異源冷讀的原因（見 #165）。物理化錯配是三者裡唯一有穩定關鍵詞可掃的（撐／扛／掛／垮／頂），所以它可以進 grep bank；另外兩種不行。
