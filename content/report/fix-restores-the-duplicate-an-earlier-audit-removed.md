## 論述基礎與限制

本卡從一批 skill 的多輪審查抽出，那一批跟 [規則替執行者預測平台或元件內部的行為時，個案實跑每一輪都從原始碼找到下一個分支](/report/rule-predicting-platform-internals-grows-a-branch-per-round/) 是同一批。兩支 skill 都寫到「共用層」：一支是元件契約的行動 APP 筆記，在〈驗收的證據〉定義什麼算共用層、改了它之後哪些截圖要重拍；另一支是截圖驗證的流程，在「改程式碼之後熱重啟」那一步要執行者判斷這次的改動是不是共用層。

那一批審查跑了三個版本：原版、原版去重之後重寫的重寫版、拿掉實測配置以外內容的縮減版。共用層這一處的經過依序是：

1. 原版的 Round 3 之後，設計稽核判定「同一條規則在兩份檔裡各有一份完整寫法」成立：共用層的定義與重拍範圍兩份檔各寫一份。處置是只留元件契約那一份，截圖流程改成一句話加連結。
2. 縮減版的 Round 1，寫作與一致性審查指出截圖流程又寫了一份重拍範圍，而且漏了面板與對話框（必修），修法照舊改回只指向元件契約。
3. 同一個版本的 Round 2，冷讀審查指出截圖流程從頭到尾沒有定義「共用層」，執行者在那一步要離開這支 skill 才判得了（必修），建議「就地寫一句定義」。整合時寫進去的是定義加上兩種判定各自的重拍範圍，又成了一份完整寫法。
4. Round 3 的反例審查指出兩份全文會一起漂移（Round 3 另一則必修要同時改兩處）。設計稽核這一批的結構事實累計第三次成立，其中一項正是第一次去重的那一處，審查停下來交給使用者。

兩則冷讀與一致性的必修都是對的：讀者確實要在那一步知道共用層是什麼，兩份全文也確實會分歧。錯在整合 Round 2 的那一步沒有查這個位置先前的稽核決定，把「寫一句定義」做成了「寫一份全文」。證據只有這一批的這一處；其他規則批次有沒有同樣的經過，沒有回頭查過。

## 核心原則

**稽核的結構決定沒有寫在稿件裡，下一輪的 reviewer 看不到它。** 去重之後，稿件上只剩一句話加連結；為什麼只剩一句、哪一份是權威，寫在稽核的紀錄裡。冷讀 reviewer 只拿到稿件，看到的是「這一步要用的概念沒有定義」，照它的 frame 要求就地定義是對的。決定被推翻，發生在整合的那一步：整合的人手上有稽核紀錄，卻只對照 finding 的建議修法，沒有回頭查這個位置。

**「就地定義」與「只寫在一處」可以同時滿足，條件是把定義與規則分開。** 冷讀要的是執行者在那一步讀得懂這個詞：一句定義（共用層是兩個以上的畫面都用到的設定或元件）就夠。住址的規則管的是那條規則的完整寫法：判定的範圍、例外、重拍到哪裡。定義寫在使用的位置、規則只留在住址，兩邊的要求都成立；把範圍也抄進來，才成了第二份完整寫法。站上的住址規則本來就允許「一處完整、別處一句話加連結」，這一句話寫的就是定義。

**同一個位置被修過一次，第二次的修法更容易推翻第一次。** 第二次修的人看到的 finding 跟第一次的方向相反（一次要求刪、一次要求補），而兩則附的理由都成立。只看當輪的 finding，兩次修法各自正確，合起來回到了第一次修之前的狀態。

## 反模式

- **冷讀要求就地定義，就把住址的整段規則抄進來**：讀者在那一步只需要知道詞的意思，抄進來的範圍與例外成了第二份，下一次改規則時只改到一份。
- **整合 finding 時只看建議的修法，不看這個位置的稽核紀錄**：先前去重、搬移或刪除的決定在稿件上沒有痕跡，修法照建議做就把它推翻了。
- **把「這一步讀不懂」與「這條規則要有兩份」當成同一件事**：這一步讀不懂，用一句定義解決；規則要有兩份，是住址錯了。

## 修法

1. **整合每一則 finding 之前，查它指向的位置在這一批的稽核紀錄裡有沒有結構決定**：去重（只留一份、別處連過去）、搬移、拆檔、刪除。有的話，修法不能推翻那個決定；finding 的要求跟它衝突時，找一個兩邊都成立的寫法，寫不出來就把衝突交給派審查的人決定。
2. **冷讀要求就地定義一個在別處有完整寫法的概念時**，在使用的位置寫一句定義，後面接連結指到住址：「改到的是不是共用層（兩個以上的畫面都用到的設定或元件），照〈驗收的證據〉判斷」。判定的範圍、例外與處置不抄過來。
3. **設計稽核查到同一條規則又有兩份完整寫法時**，先查第二份是哪一輪的修法加的、那一輪的 finding 要的是什麼，再決定留哪一份；只看現狀去重，下一輪的冷讀會再要求一次。
4. **把結構決定寫成下一輪 reviewer 讀得到的形式**：住址那一份的檔頭或那一節寫明「本節是權威，別處只寫定義與連結」，冷讀 reviewer 拿到稿件時就看得到這個決定。

## 判讀徵兆

| 徵兆                                                                 | 判讀                                                                      |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 設計稽核判定結構事實成立，位置跟先前某一次稽核處置過的位置相同       | 中間某一輪的修法把那一次的處置推翻了，先查是哪一輪                        |
| 一份檔先被要求刪掉某段規則、後一輪又被要求補上它的定義               | 兩則 finding 的要求不同：一個要住址、一個要定義；用一句定義加連結同時滿足 |
| 冷讀的必修寫「這一步要離頁才讀得懂某個詞」，而那個詞在另一份檔有整節 | 修法寫一句定義，不抄那一節                                                |
| 修法建議寫「就地寫出 X 的定義與範圍」                                | 範圍是規則，不是定義；只寫定義的那一句                                    |
