教材逐段審查要回答的問題是：**讀者讀完這一段，能不能確實理解、並正確地用到自己手上的問題。** 一份審查會放過大量阻礙學習的段落，有兩個互相獨立的成因。第一個在量尺：嚴重度量的是「讀者拿不拿得到字面資訊」，於是讀者要回頭翻才解得開的指稱、以及只對一部分情形成立的解法，都落在中低收益而被放過。第二個在審查者自己：他讀過全文，手上有作者的那張地圖，所以「上面那一組對照」「兩者」「第三個 `JOIN`」在他讀來全部解得開。換掉量尺能修第一個成因，第二個要換一個手上沒有地圖的讀者。

## 失效的形態

**宣稱比解法寬。** 一段把平均、中位數、百分位歸成「不可加的」一類，給的解法是把 `sum` 與 `count` 分開帶出來再相除。這個解法只對平均成立，讀者照著算中位數會得到錯的數字。這一段讀起來通順、每個字都拿得到，舊量尺把它放在措辭層級。

**概念在定義之前被使用。** 一段寫「它決定的是哪一側的列被保護」，而外連接保留某一側全部列的機制，這一篇到那個位置還沒講過。字面上讀者拿得到「保護」這個詞，拿不到它指什麼。

**指稱的對象隔了好幾段。** 「上面那一組對照在真實系統上有它的故障形態」，對照在兩節之前；「那句可驗收的話管住了缺測」，那句話在三整節之前；「這一點是前面那個 `PRAGMA` 的直接後果」，那個 `PRAGMA` 隔了兩個大節。每一句單獨看都是完整的中文。

**計數與成員對不上。** 「全文的範例只有兩個 `JOIN`，這裡寫第三個 `JOIN`」；一段摘要先列三種寫法、再寫「量四種寫法的時間」；一節標題寫「三家給兩種答案」，下面的表格有四家引擎。

## 為什麼審查放行

**量尺量的是有沒有缺資訊。** 第一版量尺把嚴重度定成高、中、低，並附兩條回報門檻：「寧可少報，不要湊數」「措辭偏好不回報」。這兩條讓審查者判斷的是「這一段有沒有缺資訊」，而上面四種形態都不缺資訊：宣稱過寬的那一段資訊比需要的多，指稱的對象就在文章裡，計數錯的地方成員都寫在別處。它們缺的是讀者學會的條件。審查者照量尺判成中低，再照門檻不報。

**審查者用全文地圖解指稱。** 逐段審查的審查者先讀完全文，再一段一段判。他讀到「上面那一組對照」時，那組對照已經在他的工作記憶裡，解開它不花任何力氣，所以他不會停下來；他判一句過渡句，看的是它在全文結構裡承擔什麼功能，而不是它在讀者手上解不解得開。作者與同源審查者都持有這張地圖，偵測率在這一類上接近零。這跟 [#363](/report/ordinal-labels-are-the-authors-index/) 的成因相同：「第一支」「第三步」對持有清單的人永遠解得開。

## 修法

嚴重度按學習影響分兩級，取消少報門檻：

- **必修**，符合任一項：讀者照這一段去做會學錯、做錯（逐一代入它宣稱涵蓋的每個成員檢查）；讀者在這一段裡理解不了、舉不出一個自己手上的例子；讀者必須離開這一頁或回頭翻才讀得懂（名字只是代號、指路代替內容、計數代替成員、用到本篇還沒教的概念、指稱的對象隔一段以上而句子沒寫出它是什麼）；作者的編排脈絡寫進了正文。
- **可改**：讀者拿得到內容、不會學錯，但要多花力氣（一句塞了三個新概念、段首的「兩者」要回看上一段才確定）。
- 拿不準時判可改並寫出理由。「寧可少報」「措辭偏好不回報」兩條刪掉。

**指稱另派一種手上沒有地圖的讀者。** 把文章切成編號段落，派多份低階模型，指令逐字相同：把每一段當成讀者從搜尋直接落進這一段、沒讀過其他段，列出解不開的指稱詞語與有兩種以上讀法的位置。這種讀者手上沒有地圖，所以不會替作者補完。探針會大量誤報（同一段就解得開的詞也會被列出），所以回報要經過一道篩選：對照全文，逐條判定對象在不在同一段或緊鄰的前一段、有沒有歧義、是不是全篇共用的範例資料。篩選者給出的替換文字要逐字取原文片段，套用前用腳本確認每個片段在現行檔案裡恰好出現一次。

**篩選的判定也要回原文核對。** 篩選者同樣持有全文，他會把「兩種寫法的分岔」判成計數錯（前後文都在講三種錯法），而那一句實指正解與錯法兩邊，計數是對的。所以主 session 要抽查它的判定再套用。

## 論述基礎與限制

證據來自同一天對一個 24 篇 SQL 教材分類的連續三次處理：

- 第一版量尺，4 位審查者、約 550 段：回報 9 處，加上主 session 抽看 2 處，共改 10 處。
- 換成學習影響量尺、同一組審查者分組重審：必修 6、可改 18，其中包括宣稱過寬的 1.18（`MATCH FULL` 只在 PostgreSQL 生效，docker 實測）與 NOT IN 遇 NULL 的描述。同一輪主 session 抽查 1.2，自己找到 3 處隔段指稱（「上一種」「前一種」「最麻煩的一種」），審查者回報 0 處。
- 讀者探針，21 篇各 3 份：合併起來抓到 1.2 那 3 處；兩篇在重審中全數通過的文章各抓到 2 處以上指稱問題，其中一處只有一份探針回報，回原文核對成立。全分類 378 段至少被一份標記，篩選後套用 41 處，另外 3 處是抽查篩選結果時順帶發現的序數名字。

限制有三條。這是單一分類、單一生成端、單一天的觀測，量到的是這批稿件上的偵測差距，不是比例。探針的標記精確度低：378 段標記最後只產出四十幾處修改，篩選這一步的成本不能省。單份標記也可能是真的，所以篩選不能用收斂份數當門檻。

## 跟其他抽象層原則的關係

- [#281 理解檢查用低階 model 取樣讀者的實際理解](/report/comprehension-sampled-not-judged/)——那一張建立探針的五個設計條件與「一份讀錯就是判決」；本卡把它用在指稱這個審查者結構上看不見的類別，並補上探針在逐段落地模式下誤報很多、需要一道對照全文的篩選。
- [#270 敘事的解碼材料要在讀者已讀的文本裡](/report/decodable-from-text-already-read/)——那一張是寫作端的規則（解碼材料不能只在作者的地圖裡）；本卡是審查端的對應：審查者也有那張地圖，所以違反那條規則的句子在他手上不會現形。
- [#363 正文裡的對象要用它是什麼來命名](/report/ordinal-labels-are-the-authors-index/)——同一個成因的另一個位置：序數名字對持有清單的人永遠解得開。本卡的指稱不一定是序數，「上面那一組對照」「那句可驗收的話」一樣靠地圖解開。
- [#194 多輪審查缺 outside-in 讀者 frame](/report/review-lacks-outside-in-reader-frames/)——那一張列出審查缺少外部讀者視角的盲點；本卡量到其中一個的具體偵測差距，並給出落點讀者這個可派發的形態。
- [#202 多輪審查至少三輪是硬底線](/report/multi-round-review-minimum-three-rounds/)——輪數解決不了這一類：每一輪的審查者都持有地圖，加輪數加的是同一種讀者。

## 判讀徵兆

- 審查回報集中在內容錯誤與明顯的格式問題，指稱與過渡幾乎沒有，而文章有很多「上面」「兩者」「那一組」。
- 審查者的 prompt 裡有「寧可少報」「措辭偏好不回報」或以高、中、低分級而沒有定義各級對讀者的影響。
- 重審換了量尺之後，同一批稿件回報的數量翻倍——代表舊量尺的門檻在過濾，不是稿件乾淨。

## Case

2026-09-24，SQL 教材分類。使用者看過一輪依範例改寫的段落之後，要求重審全分類，並指出「為什麼有中低收益段落會被放過」值得檢討，目標是教學文章讓讀者確實理解並學會相關知識與操作。重審揭露了量尺的問題；主 session 抽查 1.2 時發現審查者對隔段指稱回報為零，才加派讀者探針。
