## 論述基礎與限制

證據來自同一個內容庫的兩次獨立審查。

第一次是一篇 work-log 的三輪審查：寫作動機是記錄一個平台機制與對應寫法，三輪九個 reviewer 產出五十餘項 finding，修完之後由作者指出整篇已經變成查證報告，最重的一節（一個異常現象的假說排查）與讀者的問題無關、整節刪除。

第二次是一個教學模組的五輪審查（四章、七張知識卡、一則案例、兩張原則卡，共十七個 reviewer）。第五輪特別派了只問刪除的 frame——明令不准提還可以補什麼，只問每一段憑什麼佔這個位置——結論是可刪近三成而不損失任何一條可執行判準。兩次都出現同一個現象：被判該刪的往往是審查投入最多的地方。

限制：兩次都在同一個內容庫、同一套寫作規範下，跨團隊未驗證；「近三成」是單次量測，不是可預期的比例；「哪一輪排這個 frame 最有效」仍無資料，本卡主張的是它必須存在，不是它的最佳位置。

## 核心原則

多輪審查的每個 frame 都在回答「這篇寫得好不好」，沒有一個在回答「這篇該不該有這一節」。事實查核要求補證據、冷讀要求補脈絡、steelman 要求補排除的假說、個案實跑要求補涵蓋不到的情形——每一項單獨看都是正確的改進，而它們的方向一致：往裡面加。

累積的結果是文章離開它原本要解決的問題。審查因此需要一輪的問題換成：**這篇要讓讀者知道的是什麼，現在它還是在講那件事嗎。**

這一輪的操作是把寫作動機寫成一句話，逐節問「刪掉這一節，那個動機還達得成嗎」。達得成的節就是候選。判定不看那一節寫得好不好——被刪掉的往往是全篇最紮實的部分，因為它是審查投入最多的地方。

## 這一輪會找到三類東西

| 類別                 | 形態                                                                                     | 為什麼逐輪審查看不到                                                                         |
| -------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 離開動機的內容       | 正確、紮實、而與讀者帶來的問題無關                                                       | 每一輪的 frame 都在問寫得好不好，沒有一輪問該不該有                                          |
| 跨 surface 複寫      | 同一件事在知識卡、章節、案例、原則卡各說一次，每一份單看都完整                           | 四份各自被單獨審過，沒有任何一輪一次攤開四份——這是空間上的分散，跟時間上的分次是兩條不同的軸 |
| 同一個意見被回應多次 | 前後輪的 reviewer 報了同一個缺口，作者在不同位置各補一次，兩份互不指涉、規則還可能不一致 | 新一輪的 reviewer 不知道前一輪的修法已經蓋掉什麼                                             |

第二類在教學模組那次佔可刪份量的六成，是三類裡最大的一塊。第三類的實例是同一條要求長出四層：兩輪 reviewer 各報一次同一個缺口，作者一次補在章節、一次補在模組入口，而兩處的規則不一致（一處要求配對檢查點、一處要求留下記錄列），讀者無從判斷兩件都要做還是擇一。

## 為什麼審查抓不到

**Reviewer 不知道目的。** 派工的 prompt 通常寫審查維度與輸出格式，不寫這篇的讀者是誰、帶著什麼問題來。上述實例的九個 reviewer 沒有一個問過這件事，於是九個都在優化一篇查證報告的嚴謹度。

**加東西有 finding、刪東西沒有。** Reviewer 的產出單位是 finding，而「這一節不該存在」需要先知道目的才提得出來。缺少目的的情況下，最省力也最安全的產出是指出可以再補什麼。

**膨脹是分次發生的。** 每一輪加的量都不足以構成問題，只有把初稿與定稿並排才看得出偏移。逐輪檢查的視角看不到累積量。

**審查會製造要被審查的東西。** 輪次越後面，finding 的來源越是前幾輪的修法而非原始內容——傳播不完整、插入的句子切斷原本的段落、免責被下一句抵銷。這代表再跑一輪的邊際效益不會遞減到零，但多出來的部分不是內容變好，是修法在製造新的債。

## 修法

派工時把「這篇要讓讀者知道什麼」寫進每個 reviewer 的 prompt，讓維度以外的判斷有依據。事實層與正確性修完之後，排一輪專門的 frame，問三件事：

- 概念與要素會不會太多——讀者要同時記住幾件事才讀得完
- 主題有沒有發散——目前的段落有幾個不同的主題，它們是不是同一個問題的不同面
- 想讓讀者知道的是什麼——用一句話寫下來，再逐節對照

順序不能顛倒。先確保寫的是對的，再確保寫的是需要的；反過來會刪掉還沒被驗證的內容。

跨 surface 的檢查要一次攤開所有份數並排看。逐份審查看不到複寫——每一份單看都完整，那正是它通過前面每一輪的原因。

不再投資新輪次之後，改跑一次機械化的傳播檢查：把每個承重宣稱做成 grep pattern 掃全站，確認所有出現的位置說的是同一件事。成本是幾分鐘，而它針對的正是唯一還在累積的那一類——前幾輪修法留下的不一致。教學模組那次用這個方法在停止審查之後又抓到兩處。

## 沒這樣做的麻煩

發散的文章對帶著問題來的讀者最不友善：他要在正確但不相關的內容裡找到自己那一段。而審查投入越多，這個問題越嚴重——每一輪都讓文章更嚴謹、也更遠離讀者的問題。

代價還有一層在流程上。刪掉的那一節通常是審查投入最多的部分（排查、反證、逐條驗證），發現得越晚、丟掉的工作越多。

## 判讀徵兆

| 徵兆                                                             | 判定                                               |
| ---------------------------------------------------------------- | -------------------------------------------------- |
| 文章長度每輪增加，而讀者要解決的問題從第一版就沒變               | 加的內容多半服務的是審查而非讀者                   |
| 某一節的存在理由說得出「這是查證的一部分」而說不出讀者用它做什麼 | 該節是過程的副產品                                 |
| 段標列出來之後，有兩組以上互不從屬的主題                         | 主題發散，先問哪一組屬於原本的動機                 |
| Reviewer 的 finding 全部是「可以再補什麼」                       | 沒有任何 frame 在問該不該有，補這一輪              |
| 作者要用超過一句話才說得出這篇在解決什麼問題                     | 動機本身已經漂移，先收斂動機再談內容               |
| 同一條要求在兩個以上的 surface 各有一份、彼此不指涉              | 跨 surface 複寫，攤開所有份數並排比對規則一不一致  |
| 掃「套用在自己身上」「自己也是」這類自指句、命中兩處以上         | 檢查它們回應的是不是同一條原則、以及規則一不一致   |
| 後面幾輪的 finding 多數指向前幾輪的修法而非原始內容              | 審查在追自己的尾巴，改跑機械化傳播檢查而非再開一輪 |

## 這條原則什麼時候不成立

單一目的明確的短文不需要專門一輪：段落數少到可以一眼看完時，發散在寫的當下就會被發現。

參考型內容（規格表、API 文件、術語表）也不適用——它們的完整度本身就是目的，「涵蓋更多」不構成發散。這一輪針對的是有明確讀者問題的文體：教學、檢討、工作紀錄。
