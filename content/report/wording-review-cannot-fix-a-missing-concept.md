## 論述基礎與限制

本卡從一次全站換詞抽出：把從英文 mechanical 直譯的「機械」（機械檢查、可機械執行、沒有機械的答案）照原句的意思改寫，涵蓋 175 個檔、約四百行，跑了三輪審查。Round 1 的 reviewer 指出「照規則就判得出的答案」寫在談規則的句子裡時，同一句有兩個「規則」，建議統一成「沒有固定的答案」，照做了。Round 3 的 reviewer 拿誤用的方式實跑一句分流的規則：「問它有沒有固定的答案；有的話照條件寫，沒有的話寫成留意項」。最省力的執行者把「固定的答案」讀成「有標準答案」，而幾乎每個判斷都答得出一個對的答案，於是一律照條件寫，正好是那條規則要防的失敗。reviewer 建議改回「照規則就判得出的答案」，並補一句定義：兩個執行者拿同一條規則、同一份輸入，會得到同一個判定。同一句在兩輪之間被要求換兩次詞，兩次的理由都成立。

使用者在這時指出：這一批審的是寫作問題，而這一則本質上是內容的問題，審查寫作的時候不應該去修內容；停點除了退回與繼續，還要檢討原文的內容是否不足、是否拆出另一個題目深入討論。使用者也提到另一批審查在同一類停點被問過兩次，第一次選了退回原始範圍，第二次選了照 finding 修下去，兩次都沒有處理根本的問題；那一批的經過不在本卡的材料裡。

限制：證據是一批換詞審查裡的一則必修與它的同類（同一個概念在七處的說法），加上使用者對另一批的描述。「修法要補原文沒有的內容」這個判別沒有在其他批次量過。

## 核心原則

**一批審查有它的範圍；修法要補原文沒有的內容時，那一則不在這一批的範圍內。** 換詞、改句子的審查，修法是在既有的句子裡換一個說法，原文的論證、定義與概念不動。一則 finding 的修法要在句子裡加一句定義、補一個名字或補一段推導時，它要的是原文沒有的內容，缺陷在內容那一層。這一批的「機械」在本 repo 承載一個概念：兩個執行者拿同一條規則、同一份輸入，會得到同一個判定。這個概念從來沒有被命名、在一處定義；原文寫「機械」時，讀者不必知道這個概念叫什麼。換詞之後，改寫的人要在每一處各選一個詞代替一個不存在的名字，選哪個詞，都會有句子被讀成另一個意思。

**在範圍內修範圍外的缺陷，修的人會在幾個詞之間來回換。** 每一輪的 reviewer 讀到的是缺陷在某一句上的投影（同句兩個「規則」、分流句的歧義），照它修完，缺陷在另一句上再投影一次。這是 [多輪審查不收斂時，先查一篇討論了幾個主題、同一個機制在幾處展開](/report/review-nonconvergence-points-to-outline/) 說的「大綱缺陷在句子上的投影」在換詞批次裡的形態：這裡缺的是一個概念的定義，大綱不必重排。

**停點只給退回與繼續時，兩個選項都留下根本的問題。** 退回是把範圍縮回去，缺的概念照樣缺；照 finding 修下去是在範圍內換詞，回到上一段的來回。第三個選項是把它當成內容的題目：寫出原文缺的是什麼（一個概念的名字與定義、一段推導、另一篇文章），寫出它的住址，拆成另一個題目做；這一批只修範圍內的寫作問題。規劃停點的人要主動列出這一項：退回與繼續決定的都是這一批要不要往下做，兩者都沒有問這一則該不該在這一批修。

## 反模式

- **把要補定義的修法當成換詞做**：在句子裡加括號定義，或換一個比較長的詞，讓一個沒有名字的概念在每一處各被描述一次。
- **同一段兩輪換兩種說法，仍然照 finding 修**：兩次的理由都成立，代表兩個詞都不是那個概念的名字。
- **停點只列退回與繼續**：使用者只能在兩個都不處理根本問題的選項裡選。
- **在範圍外的住址順手補內容**：概念的住址是規則或原則卡時，補上定義是規則級的改動，要有自己的審查。

## 修法

1. **整合每一則 finding 時，問它的修法要不要補原文沒有的內容**（定義、名字、推導、新的段落）。要的話標成內容題目，不在這一批修。
2. **同一段在兩輪裡被改成不同的說法時，問那幾個說法在代替什麼**：說得出它們共同指的那個東西、而原文沒有替它命名時，是內容題目。
3. **內容題目寫出三件事**：缺的是什麼、它的住址（哪一張卡、哪一節規則、要不要另寫一篇）、這一批留下的哪幾處要在那個題目做完之後改成引用它。寫進 commit message 與給使用者的總結；有模組結構的，另外記進那個模組的 Backlog。
4. **停點交給使用者的選項列三項**：退回、照 finding 修下去、拆成內容題目；標出哪幾則 finding 屬於內容題目。
5. **這一批只修寫作問題**：句子自己寫錯、寫過頭、跟同批的說法不一致的，照常修。

## 判讀徵兆

| 徵兆                                                             | 判讀                                       |
| ---------------------------------------------------------------- | ------------------------------------------ |
| reviewer 的建議修法是「改成 X，並補一句定義：……」                | 定義是原文沒有的內容；這一則可能是內容題目 |
| 同一段在 Round 1 與 Round 3 被要求換成兩種說法，兩次的理由都成立 | 兩個詞都在代替一個沒有名字的東西           |
| 一個舊詞換掉之後，同一個意思在各檔分成五種以上的說法             | 舊詞承載的是一個概念，不只是一個修飾語     |
| 停點的選項只有「退回」與「繼續」                                 | 少了「拆成內容題目」                       |
| 使用者在停點選過一次之後，同一類停點又出現                       | 前一次的選項沒有處理根本的問題             |

## 跟其他抽象層原則的關係

- [多輪審查不收斂時，先查一篇討論了幾個主題、同一個機制在幾處展開](/report/review-nonconvergence-points-to-outline/)：最接近的既有卡。那張卡處理文章的大綱與規則的結構讓句子層的修法不收斂；本卡補的是換詞批次裡的同一個形態：缺的是一個概念的定義，處置是拆成內容題目，停點要列出這個選項。
- [規則的審查走到設計稽核的停點時，先反省寫法、再反省對規則的理解、最後才簡化](/report/rule-nonconvergence-reflect-form-then-understanding/)：那張卡給停點的兩層反省，以及照 finding 修下去與重寫兩種走法；本卡在交給使用者的選項裡加一項：這一則 finding 不在這一批的範圍內。
- [從名字出發的術語檢查，抓不到被反覆使用而從未命名的概念](/report/concept-used-but-never-named/)：本卡的個案就是那一類概念，在換詞時現形：舊詞讓它不必命名，換詞的人要在每一處替它選一個名字。
- [切開一個集合之前先寫切分的依據，再替每一塊命名](/report/unnamed-halves-are-unextracted-variables/)：命名會逼出內容；本卡的處置是把命名當成另一個題目做，不在換詞的批次裡做。
- [宣稱照做不需要判斷的條文，要先把中文允許不決定的那幾項決定掉](/report/mechanical-rule-must-close-optional-grammar/)：那張卡寫出了這個概念的定義（兩個執行者得到同一個判定）；本卡個案的內容題目，是替它命名、在一處定義。
