## 論述基礎與限制

這張卡處理的寫法：一段操作說明要讀者改動某個設定，說明裡寫的是改之前看到的現象（「音量滑桿在最左邊時聽不到」）與改之後的結果（「往右拉就聽得到」），沒有寫出這個設定控制的是什麼、預設值是什麼、預設值是為了哪種使用情境。

這張卡來自 2026-11-12 家用音響 til〈用 iPad 與藍牙喇叭擴充 Mac 的聆聽配置〉的一句修改。那一節寫的是把「音訊MIDI設定」啟用的 iPad 輸入，用 QuickTime Player 的「新增音訊錄製」從 Mac 的喇叭播放。實測時，視窗打開後聽不到 iPad 的聲音，把視窗裡的音量滑桿往右拉之後才聽得到；初稿照實測的順序寫成「再把視窗裡的音量滑桿往右拉……；音量滑桿在最左邊時聽不到」。使用者指出這裡應該寫成：系統預設錄音時的播放音量是靜音，所以要讓 iPad 輸入的聲音從喇叭放出來，需要把滑桿往右拉。使用者也指出，寫功能說明時不只講操作的方法，重點是分析設計的理念或考慮的背景。改寫後的版本寫出滑桿控制的是「錄音時把輸入同步從喇叭播放的音量」、預設在最左邊（靜音）、錄音時只把輸入寫進檔案，以及預設靜音的效果：用麥克風錄音時，喇叭放出的聲音不會再被麥克風錄進去。

偵測量測：在 `content/`（排除 `report/` 與 `skills/` 鏡像）用 `(時|的話)，?(聽不到|看不到|沒有聲音|不會出現|沒有反應|不會生效)` 找「某個狀態時看不到結果」的句子，22 個檔各 1 行；依路徑排序取第 1、9、17 行讀，兩行是連結文字裡的「看不到哪些故障」，一行（`digital-streaming-source-guide.md` 的電視音訊格式）寫出了預設值（「自動」或 bitstream）與接收端只收 PCM 的理由，是這張卡要的寫法。這個形態沒有穩定的詞，偵測要逐一讀改動設定的步驟（〈修法〉的「找出改動設定的步驟」）。

限制：證據只有一個個案。預設靜音的效果是從機制推出來的；Apple 的設計理由沒有查到出處，所以改寫只寫效果，不寫成 Apple 的意圖。這張卡沒有量過讀者讀兩個版本時的實際理解。

## 核心原則

**一個設定的說明有三項內容：它控制的是什麼、預設值是什麼、預設值服務哪一種使用情境。** 操作步驟要讀者改動這個設定時，三項都寫出來，「為什麼這個用途要改它」就由這三項推得出來：滑桿控制的是錄音時同步播放的音量；預設在靜音，服務的是用麥克風錄音、不想讓喇叭的聲音被錄回去的情境；這次的用途是把輸入當成音源播放，跟預設服務的情境相反，所以要拉開。

**只寫現象與結果時，讀者拿到的是一次觀察，換一個情境就判斷不了。** 「在最左邊時聽不到，往右拉就聽得到」對照著做一次是夠的；讀者下一次用同一個視窗錄麥克風時，手上只有「往右拉才聽得到」這條經驗，判斷不出這一次該不該拉，拉了就把喇叭的聲音錄進去。寫出預設值服務的情境，讀者才知道自己的用途跟預設一不一致，在本篇沒寫到的情境也判斷得了。這跟〈判斷標準寫成條件、後果與理由〉要的是同一件事：一個設定的預設值本身就是一個判斷，作者寫出它的條件與理由，讀者才能把自己的情境對進去。

**照實測順序寫下來，就會寫成現象與結果。** 作者實測時的經過是打開視窗、聽不到、試著拉滑桿、聽到了；照這個順序寫，句子就停在觀察到的現象。設定的作用與預設值服務的情境不在這個經過裡，要另外去查、去推，所以初稿裡不會有。這跟〈文章寫題目本身，不寫作者怎麼認識它〉是同一類成因：文章照作者發現的順序組織，而讀者要的是題目本身的結構。

**設計的理由查不到出處時，寫效果，不寫意圖。** 「Apple 預設靜音是為了避免回授」是對設計者意圖的宣稱，需要出處；「預設靜音的效果是用麥克風錄音時，喇叭的聲音不會被錄進去」是從機制推得出、讀者可以自己驗證的事實。兩者給讀者的判斷材料相同：讀者知道預設值服務哪個情境就夠了，不需要知道設計者心裡怎麼想。官方文件寫了設計理由時，寫的人照文件寫並附出處。

## 反模式

- **只寫現象**：「音量滑桿在最左邊時聽不到。」讀者知道要拉，不知道滑桿控制什麼、什麼時候不該拉。
- **只寫結果**：「把滑桿往右拉，就聽得到 iPad 的聲音。」同上，而且讀者會以為滑桿是這個功能專用的開關。
- **把效果寫成設計者的意圖**：「Apple 為了避免回授，預設把它設成靜音。」沒有出處時，這是虛構的歸因。
- **寫了預設值、沒寫它服務的情境**：「這個滑桿預設是靜音。」讀者知道起點，仍然判斷不出自己的用途要不要改。

## 修法

1. **找出改動設定的步驟**：逐一讀操作說明裡要讀者打開、關閉、拉動、切換、改選某個設定的步驟。「某個狀態時看不到結果」這類句子是候選，但沒有穩定的詞可以掃，所以以步驟為單位讀。
2. **對每一個設定寫出三項**：它控制的是什麼（「錄音時把輸入同步從喇叭播放的音量」）、預設值是什麼（「最左邊，也就是靜音」）、預設值服務的情境（「錄音時只把輸入寫進檔案；用麥克風錄音時，喇叭的聲音不會被錄進去」）。
3. **接著寫這次的用途為什麼要改**：這次的用途跟預設服務的情境哪裡不同（「要讓 iPad 輸入的聲音從喇叭放出來」），所以要改成什麼值。現象（「拉之前聽不到」）可以留下，寫成驗證的訊號，不當成理由。
4. **預設值的理由分出處**：官方文件寫了，照寫並附出處；沒寫，寫效果並標明是從機制推出的；效果也推不出來時，寫「文件沒有說明這個預設值」，不替設計者補理由。

改寫的例子：

- 改前：「再把視窗裡的音量滑桿往右拉，不必按下錄音，iPad 的聲音就從 Mac 目前的聲音輸出播出；音量滑桿在最左邊時聽不到。」
- 改後：「錄音視窗裡的音量滑桿控制的是錄音時把輸入同步從喇叭播放的音量，視窗打開時它預設在最左邊，也就是靜音：錄音時只把輸入寫進檔案、不從喇叭播放。這個預設的效果是用麥克風錄音時，喇叭放出的聲音不會再被麥克風錄進去。所以要讓 iPad 輸入的聲音從喇叭放出來，要把音量滑桿往右拉；拉開之後不必按下錄音，iPad 的聲音就從 Mac 目前的聲音輸出播出。」

## 判讀徵兆

| 徵兆                                                                     | 判讀                                                                |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| 步驟寫「X 在某個狀態時看不到結果，改成另一個狀態就有」                   | 只交付一次觀察；補設定的作用、預設值與預設值服務的情境              |
| 步驟寫了預設值，沒寫預設值服務哪個情境                                   | 讀者知道起點，判斷不出自己的用途要不要改                            |
| 句子寫「為了……，所以預設……」，主詞是廠商或設計者，沒有附出處             | 把效果寫成意圖；改寫成效果，或補上出處                              |
| 讀者換一個本篇沒寫到的用途（同一個視窗錄麥克風），照本篇判斷不出該怎麼設 | 預設值服務的情境沒寫出來                                            |
| 說明照作者的實測經過排列（打開、沒反應、試著改、成功）                   | 文章照發現的順序組織；改成設定的作用 → 預設值 → 本次用途 → 改成什麼 |

## 跟其他抽象層原則的關係

- [判斷標準要寫到條件層：維度清單是判斷標準的空殼](/report/criteria-need-condition-action-mapping/)：最接近的既有卡。那張卡要求判斷標準寫出條件、後果與理由；這張卡把同一個要求用在設定的預設值上：預設值是設計者做好的一個判斷，說明要寫出它服務的條件，讀者才能拿自己的用途比對。
- [文章寫題目本身，不寫作者怎麼認識它、也不寫從它推出了什麼](/report/article-writes-the-topic-not-the-authors-path-to-it/)：同一類成因。那張卡處理文章寫進作者的認識過程；這張卡處理操作說明照作者的實測經過寫成「沒反應、改了、有了」，設定本身的作用沒有寫進去。
- [AI 生成的內容不虛構經驗與出處](/report/no-fabricated-experience-or-attribution/)：補預設值的理由時，查不到出處的設計意圖不寫；這張卡〈修法〉的「預設值的理由分出處」把那張卡的要求用在「設計理念」這一類句子上，改寫成可驗證的效果。
- [教鑑別能力、不教操作流程：知識目標決定文章結構](/report/teach-judgment-not-procedure/)：那張卡在文章層要求以機制理解為主線；這張卡在單一步驟的層次做同一件事，一個設定步驟也要交付讀者在別的情境用得上的判斷。
- [會誤解處補正向知識、不把誤會當敘事中心](/report/fill-knowledge-gap-not-center-misconception/)：「在最左邊時聽不到」是把讀者會遇到的現象當成說明的內容；那張卡的修法是補上讓誤會不發生的正向模型，這張卡補的正向模型就是設定的作用與預設值。
