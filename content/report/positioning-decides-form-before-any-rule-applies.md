## 論述基礎與限制

本卡從一次使用者對教學短文的體例修正抽出，事件在 2026-08-31。一篇解釋外語菜名的教學文被寫成了操作手冊：判讀段落標成第一層、第二層、第三層，後面接一則演示判錯代價的微案例。三輪審查加低階模型探針都沒有報它，因為每一條規則都被遵守了。

隨後跑了一次量測。同一個低階模型五個互不通訊的實例，讀同一份六段的檔案，指令逐字相同：每一段回答寫給誰看、讀完的第一個動作是什麼、預期讀者會照著做嗎、會放在手邊隨時翻還是讀過一次就好、以及讓你這樣判斷的是哪幾句。**五個問題沒有一個提到手冊或教學**——受測的是類型認知，問法不能點名類型。

六段裡兩段是控制項且不標示：一份十步驟的操作流程，一份概念解釋。控制項在「隨時翻」這一軸上完全分開（手冊五份全答放手邊、教學五份全答讀一次就好），測試項的判讀因此可歸因。探針引用的句子逐條回原文核對過，全部逐字存在，所以歸因落在文章而不在模型。

限制有兩項。**單一批次**：四個測試項來自同一個分類、同一個作者、同一天。**這個 repo 的 surface 只有三種**，surface 更多或邊界更模糊的專案裡，定位這一關要怎麼判沒有驗過。

## 核心原則

動筆之前先確定這份稿件的定位——**誰讀、讀完要做什麼**——因為語氣、文法與格式都由定位決定。

規範裡的每一條規則都誕生自某一個定位。共用一套規範的專案裡，那些規則會累積成一個池子，而池子不記得自己的來歷。**套規則之前沒有先過定位這一關的話，一條為 A 定位設計的規則會把 A 的體例搬到 B 上，而且每一步都合規。**

判別定位的軸不是「內容裡有沒有可執行的東西」——量測顯示教學控制項也給了可執行的內容（辨識訊號、可以改的東西），而五份探針仍然全部答讀一次就好。**分開兩邊的是那個動作落在哪裡：在世界上動手，還是在腦中重新歸類。** 教學控制項要讀者做的是用一個框架重新詮釋已經發生的事；被讀成手冊的那幾段要讀者去轉小火、按比例準備、在鍋蓋下夾兩根筷子。

## 三種定位，三種體例

同一套寫作規範在這個 repo 裡服務三個 surface，而它們對讀者的預設完全不同。

**Agent 指令**（skill、規範文件）的讀者是照著執行的執行者。它是操作手冊：步驟要編號，因為編號是執行的位置；判錯的代價要寫出來，因為執行者需要知道哪一步不能錯。

**人類教材**（教學文章）的讀者是來理解一件事的人。它要引導、說明、給脈絡。**講清楚為什麼是這個順序，順序自己就跟著出來，不需要編號**；讀者要的是判讀的依據，不是判錯的下場。

**程式碼註解**的讀者是正在讀那段程式的人。它只解釋商業邏輯——為什麼這個行為存在、這個旗標在擋什麼——不解釋程式碼原理，也不冗長，因為原理讀程式碼就有。

三者的差別可以收成一句：手冊告訴人怎麼做，教材讓人自己知道怎麼做，註解只補程式碼說不出來的那一件事。

## 實例：一篇教學被寫成手冊，而每一條規則都遵守了

一篇講某個外語菜名在各國指什麼的教學文，判讀段落寫成「第一層是它在哪一國」「第二層是它出現在哪裡」「第三層是主體食材」，接著另起一段演示判錯的後果——一個人在甲國吃過某道菜、記住了它的性質，到乙國照同一個名字點餐而端上來的是另一種東西。

每一項都通得過檢查。三個線索的內容正確、順序有理由、微案例四拍齊全。審查沒有報它，因為審查問的是「這一條規則遵守了嗎」，而規則確實遵守了。

改寫的方向是換一套體例，不在修辭上：開頭直接給理由（這個字的用法沿著國界走，所以先確認國別），把原本獨立列出的撞車例子移上來當那個理由本身，三個動作用先、之後、最後承接。判錯的代價整段刪掉，收成一句「判斷不出來就直接問侍者」。

同一批稿件裡另外兩處同型：一句警告接在事實後面（「這一點在點餐時會踩到」），以及一句祈使式指導（「在櫃檯前要看的是斷面，不是招牌」）。兩者都改成陳述，讓讀者自己得出結論。

## 量得到的是裝置，不是語氣

探針的第五題要求抄出讓它那樣判斷的原文，回來的句子收斂得很集中。把它們按形態歸類，就是一份會讓稿件被讀成手冊的裝置清單：

| 裝置                   | 樣子                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| 表徵對映清單           | 「孔洞遍佈整體，盤底或邊緣積出一層水：加熱過猛。」冒號兩邊是症狀與成因，讀者拿成品去對號         |
| 檢查順序的指示         | 「凝固之後才看孔洞的分布。」規定先看什麼再看什麼                                                 |
| 配比數字               | 「常見的配比是瘦肉、肥肉、魚漿約六比三比一。」                                                   |
| 順序關鍵加上顛倒的後果 | 「攪拌到產生極強的黏性之後才拌入魚漿……顛倒過來的話，魚漿會先把肉泥裹住而攪不出黏性，成品就散。」 |
| 可執行的操作判準       | 「火力大小看蒸氣就判得出來……『咻』地衝出來是火太大。」                                           |
| 具體器具作法           | 「在蒸鍋蓋下橫夾兩根筷子、上面再蓋一條布巾。」                                                   |
| 序列連接詞             | 「先確認這是哪一國的菜單……國別定了之後……最後看主體食材。」                                       |

最後一項推翻了作者原本的判斷。那一段本來寫成第一層、第二層、第三層，改寫時把編號拿掉換成先、之後、最後，而量測顯示這只成功了一半：「會放在手邊隨時翻」翻到了教學那一側，「預期讀者會照著做」還留在手冊那一側，五份全部引了那三個連接詞。**序列連接詞自己就攜帶程序讀法，編號只是它比較顯眼的形態。**

另有一份把同一段讀成兩種讀者——「廚師開始做這道菜；食客理解這道菜是什麼」。定位沒定下來的稿件在讀者那一側就長這個樣子。

## 為什麼審查抓不到

**審查的問題形狀是「這一條遵守了嗎」，而定位失配的稿件每一條都遵守了。** 要抓到它得問一個不同的問題：這一條規則是為誰設計的，手上這份稿件是不是那個誰。

frame 的觸發條件也幫不上忙，因為它們多半按**內容形狀**判定而不按定位判定。要求補微案例的那一條 frame，觸發條件是「判讀 / 選型型內容」——而一篇教人看懂菜單的文章確實給了判斷標準，形狀對上了，於是 frame 照常要求手冊才需要的裝置。

還有一層：同一條規則自己帶的判斷標準會被跳過。要求微案例的那條規則明寫了要挑後果最不直觀的、直觀的補了是冗餘，而點錯一道菜的後果直觀得不能再直觀。**定位沒先定下來的時候，規則的觸發條件會先於它自己的判斷標準生效。**

## 修法

**動筆前寫下一句定位。** 誰讀、讀完要做什麼。這一句是後面所有體例決定的依據，也是套規則時的過濾器。

**規則寫進共用規範時標注它的定位。** 「這一條為哪一種 surface 設計」寫在規則旁邊，比事後判斷便宜。共用的規範會累積來自各個 surface 的規則，而沒有標注的規則看起來一律通用。

**frame 的觸發條件除了內容形狀，還要收定位。** 「判讀 / 選型型內容」這種條件對形狀有效而對定位無效，補一個定位條件之後才分得開「工程決策的判讀」與「解釋性的判讀」。

**審查加一問。** 逐節問「這一節的體例屬於哪一種定位」，而不只問「這一節合不合規」。體例失配的稿件在合規那一問底下全部通過。

## 跟其他原則的關係

- [#242 形態讓讀者對號入座，微案例才讓他想像得出後果](../micro-case-makes-consequences-imaginable/) 是本卡實例裡被誤用的那條規則。那張卡的適用範圍寫的是「判讀 / 選型 / 決策類內容」——一個內容形狀的條件——而它真正的前提是後果不直觀且代價可觀，那是工程決策才滿足的。兩者不衝突：那張卡管的是判讀內容裡要不要補敘事，本卡管的是這份稿件屬不屬於那張卡設想的那種判讀。順序是先定位、再套它。
- [#217 審查要有斷言支撐 frame](../review-needs-claim-support-frame/) 抓的是模組的知識類型跟它所在分類的 house style 失配，兩邊都在 `content/` 裡面。本卡抓的是跨 surface 的失配——一份給人讀的教材套上了給 agent 執行的體例，而那兩個 surface 的 house style 本來就該不同，比對 sibling 也比不出來。
- [#254 教學與檢討內容寫給帶問題來的讀者](../write-for-readers-not-audiences/) 是同一個家族的另一個成員：那裡搬進來的是演講的體例（問句標題、懸念、三幕劇），這裡搬進來的是手冊的體例（步驟編號、判錯代價）。兩者的來源不同而機制相同——一種為別的場合設計的形式被當成通用的好寫法。
- [#150 教材用中性陳述、不對讀者喊話](../teaching-register-states-not-addresses-reader/) 管的是句子層的姿態，本卡管的是整份稿件的體例。祈使式指導同時命中兩者：它是對讀者喊話，也是手冊的形式。

## 判讀徵兆

- 教學內容裡出現步驟編號（第一層、第二層、第三步），而那些編號沒有被別處引用；換成先、之後、最後同樣算，序列連接詞攜帶的程序讀法與編號一樣。
- 問「讀者讀完之後那個動作落在哪裡」，答案是在世界上動手而不是在腦中重新歸類，而這份稿件的定位是讓人理解一件事。
- 一段判讀之後另起一段演示判錯的後果，而那個後果讀者從前文已經知道。
- 稿件通過了所有規則檢查，而讀的人說「內容是對的，但不會這樣寫」。
- 套某條規則時說得出它的觸發條件，說不出它為哪一種讀者設計。
- 共用規範裡的規則沒有標注定位，而那份規範同時服務兩種以上的 surface。
- 祈使句出現在教學內容裡（要看的是、記得、先確認），而讀者並沒有要照著執行。
