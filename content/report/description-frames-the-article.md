## 論述基礎與限制

本卡抽自一個語言層教材分類的全篇量測。該分類的二十二個檔裡有二十一個 `description` 寫成「遇到 X、想知道 Y 時」的觸發條件式，因為它們照著站內既有的規範寫。剩下那一個沒有寫成觸發條件，它是一句沒寫完的殘句。

**其中真正違規的是十一篇教材裡的十篇**——九張知識卡與兩個目錄頁依本卡自己的修法就該寫成觸發式，把它們算進違規數會讓這張卡的證據把自己判為合規的檔也算進去。三十三份理解探針回報時，每一份回答「這一篇解決什麼問題」都去引 `description`——那個欄位不只描述了文章，它已經替文章定義了目的。

全站另有七十餘篇同型，散在各分類。

限制是一個分類的觀察，而它的成因可推：**規範說了什麼，生成端就照著長。** 這一條在別的規範上是否同樣成立沒有測過。推翻方式：找一個 `description` 寫成觸發條件、而正文仍照規劃的觀念序列走的分類；本卡對那一批不成立。

## 核心原則

**`description` 是整篇文章的輔助說明，不是進來讀它的理由。** 它的位置在索引頁，作用是讓掃列表的人知道這一篇涵蓋什麼、補上標題說不完的那一段。文章從標題發想，`description` 從文章發想——順序是這樣，反過來就換了主人。

**觸發條件式的 `description` 決定的是讀者對這一篇目的的認知，而它也在寫作當下拉著作者。** 讀者那一半是量到的：三十三份探針回答「這一篇解決什麼問題」時都去引 `description`。作者那一半是機制推導——那句話在寫的時候就在檔案最上面，開場容易跟著先把 X 描述出來。

**但「它會重組正文」這一步，本卡的主要案例不支持。** 本卡抽出之後那個分類的 `description` 全部改寫過，而十一篇的正文結構一處都沒有動（逐篇比對段標增刪，唯一的變動是末節改名）。正文本來就照觀念序列走，寫成觸發式的只有那個欄位。所以規則要留，理由要換成**這個欄位在索引頁上沒有增量、而且會給讀者一個錯的目的**，不能宣稱它決定了正文的形狀。

**教材的組織單位是規劃好的觀念序列，不是問題集合。** 一章一章帶出讀者需要知道的東西，讓知識網絡沒有缺口；以回答問題的角度組織，會產生**沒有問就不知道的斷點**——讀者不曾遇到那個問題，就永遠不會知道有那件事。查閱型內容沒有這個問題，因為它的使用者本來就帶著問題來。

## 反模式：把查閱型的判斷標準套到教材上

[#170](/report/description-as-recall-trigger/) 立的規則是 `description` 要回答「什麼情境下需要回來讀」，而它的論述基礎是三篇 macOS 排錯文章——查閱型內容，使用者確實帶著症狀來。那張卡在自己的限制段寫著「單一案例（操作型文章），其他類型（教學模組、report 卡、知識卡）的 description 可能有不同的 recall 結構」。

限制寫了，推廣照樣發生。成因在卡片的結構：引用它的人讀的是核心原則段與修法段，而射程限制住在論述基礎段——那一段在讀者要動手的時候已經捲過去了。**一張卡的射程限制放在它自己身上是沒有效力的**，要擋住推廣得由引用它的那份規範寫出適用邊界。

第二個形態在同一批出現：文章開場補「讀者什麼情況下會需要這一篇」。它與 `description` 是同一個框架換一個位置，代價相同。

## 修法

**`description` 寫這一篇涵蓋什麼、交付哪一段觀念。** 判斷標準沿用 #170 仍然成立的那一條——遮住 `description` 只看標題，猜不猜得出全部內容；猜得出就是沒有增量、要重寫。改的是框架不是密度。

四種要換掉的句型：以「⋯⋯時」收尾的觸發條件、「想知道 / 想確認 / 想判斷」起手的意圖句、把症狀寫在前面的排錯敘述、以及問句。

**文章開場給概念，不給情境。** 首句說這個概念是什麼、承擔什麼責任（這一條本來就在寫作規範裡）；接下來的句子往下推導，不繞回「讀者為什麼在這裡」。

**跨篇引導改成範圍交代。** 現行的寫法是「遇到 X 的時候去讀 Y」，它把另一篇的存在綁在讀者有沒有遇到那件事上。改成說明本篇的邊界：這個主題不涵蓋哪些脈絡、那些面向另有專篇深入。前者要讀者先有問題，後者告訴讀者這裡還有別的面向——**差別在於讀者不必先知道自己缺什麼。**

**查閱型內容不動。** 排錯記錄、工具筆記、知識卡的定義層、歸納層的卡、以及各分類的目錄頁，使用者帶著症狀或問題來，觸發條件式在那裡是對的。

判別**不要用「在不在一條規劃好的序列上」**——那是本卡初稿的判別線，而它對歸納層給出錯的答案：那些卡有連續編號、有篇目索引，形狀上「在序列上」，而沒有人照序讀它們。可用的問句是**讀者是在掃列表決定要不要進去，還是已經決定要讀而需要知道範圍**。

## 判讀徵兆

| 徵兆                                                  | 為什麼是訊號                                 | 下一個動作                     |
| ----------------------------------------------------- | -------------------------------------------- | ------------------------------ |
| 一個教材分類的 `description` 幾乎每一篇都以「時」收尾 | 這是規範直接長出來的形狀，不是各篇各自選的   | 整批重寫，並回頭改那條規範     |
| 理解探針回答「這篇解決什麼問題」時去引 `description`  | 那個欄位已經替文章定義了目的，而正文只是配合 | 檢查正文是不是繞著那句話組織的 |
| 跨篇連結的句型清一色是「遇到 X 時見 Y」               | 另一篇的存在綁在讀者的問題上，沒遇到就不知道 | 改成本篇的範圍交代             |
| 一張卡自己寫了射程限制，而引用它的規範沒有寫適用邊界  | 限制在論述基礎段，動手的人不會讀到那裡       | 把邊界寫進規範，不留在卡上     |

## 跟其他抽象層原則的關係

**限定 [#170 description 是 recall trigger](/report/description-as-recall-trigger/) 的射程。** 那張卡的判斷標準對查閱型內容成立，而它的論述基礎正是查閱型的（macOS 排錯三篇）。教材套用它會讓文章反過來被那句話決定。兩張卡共用一條驗收——遮住 `description` 只看標題能不能猜出全部內容——差別只在框架：那裡問「什麼時候回來」，這裡問「這一篇涵蓋什麼」。

**是 [#306 按功能組織的教材沒有選擇的住址](/report/feature-organized-teaching-has-no-address-for-tool-choice/) 的邊界條件。** 那張卡的修法是加一層問題到落點的路由，而本卡說教材不該被問題組織——兩者不衝突，因為它們動的是不同的面：路由住在目錄頁（那是查閱面，使用者確實帶著問題來），觀念序列住在文章本身。真正要防的是路由變成主結構——目錄頁把問題表排在章節序列前面的時候，整個分類就宣告自己是問答集。

**與 [#302 定位先於任何規則](/report/positioning-decides-form-before-any-rule-applies/) 同機制。** 那裡是為 agent 指令設計的規則被套到文章上，這裡是為查閱型內容設計的規則被套到教材上。共同的成因是規則不記得自己的來歷，而觸發條件只看形狀對不對得上。

**與 [#303 跨連結吃掉它所在的那篇文章](/report/cross-links-eat-the-article-they-live-in/) 處理同一批連結的兩件事。** 那裡問的是連結有沒有交代目的地給什麼，這裡問的是連結要不要先預設讀者遇到了什麼。一條連結可以完全符合那張卡（寫清楚目的地交付什麼）而仍然踩本卡（把它綁在一個假想的情境上）。
