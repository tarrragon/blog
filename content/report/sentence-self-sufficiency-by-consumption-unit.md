## 結論

一個語句的自包含義務由它的**消費單位**決定：設計上會被單獨抽離消費的句子（checklist 項、表格格、判準句、grep 命中的行、章節首句）——本卡稱**單句消費位**——必須在句內資訊自足；嵌在段落敘事裡的句子——**敘事位**——可以依賴鄰句、壓縮合法。判斷單位是句子的消費方式、跟 [#260](../hyperbole-legitimacy-by-position-function/) 用位置功能判誇飾是同一個思考形狀。

**資訊充足**是可檢查的正向規格、四個條件：

1. **命題完整**：主詞在場（誰）、謂語完整（做什麼 / 是什麼）、作用對象與範圍明確（對什麼）、成立條件顯式（什麼時候）、量化範圍與情態顯式（全稱或存在、強制或建議、不留給讀者推定）。省略只在成分可從句內回收時合法。
2. **指涉閉合**：句中每個代詞、縮略形、殘片名詞、在句內找得到先行詞或完整形；跨句指涉要帶復原提示——完整名詞頭先出現、殘片形後用。在單句消費位、閉合的標準是**判讀時不需先解壓**：先行詞雖在單位內、但讀者要把殘片解壓回完整概念才判得動論證的、視為未閉合——逐項執行讓解壓成本每次都被重複支付。
3. **實詞可反推**：每個承載內容的詞能反推到具體機制、條件、契約（沿用 #111 口語化修辭卡的精度判準）；高度壓縮的謂語（「強到失實」）展開所需的內容要在句內或緊鄰處存在。
4. **一句一命題**：對仗與排比裡的每個半句能獨立判真；把多個命題壓進一個節奏單位時、每個命題各自通過前三條。複合條件句（若 A 且 B 則 C）與合連詞定義是單一命題、不觸發本條。

驗收測試是**抽離重讀**：把一個消費單位（checklist 的一項、表格的一列含鍵欄、獨立的判準句）單獨交給沒讀過上下文的讀者（人或模型）、命題能不能無歧義復原——抽離的單位是消費單位、不是裸句、所以內容欄可以靠同列鍵欄回收主詞。執行協議防一個已知失效：模型填補歧義用的正是造成問題的文體先驗、會生成看似合理的復原然後回報「沒有歧義」——所以執行者要**輸出復原出的命題本身**、不是回報通過與否、由作者比對復原是否等於原意；人與模型判定不同時、以不足計。回收不了的、在單句消費位是缺陷、在敘事位不強制。

正向規格是刻意的設計選擇：「避免為了美感犧牲資訊」這類負向禁令以模糊審美概念為軸、執行者（尤其是 LLM）要先自行定義「什麼算美感導向的簡潔」、而那個定義只能來自造成問題的同一個文體先驗（寫作者——人或模型——從語料學來的文風預設、機制見下段）——禁令沒有梯度、合法的簡潔跟失資訊的簡潔在表面上長得一樣。四條件把違規變成可指認的偏差：「缺主詞」「指涉懸空」比「太簡潔了」可執行。

## 為什麼會寫出資訊不足的句子

壓縮把解歧負擔外移。每省一個成分（主詞、名詞頭、修飾語）、句子變短、節奏變好、而解讀所需的資訊轉嫁給讀者手上的 context。人類的線性閱讀有 discourse memory（順讀累積的上下文記憶）、多數時候付得起這筆轉嫁；抽離消費的讀者付不起——負擔轉嫁直接變成歧義。

推力來自文體先驗（機制的完整敘述以 [#259](../rewrite-preserves-claim-intensity/) 的「文體先驗接管」段為準、本卡只補句層形態）：中文技術寫作常見四字節奏、對仗、殘句收尾的文風、寫的人（人或模型）往這個典型滑、且滑的當下句子讀起來「更好」——失資訊藏在美感裡、寫作者自己看不到、因為他腦中有完整 context、每個殘片對他都可回收。

中文在這裡是放大器：單字是多義語素、壓縮砍掉名詞頭、修飾語、主詞時、砍掉的正是解歧成分。放大器之上、不同消費者付不起解歧轉嫁的原因各不相同：

| 消費者 | 消費情境        | 為什麼付不起解歧轉嫁                                                                                       |
| ------ | --------------- | ---------------------------------------------------------------------------------------------------------- |
| LLM    | 單行檢索        | grep-friendly 設計預期句子被單獨命中、句子的指涉成分沒跟著句子走                                           |
| LLM    | 長 context 生成 | 模型對幾句之前定義的取用可靠度隨距離下降（[lost-in-the-middle](/llm/knowledge-cards/lost-in-the-middle/)） |
| LLM    | 風格繼承        | 被讀進 context 的規範文字是生成的直接素材、文風連同缺陷被輸出延續                                          |
| 人     | 跳讀與搜尋落地  | 掃描式閱讀直達段落中間、手上沒有順讀累積的上下文記憶                                                       |

風格繼承這一層會遞迴：模型延續被讀進 context 的素材文風、填補歧義用的正是自己的文體先驗——[#259](../rewrite-preserves-claim-intensity/) 描述的漂移機制、會由壓縮到產生歧義的規範文字在下游重演、一份規範的文風缺陷因此複製進所有引用它的產出。生產側另有兩個放大時點：審查修法的當下（作者剛想通、腦中 context 最滿、最看不到殘片——本卡的 case 正是一次審查修正自己寫出來的）、與容器形狀壓力（#262 的表格格與標題長度帶直接誘發句層壓縮）。

## Case：一條 checklist 項的兩版對照

一份 audit reference 的 checklist 項、初版（一次多輪審查的第一輪修正自己寫出來的）：

> - [ ] **反比操縱訊號**：越難驗證的段落話講得越滿嗎？（強度與可驗證性反向是推銷話術的結構特徵；反比結構無法用文體先驗的無意滑動解釋、所以警惕等級最高）

括號後半的「反比結構」「無意滑動」是同項前分句已定義概念的**壓縮重述**：主詞與謂語都在（條件一過）、實詞可反推（條件三過）、卡在條件二的解壓標準——先行詞雖在項內、讀者仍要把殘片解壓回「強度與可驗證性反向的分布」「作者無意的文風滑動」才判得動後半的論證、checklist 逐項執行讓這筆解壓成本每次被重複支付、而「解釋不成無意」這個六字謂語把一個完整命題壓縮到單獨閱讀無法復原的程度。第二輪的篇章層冷讀 reviewer 未見（順讀時殘片可從前分句回收、逐篇冷讀這個方法對句內壓縮結構性看不見——「方法看不見」跟「沒問題」在報告裡同訊號）、由審查流程之外的另一位讀者以抽離重讀指出。修正後（含後續一輪把「只有刻意誇大」的過強歸因一併降級）：

> - [ ] **反比操縱訊號**：越難驗證的段落話講得越滿嗎？（「話最滿的段落恰好最難查證」這種全篇分布比單點升格更難歸因於無意的文風滑動、所以警惕等級最高）

每個指涉在句內閉合、而括號總長不增（47 字對 46 字）——**自足的成本落在成分安排、不必然落在字數**：把殘片重述換成完整命題、省下的正是讀者的解壓步驟。

教學文章側有同型的觀察：章節用字簡潔到讀者辨識不出議題與關心重點、後續寫作被要求補足引導與舉例——問題在句層就發生了、段落層的補救是在替句子還債。這是一位讀者的閱讀觀察、獨立驗證尚未做、作為佐證而非第二個實證。

## 消費單位的判定

| 消費單位   | 例子                                                      | 自足義務                                                                                       |
| ---------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 單句消費位 | checklist 項、表格格、判準句、章節與段落首句、grep 目標行 | 資訊充足四條件（命題完整 / 指涉閉合 / 實詞可反推 / 一句一命題）全數強制、驗收跑抽離重讀        |
| 檢索鍵位   | title、description、表格鍵欄、卡名、anchor                | 義務是**識別充足**（讀者能指認它索引的是哪個命題）、命題完整不適用；跟精簡規範衝突時 #170 優先 |
| 敘事位     | 推導過程、case 敘述、段落中段                             | 句子可依賴鄰句復原成分、為了節奏而壓縮合法                                                     |

分配是三角取捨的解法：用詞精準、總 context 精簡、句子自足三者不可能同時最大化——自足要求補成分、精準要求加限定語與完整名詞頭、兩者都與精簡的減字方向相反；敘事位省下的字、供應給單句消費位的展開。全域加長跟全域壓縮都是錯的答案。

表格是前兩類的組合：一列是一個消費單位、鍵欄（第一欄）是檢索鍵位、命題完整的義務落在內容欄——「中文單字多義」這類鍵欄短語合規、判違規的是內容欄裡回收不了的殘片。文章 title 同理：「營業利益率」這類純名詞短語是檢索鍵、四條件對它不適用、它的義務是讓讀者指認得出正文在講哪個命題。

## 判讀徵兆

| 訊號                                           | 該做的事                                                                                  |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 句子出現四字節奏、對仗、殘句收尾               | 候選訊號、不是判決——先判消費單位、單句消費位才跑抽離重讀                                  |
| checklist 項或表格格裡有代詞、縮略形、殘片名詞 | 查指涉閉合（條件二）：完整形在單位內且判讀不需先解壓嗎、需要就展開                        |
| 讀者反映「章節簡潔到看不出議題」               | 先定位層：句層問題掃段落首句與判準句跑資訊充足四條件、容器層問題（判準被塞進表格）走 #262 |
| 給 LLM 讀的規範要新增一條規則                  | 規則句預設是單句消費位——寫完單獨重讀一次、指涉閉合了才放進規範                            |
| 修文時想把長句「收乾淨」                       | 先判位置：敘事位可收；單句消費位的自足為抽離消費而存在、成本落在成分安排、字數增減都可能  |

**核心**：句子的美感由讀過上下文的人評、句子的資訊由沒讀過上下文的消費者取——單句消費位為後者寫、四條件是它的規格、抽離重讀是它的驗收。
