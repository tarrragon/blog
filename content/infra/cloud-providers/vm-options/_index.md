建立虛擬機的頁面把三十幾個欄位排在一起，而它們分屬幾類互不相干的功能。這個資料夾一類功能一篇，每篇涵蓋的項目見〈各篇共用的寫法〉。

## 章節文章

| 文章                                                                                                       | 這一類選項決定什麼                                                     |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| [位置：區域、可用區與故障域](/infra/cloud-providers/vm-options/placement/)                                 | 主機的實體位置：延遲、出口 IP 的國家、可用機型、硬體故障時的影響範圍   |
| [機型與映像檔](/infra/cloud-providers/vm-options/shape-and-image/)                                         | CPU 架構與核心、記憶體大小，計費與可被收回的條件，作業系統與架構相容性 |
| [網路：subnet、私有 IP、公開 IP 與防火牆規則](/infra/cloud-providers/vm-options/networking/)               | 主機在網路上的位置，誰連得到它、它連得到誰                             |
| [登入：SSH 金鑰、預設使用者、建立後加金鑰與不放金鑰時的登入服務](/infra/cloud-providers/vm-options/login/) | 建好之後管理員用什麼身分、什麼金鑰登入，沒有金鑰時還有哪些入口         |

## 各篇共用的寫法

每一篇都寫這幾項：這一類選項是什麼、建立後能不能改（改不了的才需要在建立頁上想清楚）、對費用的影響、選錯時的徵兆、實驗用的小主機怎麼選，結尾是三家的欄位名稱對照。維護時照這一份清單檢查各篇。主要例子取自 Oracle Cloud（實測在那一家），寫通則句之前先確認另兩家的行為，只對一家成立的句子在句首寫明業者。各家的實測紀錄放在業者子資料夾底下的 `hands-on/`，例如 [Oracle Cloud 建立主機的實測紀錄](/infra/cloud-providers/oracle-cloud/hands-on/launch-instance-walkthrough/)，那一篇照主控台的分頁順序，每一欄連回這裡對應的那一篇。
