本模組承擔語言無關的軟體設計原則：模組的邊界怎麼畫、哪些程式碼該放在一起、違反時在程式碼與修改紀錄上留下什麼痕跡。這些原則在每種語言的寫法不同（Python 的套件與 re-export、Go 的 package、Dart 的 library），所以本模組只放定義與判斷標準，實作細節放在各語言模組。

路由方向是單向的：本模組的定義不依賴任何語言的實作；語言模組引用本模組的卡片建立概念。

### 範圍決定

2026-10-19 評估過把 DDD、UX Design、Testing 移進本模組，三者都維持獨立、與本模組並列：

- **DDD**：理解的對象是領域模型，自有詞彙與案例庫；它引用本模組的單一職責與開放封閉原則，關係是引用而不是隸屬。
- **UX Design**：理解的對象是使用者與畫面，與程式碼結構沒有交集。
- **Testing**：理解的對象是驗證怎麼分層，涵蓋可觀測性、UI 自動化與 agent 產出程式碼的驗證，大半與程式碼結構無關。

本模組的內容改由抽取補齊：語言模組裡講語言無關原則的段落，把定義與判斷標準抽成本模組的卡，語言寫法留在原處並連過來。DDD 的 Dependency Injection 與 Test Seam 卡評估後留在 DDD：兩張的引用全部在 DDD 內部，內容以 port、adapter、composition root 定義，搬出會切斷那組卡的互連。

重新評估的條件：DDD 的章節開始處理與領域模型無關的模組設計，或讀者路線固定成先讀本模組再讀 DDD 的一條階梯。
