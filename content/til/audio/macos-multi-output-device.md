本篇的延遲與音量資料來自 2026 年 11 月在一台 Mac mini（Apple M4，macOS 15.3.1）上讀取 CoreAudio 裝置屬性的結果。那台 Mac 接著兩台內建喇叭的螢幕（一台走 HDMI、一台走 DisplayPort）與一台藍牙喇叭，已經建好一個由 Mac mini 內建揚聲器與那台藍牙喇叭組成的多重輸出裝置；讀取用的是只讀不寫的 Swift 程式（全文在〈查自己的 Mac 上每個輸出裝置的延遲與音量控制〉）。介面文字取自同一台 Mac 的繁體中文介面。

這篇寫 macOS 內建的多重輸出裝置（Multi-Output Device）：它把同一路聲音複製到哪些裝置、跟聚集裝置（Aggregate Device）差在哪裡；在「音訊MIDI設定」建立它、選成聲音輸出的步驟；主要裝置與偏移修正這兩個設定各自管什麼；有線裝置與藍牙裝置之間的延遲差，以及延遲差在聆聽位置造成的頻率抵消與回音；多重輸出裝置沒有系統音量時，各裝置的音量在哪裡調；藍牙喇叭帶麥克風時的通話模式；最後是分房間播放、耳機與喇叭給不同的人聽、兩副藍牙耳機一起看影片、同一個位置疊加音量、分左右聲道這幾種擺放各自的結果。藍牙的編碼格式與延遲的成因在〔[數位訊源的構造與選擇](/til/audio/digital-streaming-source-guide/)〕，兩個聲音疊加時的相位在〔[家用音響的基礎概念](/til/audio/audio-fundamentals/)〕的〈相位：兩個聲音疊加時的加強與抵消〉；本篇只寫 macOS 內建的功能，不寫第三方軟體，也不寫 iPad、iPhone 這類 Apple 行動裝置當接收端的做法。

## 多重輸出裝置把同一路立體聲複製到每個勾選的裝置

多重輸出裝置是 macOS 在「音訊MIDI設定」裡建立的一個虛擬輸出裝置，由幾個實體的輸出裝置組成。App 把聲音送給多重輸出裝置時，macOS 把同一路聲音送到組成它的每一個裝置。Apple 的說明寫的是「送到主要裝置的聲音，也會經由堆疊裡的其他裝置播放」（Apple 支援文件〈Play audio through multiple devices at once in Audio MIDI Setup on Mac〉）。每個裝置收到的是同一份左右聲道：一台喇叭放左聲道、另一台放右聲道這種分工，多重輸出裝置做不到。

能加入多重輸出裝置的是 Mac 的輸出清單裡看得到的裝置：內建揚聲器、耳機孔、經由 HDMI 或 DisplayPort 接的螢幕或電視、USB 的 DAC 與喇叭、已經配對並連線的藍牙喇叭與耳機。「音訊MIDI設定」另外有「連接AirPlay裝置」的選項，AirPlay 喇叭接上之後也會出現在清單裡；本篇沒有實測 AirPlay 裝置放進多重輸出裝置的情形。

同一個 App 裡的聚集裝置是另一種虛擬裝置。Apple 的說明寫的是聚集裝置讓「多個裝置在 App 裡顯示成單一裝置」，用途是增加同時可用的輸入與輸出數（Apple 支援文件〈Create an Aggregate Device to combine multiple audio devices〉）：兩台各有兩個聲道的裝置聚集起來，App 看到的是一台有四個聲道的裝置，由 App 決定每個聲道送什麼。所以兩者的分工在聲道：多重輸出裝置把同一份聲音複製出去，聚集裝置把各裝置的聲道並排出來，讓支援多聲道輸出的 App（錄音與混音軟體）分別指定。一般的音樂與影片 App 只送兩個聲道，放在聚集裝置上時，聲音只會從前兩個聲道所屬的那一台出來。

## 建立多重輸出裝置並選成聲音輸出的步驟

下面的步驟在同一台 Mac 上建一個多重輸出裝置並讓所有 App 的聲音經由它播放。每一步寫出它為什麼在這個位置，以及做錯或略過時會看到什麼。

1. **打開「音訊MIDI設定」**：它在 Finder 的「應用程式」>「工具程式」裡，也可以用 Spotlight 搜尋「音訊MIDI設定」。視窗左側的側邊欄列出這台 Mac 目前看得到的每個音訊裝置。藍牙裝置要先在系統設定的藍牙頁連線，才會出現在這份清單裡：沒有連線的藍牙裝置在勾選裝置的清單裡也不會出現。
2. **按側邊欄左下角的「+」，選「製作多重輸出裝置」**：側邊欄多出一個名為「多重輸出裝置」的項目，點兩下可以改名。建幾個都可以，例如一個「客廳加書房」、一個「兩副耳機」，之後在輸出清單裡依名字切換；不改名時，幾個項目都叫「多重輸出裝置」，輸出清單裡分不出來。
3. **在右側的清單裡勾選要用的裝置**：右側清單的說明是「在此多重輸出群組中的裝置會同時輸出音訊。請勾選裝置旁的『使用』按鈕來將它加入裝置群組」。勾了幾個，聲音就從幾個裝置出來；只勾一個時，多重輸出裝置等於那一台裝置，只是少了系統音量（〈音量〉那一節）。
4. **在「主要裝置：」選單選一台裝置**：主要裝置是其他裝置對齊的時脈基準；在本篇讀取的那台 Mac 上，多重輸出裝置回報給 App 的延遲也等於主要裝置的延遲。選哪一台、各自換到什麼，在〈主要裝置：時脈的基準與回報給 App 的延遲〉。
5. **勾選主要裝置以外每一台的「偏移修正」**：偏移修正讓這台裝置的播放速度跟著主要裝置的時脈調整。不勾時，兩台裝置各自依自己的時脈播放，播得越久錯開得越多，到某個時候會聽到斷音或爆音；原因與估算在〈偏移修正：讓其他裝置跟上主要裝置的時脈〉。
6. **在「取樣頻率：」選一個取樣率**：這是多重輸出裝置對 App 呈現的取樣率。設成跟主要播放的音樂相同（多數串流與 CD 是 44.1 kHz），音樂進到多重輸出裝置時就不必先重新取樣；設成 48 kHz 時，44.1 kHz 的音樂會先被重新取樣一次。重新取樣的誤差量級在〔[數位訊源的構造與選擇](/til/audio/digital-streaming-source-guide/)〕的〈串流從服務到 DAC 經過的環節〉。組成多重輸出裝置的各裝置不一定用同一個取樣率：本篇讀取的那台 Mac，多重輸出裝置設在 44.1 kHz，底下的內建揚聲器維持在 96 kHz，兩者之間由 macOS 轉換。
7. **把多重輸出裝置選成聲音輸出**：在側邊欄用 Control 鍵點一下多重輸出裝置，選「使用此裝置來輸出聲音」；在系統設定的「聲音」或選單列的聲音選單裡，從輸出清單選它，結果相同。同一個選單裡另有「透過此裝置播放提示聲和音效」，不勾時系統的提示聲照舊從原本的裝置出來，只有 App 的聲音走多重輸出裝置。選錯成聚集裝置時，音樂只會從其中一台出來（〈多重輸出裝置把同一路立體聲複製到每個勾選的裝置〉的聚集裝置那一段）。
8. **調各裝置的音量**：選了多重輸出裝置之後，鍵盤的音量鍵與選單列的音量滑桿調不了音量，各裝置的音量要分開調，做法在〈音量：多重輸出裝置沒有系統音量〉。

主要裝置、偏移修正與取樣頻率是這個多重輸出裝置自己的設定，它還沒被選成輸出時就能設定。所以這幾步排在選成聲音輸出之前，切換過去時第一個聲音就已經用到正確的設定。播放中改這幾項也可以，改的當下可能聽到短暫的中斷。

## 主要裝置：時脈的基準與回報給 App 的延遲

主要裝置決定兩件事：其他裝置對齊哪一台的時脈，以及多重輸出裝置回報給 App 的延遲。

每一個音訊裝置依自己的[時脈](/til/audio/knowledge-cards/clock-jitter/)決定每秒送出多少個取樣，兩台裝置的時脈不會完全一樣快。多重輸出裝置以主要裝置的時脈為準，其他裝置靠偏移修正跟上它。Apple 對聚集裝置的建議是「選時脈最可靠的裝置」當時脈來源（〈Create an Aggregate Device to combine multiple audio devices〉）；多重輸出裝置的說明頁沒有寫選擇的建議。

回報給 App 的延遲影響的是影片。看影片的 App 會讀輸出裝置回報的延遲，把畫面延後同樣的時間，讓聲音跟畫面對齊。本篇讀取的那台 Mac 上，主要裝置是藍牙喇叭，多重輸出裝置回報的延遲（約 186 ms）跟那台藍牙喇叭的值完全相同，而內建揚聲器的值約 11.5 ms。依這個讀數推論：主要裝置是藍牙裝置時，影片的畫面會配合藍牙裝置的聲音，有線裝置的聲音比畫面早到；主要裝置是有線裝置時，畫面配合有線裝置，藍牙裝置的聲音比畫面晚到。這個推論只在一台 Mac、一種組合上讀過一次，沒有換主要裝置再讀，也沒有用影片實際對過嘴型。

由這兩件事推出選擇的條件：多重輸出裝置用來看影片、而觀眾聽的是藍牙耳機或藍牙喇叭時，選那台藍牙裝置當主要裝置，對白跟嘴型才對得上；只放音樂時沒有畫面要對齊，照 Apple 對時脈來源「選時脈最可靠的裝置」的建議選。Apple 沒有寫哪一類裝置的時脈最可靠；本篇的推論是選一台有線的裝置（內建揚聲器、耳機孔、USB DAC），因為有線裝置的取樣節奏由 Mac 或裝置本身的振盪器直接決定，藍牙裝置之前還多了無線傳輸與接收端的緩衝。

## 偏移修正：讓其他裝置跟上主要裝置的時脈

偏移修正（drift correction，介面上的「偏移修正」欄）處理的是兩台裝置的時脈快慢不同所累積的時間差。時脈的快慢差異以 ppm（百萬分之一）計：兩台裝置的時脈相差 50 ppm 時，每播放一小時，兩者錯開 3600 秒 × 50 ÷ 1,000,000 = 0.18 秒。這個差距會一直累積，而 macOS 為每台裝置準備的緩衝區只有幾毫秒到幾十毫秒長，錯開的時間超過緩衝區時，較快的那台沒有資料可播（斷音），或較慢的那台的緩衝區滿出來（丟掉一段資料），兩種都聽得到爆音或跳動。50 ppm 是用一般石英振盪器的誤差量級估的值，實際的差異依裝置而定。

勾了偏移修正的裝置，macOS 依它跟主要裝置的時脈差持續微調送給它的取樣數（重新取樣），讓兩者不再越錯越開。Apple 對聚集裝置的說明是「每一台不是時脈來源的裝置，都勾選偏移修正」；幾台專業錄音介面用專門傳送時脈訊號的 word clock 線接在一起時，各裝置已經共用同一個時脈，Apple 的建議是取消偏移修正（〈Create an Aggregate Device to combine multiple audio devices〉）。家用的組合（內建揚聲器、耳機孔、藍牙、螢幕）都沒有 word clock 接頭，所以主要裝置以外的每一台都勾。

偏移修正只修時脈快慢造成的累積差，各裝置固定的延遲它不處理：一台藍牙喇叭從一開始就比內建揚聲器晚一百多毫秒，勾了偏移修正之後，它仍然晚一百多毫秒，只是不會再越來越晚。

## 各裝置的延遲不同：頻率的抵消與聽成兩個聲音

輸出延遲是 App 把一段聲音交給裝置、到裝置的喇叭實際發出那段聲音之間的時間。有線裝置的延遲主要來自緩衝區；藍牙裝置另外要經過[藍牙的音訊編碼格式](/til/audio/knowledge-cards/bluetooth-audio-codec/)的壓縮、無線傳輸與接收端的解碼，延遲大得多。本篇讀取的那台 Mac 上，各裝置回報的輸出延遲是：內建揚聲器約 11.5 ms、耳機孔約 13.4 ms、HDMI 與 DisplayPort 接的螢幕各約 19.2 ms、藍牙喇叭約 186 ms。這些是裝置回報給 macOS 的值，不是從喇叭量到的聲學延遲；藍牙裝置的實際延遲依耳機或喇叭的型號、使用的編碼格式而變，自己的 Mac 上的值照〈查自己的 Mac 上每個輸出裝置的延遲與音量控制〉讀。

多重輸出裝置把同一份聲音同時交給每個裝置，各裝置依自己的延遲發聲，裝置之間的延遲差原樣保留。「音訊MIDI設定」的多重輸出裝置設定裡沒有延遲補償的欄位。兩個裝置的聲音都傳到同一個聆聽位置時，延遲差（加上兩台離聆聽位置的距離差，聲音每走 34 公分約多 1 ms）決定聽到的結果：

- **延遲差在三四十毫秒以內**（兩台有線裝置，例如內建揚聲器與螢幕喇叭，上面那台 Mac 上兩者回報的值相差約 8 ms）：前後兩個聲音融合成一個，方向聽起來在先到的那一台；這是英文文獻稱為 precedence effect（也稱 Haas effect）的聽覺現象，能融合的上限依聲音的種類而不同，短促的打擊聲較短、語音與音樂較長。融合之後，某些頻率在聆聽位置互相抵消：抵消發生在兩個聲音的[相位](/til/audio/knowledge-cards/phase/)相差 180 度的頻率，延遲差是 1 ms 時，第一個抵消的頻率在 500 Hz，之後每隔 1 kHz 再出現一次（1.5 kHz、2.5 kHz……）；延遲差是 8 ms 時，抵消的頻率從 62.5 Hz 起每隔 125 Hz 出現一次。頻率響應上的凹陷像梳子的齒一樣等間隔排列，英文的聲學文獻稱為 comb filtering。聽起來是聲音變空、變薄，頭稍微移動時音色跟著改變，因為距離差變了，凹陷的頻率跟著移動。
- **延遲差超過數十毫秒**（有線裝置加藍牙裝置）：後到的聲音聽成另一個聲音，也就是回音。上面那台 Mac 上，藍牙喇叭與內建揚聲器相差約 175 ms，相當於聲音多走約 60 公尺，每一個鼓聲與子音都會聽到兩次。

所以多重輸出裝置的用途取決於聆聽位置聽得到幾台：只聽得到其中一台時，延遲差沒有作用；同時聽得到兩台以上時，延遲差直接改變聽到的聲音。〈適用與不適用的擺放〉依這個條件分。

## 音量：多重輸出裝置沒有系統音量

多重輸出裝置本身沒有可以調整的總音量。macOS 的音量鍵與選單列的音量滑桿調整的是目前輸出裝置的「虛擬總音量」屬性；本篇讀取的那台 Mac 上，內建揚聲器、耳機孔與藍牙喇叭都有這個可以調整的屬性，多重輸出裝置沒有，所以選它當輸出之後，音量鍵與滑桿調不了音量。兩台經由 HDMI 與 DisplayPort 接的螢幕也沒有這個屬性：它們單獨當輸出時，系統音量同樣調不了，音量只能用螢幕自己的按鍵或選單調。

各裝置的音量有三個地方可以調，各自影響的範圍不同：

- **「音訊MIDI設定」裡各裝置的音量**：在側邊欄點選內建揚聲器、藍牙喇叭這些個別的裝置（不是多重輸出裝置），右側「輸出」分頁的「聲道音量」滑桿調的就是那一台的音量。改了之後，多重輸出裝置經由那一台播放的音量跟著改，用來在幾台之間調平衡。
- **裝置自己的音量鈕**：藍牙喇叭、螢幕、主動式喇叭的實體旋鈕或按鍵。沒有系統音量屬性的裝置（上面那兩台螢幕）只能在這裡調。
- **播放 App 裡的音量滑桿**：音樂與影片 App 自己的音量在聲音交給多重輸出裝置之前就調低了取樣的數值，所以同時改變每一台的音量，可以當成總音量用。代價是各裝置的類比增益沒有跟著降：macOS 內部以足夠的位元深度運算時，解析度的損失在底噪以下，輸出設成 16 位元、App 音量又開得很低時，有效位元數才會明顯變少（數位音量的影響在〔[數位訊源的構造與選擇](/til/audio/digital-streaming-source-guide/)〕的〈串流從服務到 DAC 經過的環節〉的數位音量那一項）。

實際的做法是先在「音訊MIDI設定」或各裝置上把幾台的音量調到彼此平衡，之後日常用 App 的音量調整整體大小。

## 藍牙喇叭帶麥克風時的通話模式

藍牙喇叭與藍牙耳機有兩種傳送聲音的方式：放音樂時用的高音質單向傳送（A2DP 協定），以及通話時用的雙向傳送（HFP 協定）。HFP 同時傳麥克風的聲音，代價是輸出的取樣率與音質大幅降低。本篇讀取的那台 Mac 上，藍牙喇叭的輸出是 44.1 kHz，同一台的麥克風輸入是 16 kHz，16 kHz 是通話模式用的取樣率。

macOS 把帶麥克風的藍牙裝置選成聲音輸入、而某個 App 開始使用麥克風時（視訊會議、語音訊息、聽寫），那台藍牙裝置會切換到通話模式，經由它播放的音樂跟著變成通話音質，多重輸出裝置裡的那一台也一樣。Mac mini 這類沒有內建麥克風的 Mac 最容易遇到：系統找不到別的輸入裝置時，會把藍牙裝置的麥克風當成預設輸入。這一段的切換行為是依藍牙協定的機制寫的，本篇沒有實測。不想讓音樂受影響時，在系統設定的「聲音」把輸入裝置改成別的麥克風（USB 麥克風、有線耳機的麥克風）。

## 適用與不適用的擺放

多重輸出裝置播放時，聆聽位置聽到的是一個完整的聲音、某些頻率被抵消的聲音，還是回音，取決於〈各裝置的延遲不同〉那一節的條件：一個聆聽位置同時聽得到幾台裝置，以及那幾台之間的延遲差。依這個條件，常見的幾種擺放各自的結果如下。

**分房間播放背景音樂**：客廳放藍牙喇叭、書房用 Mac 的內建揚聲器或螢幕喇叭，兩個房間播同一首歌。在任一個房間裡主要只聽得到那個房間的裝置，延遲差聽不太出來；走在兩個房間之間、兩台都聽得到的位置（門口、走廊），會聽到回音。適合在家裡走動時讓音樂不中斷；兩台的音量要在〈音量〉那一節的地方各自調，因為兩個房間的大小與吸音不同，同樣的設定聽起來不一樣大聲。

**有線耳機與喇叭給不同的人聽**：一個人在 Mac 前戴有線耳機，另一個人在房間另一頭聽藍牙喇叭。每個人只聽得到自己那一台，延遲差沒有作用。戴耳機的人如果耳機是開放式，會同時聽到房間裡的喇叭聲，延遲差會變成回音；封閉式或入耳式耳機隔得住外面的聲音時沒有這個情形。

**兩副藍牙耳機一起看影片**：兩個人各戴一副藍牙耳機看同一部影片，彼此聽不到對方的耳機，延遲差只影響聲音跟畫面的對齊。把其中一副選成主要裝置，影片的畫面依它回報的延遲對齊（〈主要裝置〉那一節的推論）；另一副是同型號或延遲相近的耳機時，兩個人聽到的對白都跟嘴型相近，型號不同、延遲差得多時，非主要裝置那一副的嘴型會對不上。

**同一個位置疊加幾台裝置來加大音量或加厚聲音**：例如桌上同時開內建揚聲器、螢幕喇叭與藍牙喇叭。聆聽位置同時聽得到每一台，有線裝置之間的延遲差讓某些頻率抵消、聲音變空，加上藍牙裝置時聽到回音。結果多半比只開其中音質最好的那一台差。音量不夠時，換一台音量夠的喇叭比疊加幾台小喇叭有效，各種喇叭的適用條件在〔[喇叭的規格與構造](/til/audio/speaker-specs-and-construction/)〕。

**一台放左聲道、一台放右聲道**：多重輸出裝置送給每台的是同一份左右聲道，做不到。要分左右得用聚集裝置，加上能指定每個聲道送到哪一台的 App；藍牙裝置放進聚集裝置之後，兩台之間的延遲差一樣存在，左右兩邊的聲音到達時間不同，聲像會偏向先到的那一邊（precedence effect）。要穩定的立體聲，用一對有線連接的喇叭，起點與花費順序在〔[家用音響系統的組成](/til/audio/home-audio-system-guide/)〕。

## 查自己的 Mac 上每個輸出裝置的延遲與音量控制

「音訊MIDI設定」與系統設定都不顯示裝置的延遲，也不顯示一台裝置是否有系統音量。下面這支 Swift 程式讀 CoreAudio 的裝置屬性，對每一個有輸出的裝置印出回報的輸出延遲、目前的取樣率，以及系統音量（音量鍵與選單列滑桿）是否調得到它。程式只讀屬性，不改任何設定。

```swift
import CoreAudio
import Foundation
import AudioToolbox

let sys = AudioObjectID(kAudioObjectSystemObject)
let out = kAudioDevicePropertyScopeOutput

func addr(_ sel: AudioObjectPropertySelector, _ scope: AudioObjectPropertyScope = kAudioObjectPropertyScopeGlobal) -> AudioObjectPropertyAddress {
    AudioObjectPropertyAddress(mSelector: sel, mScope: scope, mElement: kAudioObjectPropertyElementMain)
}
func uint(_ id: AudioObjectID, _ sel: AudioObjectPropertySelector, _ scope: AudioObjectPropertyScope = kAudioObjectPropertyScopeGlobal) -> UInt32 {
    var a = addr(sel, scope); var v: UInt32 = 0; var s = UInt32(4)
    AudioObjectGetPropertyData(id, &a, 0, nil, &s, &v); return v
}
func name(_ id: AudioObjectID) -> String {
    var a = addr(kAudioObjectPropertyName); var v: Unmanaged<CFString>?; var s = UInt32(MemoryLayout<CFString?>.size)
    AudioObjectGetPropertyData(id, &a, 0, nil, &s, &v); return (v?.takeRetainedValue() as String?) ?? "?"
}

var a = addr(kAudioHardwarePropertyDevices); var size: UInt32 = 0
AudioObjectGetPropertyDataSize(sys, &a, 0, nil, &size)
var ids = [AudioObjectID](repeating: 0, count: Int(size) / 4)
AudioObjectGetPropertyData(sys, &a, 0, nil, &size, &ids)

for id in ids {
    var sa = addr(kAudioDevicePropertyStreams, out); var ss: UInt32 = 0
    AudioObjectGetPropertyDataSize(id, &sa, 0, nil, &ss)
    if ss == 0 { continue }                       // 沒有輸出串流的裝置（只有麥克風）跳過
    var streams = [AudioStreamID](repeating: 0, count: Int(ss) / 4)
    AudioObjectGetPropertyData(id, &sa, 0, nil, &ss, &streams)
    var ra = addr(kAudioDevicePropertyNominalSampleRate); var rate: Double = 0; var rs = UInt32(8)
    AudioObjectGetPropertyData(id, &ra, 0, nil, &rs, &rate)
    let frames = uint(id, kAudioDevicePropertyLatency, out) + uint(id, kAudioDevicePropertySafetyOffset, out)
        + uint(id, kAudioDevicePropertyBufferFrameSize) + uint(streams[0], kAudioStreamPropertyLatency)
    // 系統音量鍵與選單列滑桿調的是這個「虛擬總音量」，裝置沒有它時那兩處調不了音量
    var va = addr(kAudioHardwareServiceDeviceProperty_VirtualMainVolume, out); var settable: DarwinBoolean = false
    let volume = AudioHardwareServiceHasProperty(id, &va)
        && AudioHardwareServiceIsPropertySettable(id, &va, &settable) == noErr && settable.boolValue
    print("\(name(id))：回報的輸出延遲約 \(String(format: "%.1f", Double(frames) / rate * 1000)) ms，取樣率 \(Int(rate)) Hz，系統音量調得到：\(volume ? "是" : "否")")
}
```

把程式存成 `output-latency.swift`，在終端機切到存放它的資料夾執行：

```bash
swift output-latency.swift 2>/dev/null
```

`swift` 是 Xcode 或 Command Line Tools 附的指令，沒有裝的話，終端機會跳出安裝 Command Line Tools 的提示。`2>/dev/null` 把編譯器的警告藏起來：讀系統音量用的 `AudioHardwareService` 函式被 Apple 標成已淘汰，編譯時會印警告，在 macOS 15.3.1 上仍然讀得到值。藍牙裝置要先連線才會被列出來。

輸出的每一行是一台裝置，本篇開頭那台 Mac 印出的其中幾行：

```text
Mac mini的揚聲器：回報的輸出延遲約 11.5 ms，取樣率 96000 Hz，系統音量調得到：是
多重輸出裝置：回報的輸出延遲約 186.1 ms，取樣率 44100 Hz，系統音量調得到：否
```

延遲的讀法：程式把四個屬性加起來換算成毫秒，分別是裝置本身的延遲、安全偏移、緩衝區長度與串流的延遲，都以取樣數為單位；它是裝置回報的值，藍牙裝置的實際延遲可能比回報的長。兩台裝置的值相差幾毫秒以內時，對照〈各裝置的延遲不同〉的頻率抵消那一項；相差數十毫秒以上時，對照回音那一項。多重輸出裝置那一行的延遲，對照主要裝置那一行：兩者相同時，影片依主要裝置的延遲對齊。「系統音量調得到：否」的裝置，音量照〈音量：多重輸出裝置沒有系統音量〉的另外幾個地方調。
