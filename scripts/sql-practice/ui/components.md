元件規則只透過 token 取值：`scripts/sql-practice/ui/check_css_tokens.mjs` 擋下 `!important`、寫 px／rem／pt 的 `font-size` 與 `line-height`，以及寫死的色碼（`#…`、`rgb()`、`rgba()`、`hsl()`、`hsla()`）；token 的定義（`--sqlp-…: 值`）不檢查。腳本擋不到的寫法要靠審查：色名（`white`；不擋是因為 `transparent`、`currentColor` 要放行）、`oklch()`、`hwb()`、`color()`、`color-mix()`，以及把字級寫在 `font` 簡寫裡（`font: 16px/1.5 …`；`font: inherit` 沒有字級，不受影響）。腳本逐行讀，每一行只把最後一個 `{` 之後的內容當成宣告，所以一行寫兩條以上規則時，前面那幾條的宣告不檢查也不計數；這幾份 CSS 維持每行一條規則或一個宣告的寫法，壓縮過的 CSS 與 Sass 原始檔不要拿這支腳本檢查。pre-commit 在 `tokens.css`、`practice.css`、`callout.css` 或 `assets/practice/hub.css` 有 staged 時，對 staged 的那幾份跑它。讀不到 token 的位置（`#sql-practice` 外面的 `body`）在同一行註明 `sqlp-lint: allow` 與原因。版面常數（斷點、欄寬、單一元件的最小高）不在檢查範圍：它們各只用一次，寫成 token 不會讓調整變簡單，斷點也不能用自訂屬性。

### 字級：尺寸階與功能字級

字級分兩層。**尺寸階**（`--sqlp-size-*`）只放數字，元件規則不直接引用；**功能字級**（`--sqlp-t-*`，行高是成對的 `--sqlp-lh-*`）用文字在畫面上的功能命名，元件規則只引用這一層。某個功能的字在畫面上太大或太小時，改那個功能對到哪一階，不在元件規則裡寫數字；同一階的字要整體調大調小時才改尺寸階。

## 9. 實作註記

- 按鈕與連結用文字或圖示其中一種表達，不同時放兩種（2026-11-24 使用者決定）。目前全部用文字：離開按鈕、主要按鈕、文章清單、手機的收合題目鈕都沒有圖示。展開區（資料表結構、記下不懂的地方）摘要列前的加號／減號保留，它們標的是「已收合／已展開」的狀態，不是重複摘要文字的意思。
- 練習區的全域規則（重設的 `h2`、`p`、`li`、`code`、`table`、`nav a` 這類元素選擇器，以及 `::selection`、`*`、`:focus-visible`）一律寫成 `:where(#sql-practice) …`：範圍用 `:where()` 取、不計特定性（specificity），元素留在外面，特定性跟 blog 主題 `herman.css` 對應的那一條相同（`(0,0,1)`；`nav a`、`pre code` 是 `(0,0,2)`），`practice.css` 排在主題之後，所以贏過主題、又低於元件的 class 規則。練習頁與主題都沒有用 `@layer`。寫成 `#sql-practice p` 時，id 的特定性會蓋掉元件用 class 設的外距與字級：2026-11-24 曾經因此讓解析區與文字方案貼到磚的邊緣、蓋住「不推薦」磚的邊線，讓 16px 的 SQL 被 `code { font-size: .86em }` 縮成 13.8px；`#sql-practice :focus-visible` 也蓋掉過元件自己的焦點宣告。整條包進 `:where()`（特定性 0）又輸給主題：清單項目多 24px 上外距、標題多 12px 下外距、表格多框線。
- 正式頁面的 head 另有內嵌的 `assets/custom.css`（`a`、`h4`、`h5` 帶 `!important`）與 `layouts/partials/custom_head.html` 的 `details`、`summary` 規則。`!important` 的宣告重設贏不過，所以這兩處的元素規則加了 `:where(:not(#sql-practice *))`，排除練習區；改這兩個檔時保留這個排除。因為有這個排除，元件規則不需要帶 `#sql-practice` 加權，只寫 class 選擇器（2026-11-25 使用者決定拿掉 7 條帶 id 的元件規則：實測拿掉之後樣式只有一處改變，就是連結形式的主要按鈕 hover 時，從 `#sql-practice a.sqlp-btn` 造成的白底白字變成白底黑字）。驗證方法：展示頁複製一份，在 `practice.css` 前面依正式頁面的順序加載 `herman.css`、`custom.css` 與 `custom_head.html` 的內嵌樣式，逐元素比較計算後樣式（2026-11-24：1440、2560、390 三種寬度，寬度與高度以外只有一個 `margin-left: auto` 的值不同；改之前同一個比較有 574 個值不同）。比較的結果寫進 commit message。
- 精簡頂列（CompactBar）常駐時，根元素的 `scroll-padding-top` 是 72px，鍵盤移動焦點時目標不停在頂列底下；焦點在頂列裡時頂列不收起（`attachCompactBar` 的 `focusout` 監聽）。
- 2026-11-24 對比量測找出兩處細標記低於 3:1（結果列推薦方塊對列的底色、進度條未作答段對黑底），待辦記在 `content/backend/01-database/sql/practice/_index.md` 的 `## Backlog`。
- 元件的 DOM 由 `assets/js/sqlp-components.js` 產生，每個元件一個函式；元件展示頁與練習頁都從它取元件。練習頁（`assets/js/sql-practice.js`，Hugo 的 `js.Build` 打包成一支）從 2026-11-25 起只從元件庫選件與排位，每個畫面的組法照第 7 章；舊版原型的網址、儲存、抽題與熟練度邏輯原樣保留。SQL 的排版與上色在 `assets/js/sql-format.js`。
- 練習頁整頁只有練習區（2026-11-25 使用者決定：文章版型與練習頁的世界放在同一頁互相衝突）：`layouts/_default/baseof.html` 對 `sql-practice` 這個 layout 不輸出 blog 的頁首選單、分類色帶與頁尾，`body` 加 `page-practice`；`practice.css` 拿掉主題給 `body` 的內距與寬度上限，黑底鋪滿視窗，`#sql-practice` 置中、最寬 2000px。離開練習的路是 PivotBar 的 ExitLink 與瀏覽器的上一頁。頁面標題是視覺隱藏的 `h1`；`play.md` 的正文放在 hidden 的 `#sqlp-about`，練習首頁搬進 AboutPanel。
